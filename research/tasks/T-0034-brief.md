# T-0034：E-0031 写入分配筛选（X tap 侧支写入 q、v、up，与同参数 T0）

按封存的 E-0031 契约（research/experiments/E-0031.md）实现、审核、运行并分析。契约的预登记规则 1 至 10 已锁定，不改阈值与判定；需要改契约时先停下，告诉协调者。

## 要做的事

1. 实现 H-QVU 与 T0-QVU 的前向（从 E-0028 的 X tap 代码出发）：每层先算 n = input_layernorm(h)，用 n 做侧支读取，z = η a R_o；本层注意力运行时，q_proj 输出加 z C_q（q_norm 与 RoPE 之前），v_proj 输出加 z C_v（GQA 复制之前）；up_proj 输出加 z C_u。C_q、C_v、C_u 零初始化。参数在 CPU 上初始化，H 与 T0 两臂初值逐元素相同。参数计数必须是 629,000（条件对照 U-25、T0-U-25 为 619,400）。
2. 测试（PBS 上运行）：规则 1 的全部检查，包括第 0 步与 iv_off 等于 Base、计数、成对初值、第 1 步的梯度、改后缀不改前缀、padding、重载一致；保留的 E-0021 checkpoint（runs/ 下的 RB1-01 ATT-0239-1、RB1-02 ATT-0240-1、RB1-07 ATT-0245-1、RB1-09 ATT-0247-1；训练规格依次为 2g、1g、2g、2g）能用当前代码载入，并在各自的训练规格上复现记录的 dev 预测（规格不同时报告翻转条数）。
3. 正式训练前，按 research-review 请求代码审核（新的注入路径与 calibration 评估路径）；冒烟与确定性检查可以先跑。
4. 正式运行：seed 0，R1 顺序，13,115 步，η 0.25，LR 1e-3。训练结束后评估 dev（每任务 1,000 条）与 V1 calibration（每任务 2,048 条），保存两份预测；dev 曲线取 25/50/75/100%；H-QVU 做 iv_off 与 iv_swap（定义同 E-0021、E-0028）。H-QVU 与 T0-QVU 用同一 MIG 规格，能选时用 2g（X-01 与 RB1-07 的规格）。
5. 零训练复评：上面四个 E-0021 checkpoint 在 calibration 行上评估（同时复评 dev 作一致性检查）。
6. 锁定分析：按规则 3 至 10 计算并报告（合并行为主，dev 单独为描述）。规则 6 触发时，在本任务内训练 U-25 与 T0-U-25；规则 7 的复现，以及只有 T0-QVU 过实用门、或 H-0030 成立而 H-0031 不成立时的下一步，都由协调者另立决定，本任务不自动执行。结论只限 LR 1e-3 与 seed 0。
7. 记录：每次 run 先 rl run register 再提交；结果用 rl run import-result 导入；用量按实测（MIG-h × 0.25）；每条规则的结果写成 evidence（层级按契约）；不改假说状态，由协调者在结论审核后决定。

## 约束

- 所有测试、冒烟、训练、评估与分析都通过 miyabi-mcp 的 PBS 作业运行；登录节点只做控制工作，不在本地跑任何工作负载。
- 预算：初始 1.3 node·h，含条件对照总上限 2.0 node·h（含失败）。冒烟实测后在训练前更新成本表；预测超出上限时先停下报告。
- A2 确认集与官方 validation 不开封；不做新的 tap、来源、η 或初始化变体（E-0028 规则 10）。
- 交付：一条 RESULT 消息，写明各规则的结果、区间、用量与 evidence id。
