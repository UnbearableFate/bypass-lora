## Design

来源：用户 2026-11-02 的两个要求。Part A（D-0059）：“RB1-09 的方法里, 我们修改为一开始不计算 Q̃_t 等等, 而是直接用这一层的输入 X dot A_q, X dot A_k, X dot A_v 怎么样”。Part B（H-0022）：“然后,把侧分支输出的比例 η 作为超参数搜索对象, 搜索一下,看看能不能提高精确度”。

### 改动

RB1-09 在第 ℓ 层（ℓ ∈ {6, 13, 20, 27}）原来从 attention 内部取特征：q̄_t = Q̃_t A_q，k̄_t = K̃_t A_k，v̄_t = V_t A_v，其中 Q̃_t 是 q_norm 之后、RoPE 之前的 query（2048 维），K̃_t 是 k_norm 之后的 key（1024 维），V_t 是 v_proj 的输出（1024 维）。

新 tap（代码中的 direct_hidden）改为 q̄_t = X_t A_q，k̄_t = X_t A_k，v̄_t = X_t A_v，X_t 是该层 input_layernorm 的输出（attention 的输入，1024 维），A_q、A_k、A_v ∈ R^{1024×32}。之后的计算与 RB1-09 完全相同：κ_t = φ(RMSNorm(k̄_t))，M_t = M_{t-1} + κ_t v̄_tᵀ，c_t = c_{t-1} + κ_t，ρ_t = φ(RMSNorm(q̄_t) R_q)，a_t = ρ_tᵀM_t / (ρ_tᵀc_t + ε)，Z_t = η a_t R_o，FFN 变为 W_d[SiLU(u_t W_g) ⊙ (u_t W_u + Z_t C_u)]，C_u 零初始化。T0 用同样的参数，读出换成当前 token 的门控 a_t = SiLU(RMSNorm(q̄_t) R_q + RMSNorm(k̄_t)) ⊙ v̄_t，不读历史。Part A 的 η 都是 0.25（RB1 的值），Part B 只改 η。

### 初始化（用户 2026-11-02 问：A_q、A_k、A_v 用 Kaiming 还是 0）

两种 tap 都沿用 RB1-09 的初始化，A 不用 0：

- A_q、A_k、A_v 的每个元素独立取 N(0, 1/fan_in)，即代码里的 randn(fan_in, 32)/√fan_in，也就是 gain 为 1 的 Kaiming normal（又称 LeCun normal）。X tap 三个矩阵的 fan_in 都是 1024；原 tap 为 2048、1024、1024。R_q = R_o = I，C_u = 0。
- 训练起点等于 Base 靠 C_u = 0 保证（规则 1(a) 检查），不需要把 A 置 0。
- 不用 0 的理由：(1) C_u = 0 时，Z 上游的参数（A_q、A_k、A_v、R_q、R_o）梯度都是 0，只有 C_u 有梯度，且正比于 Z；A_v 再为 0 时 v̄ = 0、Z = 0，所有侧支参数的梯度恒为 0，训练不会开始。(2) A_q 或 A_k 为 0 时 RMSNorm 的输入为 0（这一点上它的 Jacobian 是 I/√ε，ε = 1e-6 时为 1000·I），φ(0) = 1，所有 query 或所有 key 都相同，读出退化成与当前 token 无关的历史平均，要靠梯度打破对称。随机初始化下不同 token 的 q̄、k̄ 从第一步起就不同。
- gain 不影响这个选择：A_q、A_k 后面接 RMSNorm，前向只看方向，尺度只改变 Adam 每步的相对改动量；A_v 的尺度在前向里与 η 只以乘积出现（Adam 下两者不完全等价），ReLU 版 Kaiming（gain √2）相当于把 η 乘 √2，在 Part B 的网格之内。
- X 是 input_layernorm 的输出，V 是 v_proj 的输出，两者尺度不同，所以同一 η 下两种 tap 的初始输出尺度不同。第 0 步记录每层 v̄ 与 Z 的 RMS（两种 tap 各一份，只作描述）；这也是 Part B 按 tap 分别选 η 的原因。

### Part B：侧支输出比例 η 的搜索（H-0022）

η 是 Z_t = η a_t R_o 里的固定标量（RB1 都用 0.25），不是可训练参数；同一 tap 下改 η 不改变初始参数（规则 1(h) 检查）。

| tap | η = 1/16 | 1/8 | 1/4 | 1/2 | 1 | 2 | 端点扩展（每个 tap 至多一个） |
|---|---|---|---|---|---|---|---|
| qknorm_pre_rope（QK） | ETA-QK-0.0625 | ETA-QK-0.125 | RB1-09（沿用） | ETA-QK-0.5 | ETA-QK-1 | ETA-QK-2 | ETA-QK-0.03125 或 ETA-QK-4 |
| X | ETA-X-0.0625 | ETA-X-0.125 | X-01（Part A） | ETA-X-0.5 | ETA-X-1 | ETA-X-2 | ETA-X-0.03125 或 ETA-X-4 |

- 全部为 C_up + KernelMatrix S1、r32、seed 0、LR 1e-3，训练与 dev 评估同下面的共同设置。每个候选都训练到完整长度，不用 200,000 tokens 的短训练：η 主要改变训练动态（例如侧支输出的增长速度），短训练的排序未必代表最终准确率，而完整 run 只需约 0.27 node·h。
- 每个候选的最终 checkpoint 另在 V1 calibration（每任务 2,048 条，与 E-0020 同一份）上评估准确率与 NLL，评估代码与 dev 相同。RB1-09 用它在 E-0021 的最终 checkpoint，与规则 1(g) 在同一作业里评估。
- 选择指标用 calibration 宏平均准确率而不用 NLL：目标是准确率，而 V1 NLL 对答案 token 求和，以 PIQA 为主。
- 新训练的候选：每个 tap 5 个，加至多 1 个扩展，共 10 至 12 个完整 run。

### 共同设置（与 E-0021 相同，除非这里另写）

- 数据、模板、候选 loss、26,230 个样本、13,115 步、有效 batch 2、AdamW、656 步 warmup 后 cosine、梯度裁剪 1、backbone BF16 冻结、侧支 FP32。
- 初始化与顺序：init 用 derive_seed(20261101, "residual_la_v21", "R1", "init", 0)，顺序用 derive_seed(20261101, "residual_la_v21", "R1", "train", 0)（order sha256 33759bc20322d0c9981128dd8574438546fc3439194ab32b7c79e35e0f0fc2bf）。X-01、X-02 与 ETA-X-* 的初始参数逐元素相同；X-03、ETA-QK-* 与 RB1-09 的初始参数逐元素相同。
- LR：所有新 arm 都用 1e-3（RB1-09 的锁定值），使 2×2 的四格与 η 网格的 LR 相同；不另校准，记为限制。
- 评估：dev 每任务 1,000 条，25/50/75% 曲线，主结果用最终 checkpoint，重载后复评逐条一致。

### 干预（只对 X-01，dev，与 E-0021 同口径）

iv_off、iv_swap、iv_window1、iv_window8、iv_strict、iv_permute。RB1-09 的干预结果沿用 E-0021。

### 预登记规则（运行前锁定；dev 宏平均点估计，单位 pp；阈值含等号，按精确分数计算）

记号：QK(η) 与 X(η) 是两种 tap 在 η 下的 C_up + KernelMatrix S1（QK(0.25) = RB1-09，X(0.25) = X-01）；η*_QK、η*_X 由规则 5 选出。

1. 实现：(a) 所有新 arm 第 0 步的 dev 预测与 Base 逐条一致；(b) X-01 的 iv_off 与 Base 逐条一致；(c) 重载一致；(d) 参数数与登记一致；(e) X-01 与 X-02、X-03 与 RB1-09 的初始参数逐元素相同；(f) X tap 取到的特征与该层 input_layernorm 的输出逐位相同（测试）；(g) 在新源码上重评 RB1-09 的最终 checkpoint，dev 预测与 E-0021 的记录逐条一致；(h) 同一 tap 的各 η 候选与该 tap 的 η = 0.25 成员初始参数逐元素相同，配置只有 η 不同；(i) η 选择脚本的测试覆盖并列、端点扩展与非有限淘汰。任何一项不成立：修实现，不下结论。
2. 可学性（只作描述）：各新 arm 是否 >= Base + 1。
3. H-0021：d_tap = X-01 − RB1-09（都在 η = 0.25）。d_tap >= +1：supports（screening）；d_tap <= 0：challenges（screening）；其余只作描述。
4. 历史（只作描述）：d_hist_X = X-01 − X-02，d_hist_QK = RB1-09 − X-03（都在 η = 0.25）。某一个 >= +1，且对应的 iv_swap 降幅 >= 1（X-01 用本实验的干预，RB1-09 用 E-0021 的 1.95）：交协调者按 D-0042 判断是否重开 H-0014。
5. η 选择（每个 tap 单独做；由脚本按本条从 calibration 结果算出，写 eta-lock 文件并记下各 manifest 的 SHA256，在汇总任何 Part B 的 dev 结果之前完成）：得分 = 最终 checkpoint 的 calibration 宏平均准确率（PIQA、BoolQ 各 2,048 条的算术平均）。训练出现非有限值的候选淘汰并记录；OOM、作业失败等工程问题重跑，不淘汰。初始六点中得分最高者（并列时取 |log2(η/0.25)| 最小者，再取较小的 η）是 1/16 时追加 1/32，是 2 时追加 4，每个 tap 只扩一次。η* 是全部有限候选中得分最高者（同样的并列规则）；η* 落在新端点时照选，标注“网格边界”，不再扩展。
6. H-0022：d_η(tap) = D(tap, η*) − D(tap, 0.25)，D 是 dev 宏平均；η* = 0.25 时 d_η = 0。某个 tap d_η >= +1：该 tap supports；d_η <= 0：该 tap challenges；其余只作描述。H-0022：至少一个 tap supports 时 supports（screening）；两个 tap 都 challenges 时 challenges（screening）；其余 inconclusive。supports 时下一步是该 tap 在 η* 与 0.25 下两个新 seed 的复现（新契约）；之后的 C_up arm 是否改用 η* 由协调者在结论审核后决定。
7. 与 LoRA（只作描述）：d_L = X-01 − RB1-07，另算 X(η*_X) − RB1-07 与 QK(η*_QK) − RB1-07。任一 >= +1：另记该版本在 dev 上高于 LoRA r7（screening），下一步是两个新 seed 的复现（新契约），并注明侧支比 LoRA 多调了 η。
8. 其他描述：X-02 − X-03（T0 下的 tap 效应）；d_tap* = X(η*_X) − QK(η*_QK)；两种 tap 的 dev 与 calibration（准确率、NLL）随 η 的曲线；第 0 步各层 v̄ 与 Z 的 RMS。未选中的 η 的 dev 只作描述，不用于选择或判定。
9. 每条规则的结果记一条 screening 证据（实现检查记 diagnostic）；PIQA、BoolQ、NLL、曲线与干预只作描述；假设状态在结论审核后再改。
10. H-0021 challenges 且 d_tap* <= 0，或 X(η*_X) < RB1-07 − 1：普通设置下不再做 tap 变体。

### 跨线（运行前固定，不改变上面的规则）

- RB1-09、RB1-07 与 Base 的 dev 数字取 E-0021 的锁定分析，不重训；规则 1(g) 保证评估路径没有变，RB1-09 的 calibration 评估在同一新源码上做。
- 不与分段协议（E-0025、E-0027）、V5（E-0013）或 M 线的数字比较。
- 限制：单 seed；dev 同时用于判定，每任务 1,000 条只能分辨约 2 pp 以上的差别；LR 没有为新 tap 或 C_up 的 T0 重新校准；η 只在 LR = 1e-3 下搜索（两者有交互）；T0 arm 不搜 η，规则 4 只在 η = 0.25 下成立；Part B 有两个 tap，规则 6 的“至少一个 tap”带有多重比较，supports 只到 screening，须复现。

### 成本、审核与记录

- 冒烟（PBS）：新 arm 的步时、峰值显存与初始参数 digest，以及一个 checkpoint 的 calibration 评估耗时；按实测更新成本表，预测超过 5.5 node·h 时先修订契约。
- 代码审核：新 arm 的配置与参数登记、η 的传入、训练与验证路径、calibration 评估、η 选择脚本、X-01 的干预和分析脚本，在正式训练和读取任何新 dev 结果之前通过只审改动的审核；冒烟与确定性检查可以先跑。
- 登记正式 run 时用 --review 点名已经审过当前辅助文件版本的审核（例如 rb_history、rb_read_diagnostics 的 RV-0076/RV-0077，rb_train、rb1_* 的 RV-0080/RV-0081/RV-0082），仍有 stale 时交协调者决定。
- 记录：每个 arm 的实际前向 tokens、步数、参数（stored/trainable/有梯度）、状态 shape/dtype/字节、η、LR、seed 与顺序 sha256、源码 commit、环境 lock、模型与 tokenizer revision、node·h；eta-lock 文件的 SHA256。
