## Design

依据：AD-0006 proposal 3；D-0042、D-0043；E-0021 的读诊断（DOC-0263；src/rb_read_diagnostics.py 的 prefix_read_metrics；src/rb1_intervene.py）。

### 对象、条件与位置

- arm：RB1-02（R_res S1）、RB1-03（R_res S2，报第 1 步与最后一步）、RB1-08（C_dual S1）、RB1-09（C_up S1）。用 E-0021 干预所用的同一最终 checkpoint，按 manifest SHA256 核对。
- 条件：normal、iv_strict、iv_window8，定义与 E-0021、RB0 相同。
- 位置：与 DOC-0263 读诊断相同的答案预测位置（gold 候选 token 的预测位置）。PIQA 每题多个位置，BoolQ 每题一个：主汇总先题内平均再题间平均，另报按位置加权（与 DOC-0263 可比）。
- 位置 0：每个序列的第一个 token。先核对同一任务所有 dev 样本的位置 0 token id 相同，并报告这个 token。

### 指标

1. share0：答案位置归一化读权重在位置 0 上的值（读权重定义同 E-0021：当前位置对因果前缀各位置的归一化读权重）；share0-2：位置 0–2 之和；argmax0：最大权重位置为 0 的比例。对照：均匀读取时的 1/n 与 3/n，按同一口径平均。
2. 常量读取指数 C：同一任务、同一层，取答案位置的读出向量（LatentReader 第 1 步的归一化读取结果，乘出口之前；S2 另报最后一步）。在固定 seed 抽取的至多 200 题之间算平均两两余弦，每题取第一个答案预测位置。对照：同一批题当前 token 的 value 向量之间的平均两两余弦。
3. 重新算出的 n_eff、相对 n_eff 与当前 token 权重，与 DOC-0263 核对一致。

### 预登记判读（运行前锁定，只决定阶段报告的写法，不改假设状态）

- 集中层：DOC-0263 中该 arm、该任务、该层 n_eff < 2 的层。
- 残差组（RB1-02、RB1-03）在所有集中层上 share0 > 0.5 且 C > 0.9：sink 读取。阶段报告写“残差组的状态读取在每个任务上近似常量（位置 0 sink）；swap 降幅小、permute 与 window 降幅大由此解释；干预表不说明 episode 特有的历史被使用”。
- 集中层上 share0 < 0.2：内容读取。阶段报告写明 swap 的小降幅需要别的解释（例如同任务 donor 的内容相似）。
- 介于两者或各层不一致：逐层描述，不下统一结论。
- concat 组（RB1-08、RB1-09）：share0 与 1/n 对照，C 只作描述。
- 一致性检查：iv_window8 下位置 0 对超过窗口的答案位置不可读，相应 share0 应为 0；iv_strict 与 normal 的 share0 差应 < 0.01。不成立时先查实现。

### 实现与运行

- 只加度量代码，复用 rb1_intervene 与 rb_read_diagnostics 的前向与读权重路径。单元测试用构造的读权重验证 share0、argmax0 与余弦。不改前向或评估路径时不需要代码审核；改动它们时先请求代码审核。
- 在 PBS（MIG）中运行；登记 run，导入结果，记一条 diagnostic 证据（不加 supports/challenges）。
