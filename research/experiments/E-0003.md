## Design

Release（E-0002 校准后锁定；来源 `research/notes/T-0002-release.md` 与 `T-0002-results.md`）：
- 沿用 E-0002 的数据切分（split map SHA256 `47cf5c777d07863b8def6903487697eafc970b0cd5b5d80babb7f20ded98571b`）、模板、截断规则、`derive_seed` 与训练顺序、按样本平均的训练 loss、优化配方（AdamW、clip 1.0、dropout 0）、FP32 新参数与 BF16 冻结主干、eager attention、GH200 MIG 2g.24gb、环境 lock 3c916b51337d。环境若有改动，先重跑 V0 与 V1 回归。
- 学习率（E-0002 选择规则的结果）：三个家族都是 3e-4。加法家族用于 V1-01、V1-02，concat 家族用于 V1-03 至 V1-06，LoRA 家族用于 V1-07、V1-08。
- 有效 batch 2（microbatch 1），与校准相同。
- 训练行排除（协调者决定，MSG-0058）：在每个任务的确定性 shuffle 之后、PIQA/BoolQ 交替混合之前，删去按锁定模板（max length 512，保留完整候选）无法编码的 train 行，其余行的相对顺序不变，所有 arm 相同。T-0002 的审计只发现 PIQA id 5528（候选 537 tokens）一行。任何任务删去的行超过其 train 行数的 1% 时停止并报告。dev 与 calibration 不变。
- 停止：在累计非 padding 输入 tokens 首次达到 2M 的那个完整优化步停止（含该步），或达到 3 epochs，先到者为准。T-0002 的估计是 13,077 步、2,000,040 tokens；实际实现须在第一个 arm 之前复现这个日程，不一致时先查原因。warmup 为 ceil(5% × 实际步数)，之后 cosine 降到 0。
- 中间评估：在 25%、50%、75% 进度（估计为第 3,270、6,539、9,808 步）只评估 dev，只用于学习曲线。主结果用最终 checkpoint，并做重载后复评（要求逐条完全一致）。
- Base 参考值沿用 E-0002 的 ATT-0011-2（相同 dev 样本与评估代码）；评估代码若有改动，则重跑 Base。
- V1-08（28 层 LoRA）的吞吐尚未测量：先用冒烟测出步时，再定 walltime 与队列。

参数数以实际加载后统计为准，表中数值只是公式预期；两者不一致时先查实现。

训练：seed 0；所有 arm 的数据顺序、batch、步数与评估点相同。

checkpoint 规则（运行前固定）：主结果用最终 checkpoint，所有 arm 相同；在 25%、50%、75% 训练进度评估 dev，只用于画学习曲线，不用于选择。

分析：
- 主指标是 dev 上 PIQA 与 BoolQ 准确率的宏平均，同时报告各任务准确率与 NLL。
- arm 之间的差异用以样本为单位的配对 bootstrap 区间描述；这是单 seed 筛选，不作确认结论。
- 宏平均差小于 1 pp 视为“近似相同”，大致对应单 seed、每任务 1,000 条 dev 的配对噪声量级。
- 若所有训练 arm 的 PIQA dev 准确率都在 Base（72.3%）±1 pp 以内，报告中注明 PIQA 没有提供区分信号；主指标仍按宏平均计算，不改换，同时单列 BoolQ 准确率与 dev NLL 的比较。（依据：E-0002 中 0.2M tokens 后 PIQA dev 准确率为 72.2%–73.3%，几乎不变。）
- F*：F_out 与 F_pre 中宏平均较高者；两者近似相同时取 F_out。
- C*：C_gate、C_up、C_dual 中有效且最简单者；与最佳者近似相同时取参数更少者。
- 额外报告：C 系列对 F 系列的差、V1-05 对 V1-06（非线性 proxy 是否有用）、C* 对 V1-07 与 V1-08（是否超出参数相近的 LoRA）。

成本：每组报告 stored、trainable 与实际有梯度的参数数，以及吞吐、wall time 和 node·h。
