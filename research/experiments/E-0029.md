## Design

来源：用户 2026-11-02 要求从 docs/plans/RB1-09_improvement_plan_2026-11-02.md 挑选有探索潜力的方向加入探索树（H-0023 至 H-0028）。本实验检验其中四个 active 假设；H-0027（local + history 混合通路）与 H-0028（激活子空间初始化）是 candidate，由本实验的规则决定是否启用。

方案里的记号与本项目的对应：方案的 X 是 input_layernorm 之前的残差流，N 是 input_layernorm 的输出。E-0028 的 X tap 取的是 N（方案的 N-QKV）。方案 §4.1 指出，S1 下 Q/K 用 X 还是 N 只差有效 ε 与参数化；value 用残差流 X 会带入逐 token 的残差尺度，这里不测。

- 侧支 arm 都是 C_up + KernelMatrix S1、r32、η = 0.25、LR 1e-3，R_q = R_o = I、C_u = 0，训练与评估同 E-0028 的共同设置。
- 初始参数：每个 arm 先按 RB1 的初始化规则（derive_seed(20261101, "residual_la_v21", "R1", "init", 0)）建好，再只改表中写明的矩阵。所以 G-T、P-T 与 RB1-09 只差 A_v 或 A_q；G-N、P-N 与 X-01 只差 A_v 或 A_q；G-QN 与 Q-N 只差 A_v。Q-N 的三个投影矩阵形状与 X-01 相同，初始数值也相同，两者只差 V 的来源。
- L-56、L-48 是只加在 up_proj 上的 LoRA：Δup_t = U_t A B，A ∈ R^{1024×r} 按 fan-in 随机，B ∈ R^{r×3072} 零初始化，缩放为 1（与 RB1-07 的 α = r 相同）。实现上就是 tokenwise 分支加 C_up 融合。

### I-G：A_v 的任务梯度子空间初始化（H-0024）

对 G-T、G-QN、G-N 各做一次，步骤运行前固定：

1. 校准样本：从 RB train 中按 derive_seed(20261101, "residual_la_v21", "R1", "ig", 0) 抽 256 条，三个 arm 共用，记下样本 id 与 token 数。
2. 模型处于初始状态（C_u = 0，函数等于 Base）。用正式训练的 loss 与归一化做一次前向和反向，不更新任何参数。每层收集：p_t，即用初始 Q/K 的核权重混合的未压缩 value 特征（p_t = ρ_t M^full_t / (ρ_t c_t + ε)，M^full_t = Σ_{i<=t} κ_iᵀ F_i，F 是该 tap 的 value 来源）；d_t，即 loss 对该层 up_proj 输出的梯度（经冻结主干反传）。padding 不计。
3. G_ℓ = Σ_t p_tᵀ d_t ∈ R^{1024×3072}（FP32），做 SVD，A_v ← U[:, :32]。
4. 尺度：在同一批样本上，s_ℓ = RMS(Z_ℓ，随机 A_v) / RMS(Z_ℓ，U[:, :32])，A_v ← s_ℓ U[:, :32]，使每层读出 RMS 与随机参照相同。
5. 正式训练用新的优化器从这个初始化开始。梯度收集的 token、时间与 node·h 计入成本。

### Q/K 配对初始化（H-0025）

- P-N：A_q ← A_k 的副本（两个独立的 Parameter，之后分别训练）。
- P-T：A_q ← G_group A_k。G_group ∈ R^{2048×1024}，按 Qwen3 的 GQA（16 个 query 头、8 个 KV 头、head_dim 128，query 头 i 用 KV 头 ⌊i/2⌋），G_group[128i + j, 128⌊i/2⌋ + j] = 1/√2，其余为 0。这样 q̄ 是每个 KV 组两个 query 头的聚合乘同一个 P_0 = A_k。
- 两者的 A_k、A_v、R_q、R_o、C_u 与随机参照逐元素相同。读取诊断里的 self 权重与 n_eff 用来判断收益是否只来自当前 token 通路。

### up-only LoRA 的 LR（H-0023）

按 E-0020 的短训练规则单独校准，代表 arm 用 L-56：初始化与顺序用 derive_seed(20261101, "residual_la_v21", "V0", "init"|"train", 0)，在首次累计达到 200,000 非 padding 输入 tokens 的完整步停止，NLL 在完整的 V1 calibration（每任务 2,048 条）上算（V1 定义）；网格 {1e-4, 3e-4, 1e-3}，最小值在端点时向外扩一次（3e-5 或 3e-3）；在有限候选中取 (NLL − min)/min <= 0.01 的最小 LR，写 lr-lock 文件（含各 manifest 的 SHA256），L-56 与 L-48 共用。锁定前不看 dev。

### 预登记规则（运行前锁定；dev 宏平均点估计，单位 pp；阈值含等号，按精确分数计算）

1. 实现：(a) 八个新 arm 第 0 步的 dev 预测与 Base 逐条一致（门槛按 D-0060：硬件不同时对同分配的 Base）；(b) 初始参数除表中写明的矩阵外与同 tap 参照逐元素相同，Q-N 与 X-01 的初始参数逐元素相同；(c) I-G：缩放前 A_v 的列正交；缩放后每层读出 RMS 与随机参照在校准样本上的相对差 <= 1e-3；G 的计算在小型合成模型上与逐样本 autograd 参照一致（测试）；(d) 配对：P-N 的 A_q 等于 A_k，P-T 的 A_q 等于 G_group A_k（逐元素），两者是独立的 Parameter；G_group 的头映射在合成张量上测试；(e) Q-N 取到的 Q/K 特征与 input_layernorm 输出逐位相同，V 特征与 v_proj 输出逐位相同（测试）；(f) L-56、L-48 只改 up_proj，参数数为 917,504 与 786,432；(g) 重载一致，参数数与登记一致。任何一项不成立：修实现，不下结论。
2. 可学性（只作描述）：各新 arm 是否 >= Base + 1。
3. H-0023：d_up(T) = L-56 − RB1-09，d_up(N) = L-48 − X-01。两者都 < +1：supports（screening）；任一 >= +1：challenges（screening），启用 H-0027。另记 L-56 − RB1-07（同四层下只改 up 与改全部七个模块的差，只作描述）。
4. H-0024：d_IG = G-T − RB1-09、G-QN − Q-N、G-N − X-01。任一 >= +1：supports（screening），启用 H-0028；全部 <= 0：challenges（screening）；其余 inconclusive。25% 与 50% 处的 dev 曲线差只作描述。
5. H-0025：d_pair = P-T − RB1-09、P-N − X-01。任一 >= +1：supports（screening）；两个都 <= 0：challenges（screening）；其余 inconclusive。self 权重与 n_eff 的变化只作描述。
6. H-0026：d_QK = Q-N − RB1-09。>= +1：supports（screening）；<= 0：challenges（screening）；其余 inconclusive。另记 d_V = X-01 − Q-N（value 来源的效应）与 G-QN − G-T（I-G 下 Q/K 来源的效应），只作描述。
7. 与 LoRA（只作描述）：每个新侧支 arm − RB1-07。任一 >= +1：另记该 arm 在 dev 上高于 LoRA r7（screening），下一步是两个新 seed 的复现（新契约）；该 arm 用了 I-G 时，复现契约同时加 LoRA-GA 初始化的 LoRA 对照。
8. 每条规则的结果记一条 screening 证据（实现检查记 diagnostic）；PIQA、BoolQ、NLL、曲线与诊断只作描述；假设状态在结论审核后再改。

### 跨线（运行前固定，不改变上面的规则）

- RB1-09、RB1-07 与 Base 的 dev 数字取 E-0021 的锁定分析；X-01 取 E-0028 的结果，且须通过 E-0028 的规则 1。X-01 无效或尚未完成时，涉及它的比较（G-N、P-N、L-48、d_V）等它完成后再算。
- 不与分段协议（E-0025、E-0027）、V5（E-0013）或 M 线的数字比较。
- 限制：单 seed；dev 同时用于判定，每任务 1,000 条只能分辨约 2 pp 以上的差别；H-0024、H-0025 各有两到三个 tap，“任一”带有多重比较，supports 只到 screening，须复现；η 固定为 0.25（E-0028 Part B 若选出别的 η*，本实验的比较仍在 0.25 下成立）；LoRA 没有对应的 LoRA-GA 初始化。

### 成本、审核与记录

- 记录：每个 arm 的实际前向 tokens、步数、参数（stored/trainable/有梯度）、状态 shape/dtype/字节、η、LR、seed 与顺序 sha256、I-G 的样本 id、奇异值与尺度因子、源码 commit、环境 lock、模型与 tokenizer revision、node·h；LoRA lr-lock 文件的 SHA256。
