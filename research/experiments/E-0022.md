## Design

依据：E-0018（T-0021，EV-0107..0109，research/notes/T-0021-results.md）。三个 D5 adapter 在 T2 dev 上 hop1 都没有达到 H3：EM 差 0.9–3.0 pp，目标权重 0.036–0.038，低于 1/16。oracle_value 的 hop1 EM 为 76–80%，说明解码器可以迁移；oracle_key 也只把目标权重提到 0.14–0.15（n_eff 约 9–10，EM 约 7%），说明问题模板和 key 两侧都没有把 T2 的事实分开。按 E-0018，V3 先登记共同起点阶段；key 也要改变，所以起点阶段训练全部侧支参数，不只训 query 侧。十组矩阵、tokenwise 核公式与 §9.4 的诊断按 plan §9；计时与样本预算按 E-0018。

### 共同设置

- 模型与协议：同 H-0012 的 D5 配方（E-0016、E-0017）。冻结 Qwen3-0.6B-Base，第 14 层，direct_hidden，SoftmaxSlot，F_out，r128，η=0.25，g=1；除 V3-09、V3-10 外 update=accumulate、readout=increment。单独编码写入：每条事实 "Head relation Tail ;\n" 不带前文单独编码，在分隔符处写入 key/value，问题侧不变；E=16。
- 数据：E-0011 的 T2 链终点生成器（ATT-0077-1 的数据，metadata SHA256 2ad8cc358ec5f6005e832125e3fa9995a0aa0a7c73f77c8fec6da6b7416a178f）已发布的 train 与 dev，只含 hops1–3；hops4/6/8 封存，本契约不开封。
- 优化：AdamW，每段重置；LR 3e-3；warmup 300 步后 cosine；每步 8 个 episode；梯度裁剪同 D5；只用最终 checkpoint；保存后重载，dev 预测须逐例一致。
- 数据顺序：起点阶段 derive_seed(20261029, "concat_loop_v2", "V3", "start", 0)；十组共用 derive_seed(20261029, "concat_loop_v2", "V3", "train", 0)，各组的样本与顺序完全相同。
- 循环实现：循环组都调用 bypass_core 的同一个 LatentReader（steps、fixed_query、update、readout 选项），与 RB 线同一实现（E-0021 的联动节）。T2 训练路径以及 V3-06、V3-07、V3-08 的新代码，在正式运行前过代码审核。

### 起点阶段（V3-S0）

- 从 ATT-0159-1（D5 seed 0）的最终 adapter 出发，按 E-0017 的 producer digest 绑定；训练全部侧支参数；数据为 T2 train 中 hop1 的问题，记忆构造不变；6,000 步。
- 门槛（E-0010@2 的标准 H3，单独编码写入，统计量分开报告）：在 T2 dev hop1、S=1 上，EM_normal − max(EM_zero, EM_shuffled) ≥ 10 pp；NLL_normal < min(NLL_zero, NLL_shuffled)；全部问题位置的目标权重 ≥ 0.125。
- 25/50/75/100% 的 dev hop1 曲线与 oracle_key、oracle_value 只作描述，不用于挑选 checkpoint。

### 十组（plan §9.2；都从共同起点出发，各 6,000 步）

| ID | 条件 | 要排除或验证的解释 | 实现 |
| --- | --- | --- | --- |
| V3-01 | 累加 S1 | 独立训练的单读参考 | steps=1 |
| V3-02 | 累加 S2 | 最小增加深度 | steps=2 |
| V3-03 | 累加 S4 | 主要多读候选 | steps=4 |
| V3-04 | S4，η=0.25/4 | 固定总步长 | eta=0.0625 |
| V3-05 | S4，query 固定为第 1 步 | 精确幅度对照，Z=4·η·a⁰·Ro | fixed_query |
| V3-06 | 同源 tokenwise 核，S4 | 无记忆的低维非线性深度是否已足够 | 新代码 |
| V3-07 | 更宽 S1 | 匹配新增运算量或实测延迟 | 新代码 |
| V3-08 | S4，Rq/Ro 不跨步共享 | 参数更多，单独报告 | 新代码 |
| V3-09 | 同核锚定 S4 | 只改 z_s 与 z_0 的外层残差锚点 | update=anchored |
| V3-10 | S4，Z=z_S 完整状态读出 | 初始 query 直通是否解释收益 | readout=full |

- V3-06：a_tok^(s) = SiLU(N_r(z^(s))·R_q + N_r(k̄_q)) ⊙ v̄_q，z^(s+1) = z^(s) + η·a_tok^(s)·R_o；k̄_q、v̄_q 来自当前问题 token，不读记忆；用共同起点的 A_q、A_k、A_v、Rq、Ro。
- V3-07：宽度按 plan §15 的 MAC 公式或 2g 上的计时 profile，在正式运行前锁定；两种匹配不能同时成立时分开报告，不称两者都公平。新增维度按“初始函数与共同起点相同”初始化。
- V3-08：把共同起点的 Rq、Ro 复制为 4 套，初始函数与 V3-03 相同。
- 初始化检查：V3-07、V3-08 在非零出口下，对 dev 的一个批次给出与共同起点（V3-08 对 V3-03 的 S4 前向）逐例一致的 logits。

### 评估

- T2 dev hops1–3。主评估取 S_eval=S_train。共享核的各组另扫描 S_eval∈{1,2,4,8}；V3-08 只扫描 1/2/4，不复用最后一套权重构造更多步。S_eval=8 只作深度外推诊断。
- 每组都有 normal、zero、shuffled、permuted 对照，以及 E-0011 的先验与结构捷径基线。
- 轨迹（plan §9.4）：每步的状态范数、读出范数、相邻步 query cosine、目标 key 权重与 n_eff（定义同 src/v2_memory.py 的 read_metrics），以及准确率随 s 的变化。独立训练的 S1（V3-01）与 V3-03 截断到一读的结果都报告。
- 中间状态干预（只对 S_M* 所在的组）：用随机状态、无关实体与匹配 donor 替换中间状态，同时作用于所有实际读取位置。模型内部能解出某个实体，不作逐跳因果链的证据。
- 区间：按 hop 分层的配对 bootstrap，10,000 次，seed 20261029，各组共用重采样索引，只作描述。

### 预登记规则（运行前锁定；dev 点估计，单位 pp；阈值含等号，按精确分数计算）

1. 起点门槛：起点阶段的最终 checkpoint 达到上面的 H3。不过：停在起点阶段，十组不训练；记 diagnostic 证据，并就 T2 的寻址与 key 可分性做一次咨询（research-advise）。
2. 主量：hops2–3 EM = (EM_hop2 + EM_hop3) / 2。
3. S_M* 取 V3-02、V3-03 中主量较高者，两者相差 < 0.5 时取 S2。
4. GL_M 成立需要同时满足：(a) S_M* − V3-01 ≥ +3；(b) hop1 EM 差（S_M* − V3-01）≥ −1；(c) S_M* − V3-07 ≥ +3；(d) S_M* − V3-06 ≥ +3；(e) S_M*=4 时 V3-03 − V3-05 ≥ +3，否则记为“暂无迭代查询证据”，GL_M 不成立。S_M*=2 时 V3 没有同深度的幅度对照，(e) 留到 V4。
5. V3-04、V3-08、V3-09、V3-10 与 S_M* 的差只作描述。它们对应 H-0005@2 陈述中其余的对照；V4 契约按 V3 的结果预先登记哪些是必需对照。
6. GL_M 成立 -> 起草 V4（E3）契约：3 个新 seed，各自先做起点阶段；按 H-0005@2，hops2–3 平均 EM 差 ≥ +3、配对区间下界 > 0、3 个 seed 方向都为正、hop1 差 ≥ −1；hops4/6/8 的外推按封存规则开一次。先做结论审核。
7. S_M* − V3-01 ≤ 0 -> screening 证据 challenges H-0005@2；结论审核后决定（plan §9.5：允许最终方法收敛为 S1）。
8. 其余情形（0 < S_M* − V3-01 < 3，或 (b)–(e) 有一项不成立）-> 只作描述。多读只比无记忆地板（zero、V3-06）好而不优于 V3-01 时，不支持循环主张（plan §9.5）。H-0005 暂停，写重开条件。
9. plan §9.3 的 untied 续训储备（2 组 × 1M）只在规则 4(a) 成立时考虑，另立小契约。
10. 规则 1–9 是推进规则，不是假设判定。每个问题记一条 screening 证据，写明差值、描述性区间与 V3 没有检验的部分。方向：GL_M 成立记 supports；S_M* − V3-01 ≤ 0 记 challenges；其余只作描述。假设状态在结论审核后再改。

### 跨线联动（运行前固定；同 E-0021 的联动节）

本契约与 RB1（E-0021）检验同一问题的两种设置：固定事实记忆上的多次读取（H-0005）与因果前缀状态上的多次读取（H-0015）。两线的循环用 bypass_core 的同一个 LatentReader，fixed_query 与 η/4 对照的定义相同；S_M* 与 S_F* 各自按本线选，不互相移植。两线结果都有之后按方向并列：两线都成立 -> 两种状态上的多次读取都有超出幅度与步长的增量；只有一线成立 -> 只在该线的状态与任务类型上称有增量，并列写明另一线的结果，不推广；都不成立 -> 本模型规模下暂无迭代查询证据。各假设仍只按本线证据判定；跨线数值不合并；联合描述属 screening，随结论审核一起审。
