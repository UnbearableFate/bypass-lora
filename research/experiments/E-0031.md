## Design

来源：用户 2026-11-03 要求把 H-0021 的相关材料交给顾问，取得一次改进建议后继续研究（顾问第 4 轮，AD-0007、AD-0008）。两位顾问都认为：普通设置下历史读取的作用和 0 分不开（四组同初值配对的 S1 − T0 为 −0.65 至 +0.15 pp）；与 all-7 LoRA r7 的差距更像写入位置的覆盖问题（只改 up 接口的各种适配器都落在 77.45 至 78.30）。本实验按 AD-0007 提案 1 的设计检验这一点（AD-0008 提案 2 问的是同一个问题，出口不同）：把同一预算分到注意力与 FFN 的写入位置，能否追上 LoRA r7，以及历史读取在这个配置下是否有贡献。
本次用户要求优先于 D-0045 对 RB1 阶段的暂停（同 D-0059 的处理）。顺序上没有照 AD-0008 的安排（先做 tier B 的多 seed，mean d_L >= +0.8 才做插入点实验）：AD-0007 把这个写入分配实验列为第一项且不设前提；用户要的是改进，本实验直接检验一项改进；合并 3,048 行与零训练复评（tier A，规则 8）以更低的成本处理分辨率问题；tier B 并入规则 7 的复现。H-0031 只限 q/v/up 写入配置，不重开 H-0014，也不改变 D-0042 的状态：即使 H-0031 supports，H-0014 在原配置下的 challenged 不变，是否重开 H-0014 另立决定。

### Arms

| Arm | 读取 | 写入位置 | rank | 参数 |
| --- | --- | --- | --- | --- |
| H-QVU | KernelMatrix prefix inclusive S1 | q_proj、v_proj、up_proj 输出 | 17 | 629,000 |
| T0-QVU | T0（当前 token 读取） | 同上 | 17 | 629,000 |
| U-25（条件） | S1 | 只写 up_proj 输出 | 25 | 619,400 |
| T0-U-25（条件） | T0 | 只写 up_proj 输出 | 25 | 619,400 |

参数：每层 3 × 1024 × r（A_q、A_k、A_v，都从 X 投影）加 (2048 + 1024 + 3072) × r（C_q、C_v、C_u）加 2r²（R_q、R_o），共四层。r = 17 时为 629,000，比 RB1-07 的 630,784 少 1,784（0.28%）。U-25 为 4 × (3 × 1024 × 25 + 3072 × 25 + 2 × 25²) = 619,400。实现要核对 stored、trainable 与有梯度的计数。

前向：每层先算 n = input_layernorm(h)，用 n 得到侧支的 q̄、k̄、v̄ 并读出 a，z = η a R_o；然后运行本层注意力，q_proj 输出加 z C_q（在 q_norm 与 RoPE 之前），v_proj 输出加 z C_v（在 GQA 复制之前）；FFN 的 up_proj 输出加 z C_u（同 C_up）。侧支读取只用本层的 n，不依赖本层注意力的输出，没有循环；注意力与 FFN 各只运行一次。C_q、C_v、C_u 零初始化，所以第 0 步等于 Base。H-QVU 与 T0-QVU 的初始张量逐元素相同（同 seed、同初始化规则，在 CPU 上初始化），训练顺序相同。

T0：同 D-0041 与 E-0028 的口径，用同一组 A_q、A_k、A_v、R_q、R_o 张量做当前 token 读取，a_tok = SiLU(N(q̄) R_q + N(k̄)) ⊙ v̄，写回相同。它是同参数的容量对照，不是关掉缓存的同一读取。

参照（不重训）：X-01（E-0028，ATT-0321-1，dev 与 calibration 预测都已保留）；X-02（ATT-0322-1，只有 dev 预测，checkpoint 已在 2026-11-03 的清理中删除）；RB1-07（E-0021，ATT-0245-1，checkpoint 保留）；Base。RB1-07 在 calibration 行上复评，同时复评 dev，与记录的 dev 预测逐条比较（同一 MIG 规格时应一致，不同规格时报告翻转条数）。合并分数用记录的 dev 预测加复评得到的 calibration 预测。零训练复评（规则 8）：E-0021 保留的 RB1-01（ATT-0239-1）、RB1-02（ATT-0240-1）、RB1-09（ATT-0247-1）在 calibration 行上评估，dev 用记录的预测。

数据：V1 的切分把每个任务的官方训练集打乱，前 1,000 行是 dev，接下来 2,048 行是 calibration，其余是训练行（src/v1_data.py）；RB 的 A2 行另从训练行中取出。所以 calibration 行没有参与训练。

### 预登记规则（运行前锁定；单位 pp；阈值含等号，按精确分数计算）

1. 实现检查（diagnostic）：新 arm 第 0 步的 dev 预测与 Base 逐条一致；iv_off（关掉侧支）等于 Base；stored、trainable 与有梯度的参数等于上表；H-QVU 与 T0-QVU 的初始张量逐元素相同；第 1 步后 C_q、C_v、C_u 都有非零梯度，主干参数不更新；改动后缀不改变前缀输出，padding 不写不读；保存后重载预测逐条一致；复评的 checkpoint 载入后，dev 预测与记录比较。不成立 -> 修实现，不下结论。
2. 可学性（描述）：每条新 arm 的 dev 宏平均 >= Base + 1。
3. H-0030（实用门）：d_X = H-QVU − X-01，d_L = H-QVU − RB1-07，都用 dev 与 calibration 合并的宏平均（每任务 3,048 条，先算每任务准确率再平均）。d_X >= +1 且 d_L >= 0 -> supports（screening）；d_X <= 0 -> challenges（screening）；其余 inconclusive。dev 单独的 d_X 与 d_L 同时报告，只作描述。
4. H-0031（历史门）：d_h = H-QVU − T0-QVU（合并宏平均）；s = H-QVU 的 dev 宏平均 normal 减 iv_swap（同 E-0021、E-0028 的定义：侧支历史换成同任务另一条 dev 样本的历史，固定 derangement，当前 token 的贡献保留）。d_h >= +1 且 s >= 1 -> supports（screening）；d_h <= 0 -> challenges（screening）；其余 inconclusive。swap 只作佐证，d_h 不到 +1 时 s 不能单独支持。
5. T0-QVU 的实用结果（描述）：T0-QVU − X-01 与 T0-QVU − RB1-07 同口径报告。T0-QVU 满足规则 3 的两个条件时，记为“这个写入配置下不带历史的适配器”的实用结果，不给历史记功。
6. 条件对照：H-QVU 或 T0-QVU 满足规则 3 的两个条件时，本任务内训练 U-25 与 T0-U-25（规则 1 同样适用），报告 H-QVU − U-25 与 T0-QVU − T0-U-25，即同预算下分到三个写入位置与只写 up 的差。这是预算分配的对照，不是纯位置效应。两条新 arm 都不满足时不训练。
7. 复现触发：规则 3 与规则 4 都 supports 时，提议两个新 seed（seed 1、2 的 H-QVU、T0-QVU、RB1-07、X-01，约 3 node·h），由协调者另立决定，本任务不自动执行。只有 T0-QVU 满足规则 3 的两个条件，或 H-0030 supports 而 H-0031 没有时，也由协调者另立决定（例如按 AD-0007 的建议，把这个不带历史的配置当作实用适配器复现）。
8. 分辨率诊断（描述，零训练）：报告 RB1-02 − RB1-01（R_res、qknorm tap 的 S1 对同初值 T0）、RB1-07 − RB1-09、RB1-07 − X-01 的合并配对区间。某个 checkpoint 无法用当前代码载入时，本条只记录原因，不影响其他规则。
9. 区间与范围：配对按任务分层 bootstrap（10,000 次，seed 20261101；dev 与 calibration 各自按任务分层重采样后合并，各 arm 共用索引）。区间只描述行抽样，不含 seed 与选择的不确定性。calibration 行曾用于选 LoRA 等的 LR（E-0020）与 X tap 的 η（E-0028，X-01 的 η 0.25 在 calibration 上输给 η 1），所以跨族比较对 LoRA 略有利、对 X-01 不利；H-QVU 与 T0-QVU 之间没有这种选择偏差。A2 与官方 validation 不开封。
10. 路线：H-0030 与 H-0031 都没有 supports，且 T0-QVU 也不满足规则 3 的两个条件时，普通设置下的 RB1-09 改进线在 E-0031 后结束；AD-0007 提案 2（all-7 LoRA r4 加 r11 侧支的固定总预算混合）与提案 3（候选排序损失）只在 E-0031 留下它们能回答的具体问题时，另立决定再做。E-0028 规则 10 对 tap 与来源继续有效。

### 成本、审核与记录

- 注意力之前的读取与 q_proj、v_proj 输出上的写入是新的 adapter 注入路径：正式训练前要过代码审核（research-review）；冒烟与确定性检查可以先跑。
- 所有测试、冒烟、训练、复评与分析都通过 miyabi-mcp 的 PBS 作业运行，登录节点只做控制工作。每条训练记录实际 MIG 规格；X-01 与 RB1-07 是 2g，能选时新 arm 也用 2g，H-QVU 与 T0-QVU 用同一规格。
- 每次 run 先 rl run register 再提交；用量按实测入账（MIG-h × 0.25 = node·h）；walltime 按冒烟实测的 1.5 倍申请。
