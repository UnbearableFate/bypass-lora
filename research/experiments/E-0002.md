## Design

数据（plan §11.2、§13.1）：
- PIQA 与 BoolQ 的官方 train 各自确定性切分：dev 1,000 条、calibration 2,048 条，其余为 train。切分 seed 按 `derive_seed(20261029, "concat_loop_v2", "V1", purpose)` 派生，与 arm 和 run seed 无关。官方 validation 封存，本实验不读取。
- 训练流是两个任务 train 的固定混合，顺序由 seed 0 固定，所有 run 相同。
- 模板为纯文本 completion。默认方案：PIQA 以 goal 为前缀，对两个 solution 计算长度归一化的对数似然并取较高者，训练用正确 solution 的 token CE；BoolQ 在 passage 与 question 后接 " yes"/" no" 标签，训练用标签 token 的 CE，评估比较两个标签的概率。若研究者认为另一种方案更合适，须在第一次运行前把它写进 release 并说明理由。BoolQ 超过 512 tokens 时的截断规则同样固定写进 release，所有 arm 相同。
- 记录每个 run 的实际非 padding 输入 tokens、loss tokens、padded tokens、样本数与 epoch。

校准 arm（每个 0.2M 非 padding 输入 tokens，seed 0）：

| arm | 家族 | 结构 | 学习率 |
| --- | --- | --- | --- |
| cal-lora-1e-4 / cal-lora-3e-4 | LoRA | 4 层 [6,13,20,27] all-7（q/k/v/o/gate/up/down）rank10，B 零初始化 | 1e-4 / 3e-4 |
| cal-fout-1e-4 / cal-fout-3e-4 | tokenwise 加法 | Z=SiLU(UA)，r32，F_out，P 零初始化 | 1e-4 / 3e-4 |
| cal-cdual-1e-4 / cal-cdual-3e-4 | tokenwise concat | Z=SiLU(UA)，r32，C_dual，Cg/Cu 零初始化 | 1e-4 / 3e-4 |

LoRA 的 alpha 与初始化写入 release，所有 LoRA arm 相同。家族内选出的学习率用于 E-0003 中该家族的全部成员：加法家族用于 F_out、F_pre，concat 家族用于 C_gate、C_up、C_dual 与线性退化组，LoRA 家族用于两个 LoRA 对照。

选择规则（运行前固定）：每个家族取 calibration NLL 更低的学习率；两者 NLL 相差不到 1% 时取较小的学习率。

切片检查：Base 在 dev 上每个任务都低于 90%，并且至少一个 LoRA 校准 run 的 calibration NLL 低于 Base，就视为“可学习且未饱和”。判定为全部近随机（接近 PIQA 50% 与 BoolQ 多数类比例）或近天花板时，按 outcome_actions 处理。

成本：每个 run 记录加载时间、至少 100 个稳定训练步的平均步时、评估与保存时间。这些实测值用于生成 E-0003 的 release（步数、batch、walltime）。
