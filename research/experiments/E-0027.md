## Design

来源：E-0025 规则 8（主任务 PIQA 不成立、次要任务 BoolQ 在 r128 成立：先做该任务两个新 seed 的复现，再下结论），D-0057，结论审核 RV-0084（提醒保留原训练混合，并在运行前锁定 seed 汇总与成功规则）。加入每个 seed 的分段 LoRA，是因为 seed 0 时 r128 的两个无历史对照在 BoolQ 上只比 Base_seg 高 0.3 与 0.6 pp，而分段 LoRA 为 64.2%，要排除“收益来自对照没学好”的解释。

### Arms（每个新 seed s = 1、2）

| arm | 结构 | 跨段通道 | 参数 | LR 家族 |
|---|---|---|---|---|
| SEG-05 | Keep：R_res + KernelMatrix，S1，r128 | 四层 (M, c, counts) | 2,752,512 | RBc-R，3e-3 |
| SEG-06 | Reset：同 SEG-05，段界清空状态 | 无 | 2,752,512 | RBc-R，3e-3 |
| SEG-07 | T0：R_res + T0，S1，r128 | 无 | 2,752,512 | RBc-T，3e-3 |
| SEG-04 | LoRA_seg：同四层 all-7，rank7，alpha=rank | 无 | 630,784 | RBc-L，3e-4 |

seed 0 沿用 E-0025 的结果（BoolQ）：SEG-05 65.90%，SEG-06 61.50%，SEG-07 61.20%，SEG-04 64.20%，SEG-05 的 iv_swap 59.40%，SEG-00 Base_seg 60.90%。

### 共同设置（与 E-0025 相同，除非这里另写）

- 分段协议、模板、候选 loss、PIQA+BoolQ 训练混合、26,230 个样本、13,115 步、有效 batch 2、LR 锁定值（research/artifacts/T-0024/lr-lock.json）、评估（dev 每任务 1,000 条，25/50/75% 曲线，最终 checkpoint，重载后复评逐条一致）都同 E-0025。
- seed：init 用 derive_seed(20261101, "residual_la_v21", "R1", "init", s)，训练顺序用 derive_seed(20261101, "residual_la_v21", "R1", "train", s)，s = 1、2；每个 seed 的顺序 sha256 在训练前登记。同一 seed 的 SEG-05、SEG-06、SEG-07 初始参数逐元素相同。
- 源码尽量沿用 E-0025 的 7d8b346；为 seed 或三 seed 分析改动的代码，在正式训练与读取任何新 seed 的 dev 结果之前做只审改动的代码审核。

### 干预（只对 SEG-05，dev，每个新 seed）

- iv_off：旁路出口在两段都置零，应与 SEG-00 逐条一致（实现检查）。
- iv_swap：第 2 段的初始状态换成同任务另一个 dev 样本第 1 段末的状态（固定 derangement，同 E-0025）。
- iv_reset：同一权重，评估时在段界清空状态（只作描述）。

### 预登记规则（运行前锁定；BoolQ dev 点估计，单位 pp；阈值含等号，按精确分数计算）

1. 实现（每个新 seed）：(a) SEG-05 在 iv_off 下与 SEG-00 逐条一致；(b) 初始化时 SEG-05 的 dev 预测与 SEG-00 逐条一致；(c) SEG-06、SEG-07、SEG-04 跑与不跑第 1 段，第 2 段输出逐位相同；(d) 重载一致；(e) SEG-05、SEG-06、SEG-07 的初始参数逐元素相同。任何一项不成立：修实现，不下结论。
2. 每个 seed 的量（口径同 E-0025 已审核的分析）：gain_s = SEG-05_s − max(SEG-06_s, SEG-07_s)，lora_s = SEG-05_s − SEG-04_s，都用训练任务里最终 checkpoint 的 dev 评估；swap_s = SEG-05_s(normal) − SEG-05_s(iv_swap)，两者取自同一次干预评估。干预评估的 normal 与训练评估逐条不一致的条数只作描述。seed 0：gain_0 = +4.40（11/250），lora_0 = +1.70，swap_0 = +6.50。
3. 汇总：对 s = 0、1、2 等权平均，得 G（平均 gain）、L（平均 lora）、W（平均 swap）。
4. supports（H-0020，screening，BoolQ，r128，3 seeds）：G >= +3，gain_1 > 0，gain_2 > 0，W >= G/2，并且 L >= +1。
5. challenges：G < +1；或 gain_1 <= 0 且 gain_2 <= 0；或 L <= 0。
6. 其余只作描述（inconclusive），不再加 seed、加宽、换 tap 或加循环。
7. 可学性只作描述：每个 seed 各组的 BoolQ 是否 >= SEG-00 + 1。某个 seed 的 SEG-06 与 SEG-07 都达不到时，另记“该 seed 的 r128 无历史对照未学成”；规则 4 的 L 条件用来防止这种情况下的高估。
8. PIQA、宏平均与 NLL 只作描述。每条规则的结果记一条 screening 证据（实现检查记 diagnostic）；假设状态在结论审核后再改。
9. 与 H-0019：无论结果如何，H-0019 维持 inconclusive。supports 时阶段报告写明这是 BoolQ 任务层面的结果；challenges 时按 E-0025 规则 10 停止侧支状态这条线，写机制性阶段报告。

### 跨线（运行前固定，不改变上面的规则）

- seed 0 的数字直接取自 E-0025 的锁定分析，不重跑。
- 不与 RB1、E-0026 或 E-0013 的数字比较；全上下文 LoRA 只作上限参考。
- 限制：只有 3 个 seed；dev 同时用于判定；LR 没有为 r128 或分段重新校准。

### 成本、审核与记录

- 冒烟（PBS）：确认新 seed 的初始化与顺序、四组的步时与显存；按实测更新成本表，预测超过 3.2 node·h 时先修订契约。
- 代码审核：seed 与三 seed 分析的改动在正式训练和读取任何新 seed 的 dev 结果之前通过只审改动的审核；冒烟与确定性检查可以先跑。
- 记录：每个 arm 的实际前向 tokens（分段）、步数、参数（stored/trainable/有梯度）、状态 shape/dtype/字节、LR、seed 与顺序 sha256、源码 commit、环境 lock、模型与 tokenizer revision、node·h。
