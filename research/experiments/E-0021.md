### 共同设置

- 结构：layers [6,13,20,27]；rank 32；tap qknorm_pre_rope（Q/K 在 QKNorm 后、RoPE 前，V 为 v_proj 输出，K/V 在 GQA repeat 前）；backend kernel_matrix（impl=prefix，经 RB0 验证）；mode inclusive；update accumulate；readout increment；η=0.25（RB1-06 为 0.0625）；g=1；ε_N=ε=1e-6；对所有有效 token 写一次、读 S 次；R_res 在代码中为 fusion=F_out（Y=H+F(U)+Z·P_R）。出口（P_R 或 C_g/C_u）零初始化；A_q/A_k/A_v 按现有 LowDimProjection 初始化；Rq/Ro 为单位矩阵。
- 初始化：derive_seed(20261101, "residual_la_v21", "R1", "init", 0)；RB1-01..06 的参数名、形状与创建顺序相同，初始参数逐元素相同（RB0 检查）。
- 数据：V1 切分（split map SHA256 47cf5c777d07863b8def6903487697eafc970b0cd5b5d80babb7f20ded98571b）的 train、模板与候选打分，max_length 512；按 E-0003 的规则在 shuffle 之后、任务交替之前删去不可编码行（V1 只有 PIQA id 5528），超过 1% 时停止报告；train 再去掉 RB 确认集行（D-0025，方案 A2）。训练顺序 derive_seed(20261101, "residual_la_v21", "R1", "train", 0)，所有 arm 相同。
- 日程：有效 batch 2（microbatch 1），逐样本平均 loss；在累计非 padding 输入 tokens 首次达到 2,000,000 的完整步停止（或 3 epochs，先到为准；步数按 RB train 的实际 tokens 计算，V1 train 不变时约为 13,077 步）；warmup ceil(5%×步数) 后 cosine 到 0；AdamW (0.9, 0.999)，eps 1e-8，weight decay 0.01；clip 1.0 并记录 pre-clip 范数；dropout 0；新参数与状态用 FP32，主干 BF16，eager attention，不用 gradient checkpointing。
- 评估：25/50/75% 只评 dev，作学习曲线；主结果用最终 checkpoint；重载后复评逐条一致。Base 沿用 ATT-0024-1（EV-0022；EV-0078 复核一致），评估代码有改动则重跑。
- 记录（plan2 §16.5）：实际 input/loss/padded tokens、epoch、步数；stored/trainable/有梯度参数；每层写/读次数与原块调用数；状态 shape、dtype 与字节；LR、warmup、clip；源码 commit、环境 lock、模型与 tokenizer revision；node·h。

### 冻结侧支历史干预（dev）

- 对象：RB1-02、S_F* 对应的 arm、RB1-08、RB1-09；RB1-01 只跑 iv_swap，作无操作检查。
- 干预：iv_off（应等于 Base）、iv_window1、iv_window8、iv_strict、iv_swap、iv_permute（定义见 RB0），另报当前 token 读权重；原 attention 与 KV 不变，四层同时作用。
- 报告每种干预的 dev 宏平均与每任务准确率、与正常路径的配对差及描述性区间。

### 延迟与状态（plan2 R1.3、§15.4–15.5）

RB1-01、RB1-02、RB1-04、RB1-08 与 RB1-07（另报 LoRA 合并后的参考）：在 2g.24gb 上 fail-fast；batch 1、上下文 512 的 prefill 吞吐；128 token decode 的 p50/p95；峰值显存；持久状态字节（KernelMatrix 为 r(r+1)×4=4,224 字节/层/序列，四层 16,896 字节）。

### 预登记规则（运行前锁定；dev 宏平均点估计，单位 pp；阈值含等号，按精确分数计算）

1. G0 正对照：RB1-07 ≥ Base + 1。不成立：停在实现与可学性检查（plan2 §5.2），不解释接口。
2. 有效：≥ Base + 1（同 V1）。
3. GR 残差单读：RB1-02 有效，且 RB1-02 − RB1-07 ≥ −1。
4. GH 侧支历史：RB1-02 − RB1-01 ≥ +1，且 iv_swap、iv_permute 各使 RB1-02 的宏平均下降 ≥ 1；iv_window1/8、iv_strict 与当前 token 权重只作描述。
5. GL 循环：S_F* 取 RB1-03、RB1-04 中宏平均较高者，两者相差 < 0.5 时取 S2；GL = S_F* arm − RB1-02 ≥ +1；S_F*=4 时还要求 RB1-04 − RB1-05 ≥ +1，否则按 plan2 §17.2 记为“暂无迭代查询证据”，GL 不成立。RB1-06 − RB1-02（固定总步长下多读是否仍有益）与 RB1-04 − RB1-06 只作描述。
6. GC concat：GC = max(RB1-08, RB1-09) − RB1-02 ≥ +1。C*_RB 按 plan2 §7.4 与 E-0003 的规则：在有效的 concat arm 中取宏平均距最佳严格 < 1 的，再按参数少、宏平均高、NLL 低依次决定（两者都入选时为 C_up）。
7. RB5：G0 成立且 GR 或 GC 成立时（plan2 §14.2：R1 通过后可直接释放 V5），起草 RB5（E3）契约，先做结论审核。矩阵：基本组 RB5-01、RB5-05、RB5-08；GL 加 RB5-02；GC 加 RB5-03、RB5-06、RB5-07、RB5-09；GC 且 GL 加 RB5-04；没有循环时 S=1，不重复训练同一 arm（plan2 §11.1）。
8. GL 不成立而 GC 成立：按 plan2 R1.3 做一次 C-S1/C-S4 配对 pilot（C*_RB+KernelMatrix，各 1M tokens，同初始化同数据，从 §14.3 储备支出，另立 E2 小契约 RB1p）；C-S4 − C-S1 ≥ +1 时 RB5 用固定 S4 跑完整九组，称“待检验的 S4”，不称最优深度；否则 concat 只在 S1。
9. G0 成立而 GR、GC 都不成立：先看 RB1-01 是否有效（T0 正对照）与梯度启动记录；实现与可学性成立后，至多释放一次容量或特征探针（候选假设：同布局 r64，或 qknorm_pre_rope/raw/SiLU(raw) 三臂各 2M，合计 ≤ 8M），仍无信号则停止 RB 确认并写阶段报告；四层 r32 的负结果只界定该配置。
10. 所有训练 arm 都在 Base ± 1 内：只做实现与可学性检查，不增加 S、r 或层数（参照 plan2 §5.2、§7.4）。
11. 规则 1–10 是推进规则，不是假设判定。每个问题记一条 screening 证据，写明差值、描述性区间与 RB1 没有检验的部分（例如同深度 T0 只在 RB5）。方向：假设陈述中的点估计条件在 RB1 上成立记 supports（主线：RB1-02 ≥ Base + 1、RB1-02 − RB1-07 ≥ +1 且两个任务的差都 ≥ −1；历史：GH；循环：GL；concat：GC）；主差值 ≤ 0 记 challenges（主线还包括 RB1-02 < Base + 1）；其余只作描述。假设状态在结论审核后再改。
