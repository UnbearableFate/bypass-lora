## Design

规格来源：plan §3.3–3.6（特征、正核状态、累加循环、concat 融合的公式）、§4.1 与 §4.5（恒等式与退化关系）、§6.3（检查表）、§16.1–16.3（模块边界、因果读取伪代码、原块数据流）。

每项检查写成独立的 pytest。结果逐项进入 manifest 的 metrics，例如 `check.<name>.pass`、`check.<name>.max_abs_err`。

| 检查 | 设置 | 通过条件 |
| --- | --- | --- |
| function_preservation | 真实模型；F 线四层与 M 线单层；每种融合接口的出口全零 | logits 与未修改 Base 在锁定的 BF16 容差内一致 |
| two_step_grad_start | 至少两个不同的有效写入项 | 第 1 步只有出口获得梯度；出口更新后，第 2 步 A_q/A_k/A_v 与 Rq/Ro 梯度非零；不以单槽 Q/K 相互抵消作为失败判据 |
| frozen_input_jacobian | 下层（layer 6）adapter，loss 在输出端 | 梯度能经冻结的上层回传到下层 adapter；全部主干参数 requires_grad=False，训练一步后不变 |
| kernel_identity | FP32；随机 k/v/q 与 mask；多种写入数 | KernelMatrix 与 KernelSlot 的输出及 q/k/v 梯度在 FP32 严格阈值内一致 |
| fusion_identity | 由同一个 P 构造 Cg=PWg、Cu=PWu | C_dual 与 F_pre 的输出以及对 P 的梯度一致 |
| fixed_query_magnitude | 固定 a，无额外 FFN 或 output norm | Z = S·eta·a·Ro |
| causality | F 线 inclusive 与 strict | 改动后缀不改变前缀输出；strict 下当前 token 读不到自身的写入 |
| cache_consistency | 一次 prefill、分块 prefill、逐 token decode | 三者输出在容差内一致 |
| reset_padding | 左/右 padding；reset | padding 不写、不读、不衰减；M、c 与 slots 同时清空 |
| ownership | batch 重排；多个 query 共享同一 support | 不串状态；M 线每个问题都从同一只读快照开始 |
| rw_counts | S ∈ {1,2,4} | 同一 token 只写一次；S 不改变写入次数；原 attention 与原 FFN 每层每次前向各调用一次 |
| m_line_access | M 线 | support 的主干 KV 不进入 query forward；问题与答案不写入 memory |
| export_reload | 保存并重新加载 adapter 状态 | 恢复算子、scope、步长与 normalization 后预测一致 |

容差：FP32 小张量参考用严格阈值，数值在检查运行前写入配置。BF16 容差由同一 Base 的重复测量确定，测量规则（重复次数、包含哪些等价变化）和由此得到的容差都在运行 function_preservation 等检查之前写入配置并提交；看到失败后不得放宽。

负对照：kernel_identity、causality、reset_padding、rw_counts 各配一个故意破坏的实现（例如全序列 KᵀV 泄漏未来、每个循环步重复写入、padding 位置写入），确认对应测试会失败。这样“通过”才说明测试有检出能力。负对照只在测试中构造，不进入正式代码路径。

数据：随机张量与少量固定文本 prompt，不需要训练数据，不消耗训练 tokens。

结果去向：全部通过才释放 V1 校准与筛选（E-0002、E-0003）；任何一项失败都先修复再重跑该项，不对其他结果作性能解释。
