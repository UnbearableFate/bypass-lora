## Design

依据：E-0014（EV-0080–EV-0085，D-0013）中只有 R1 过了 value 门槛，E=16 的 arm 都没过 H3。现有诊断已经指向寻址之外：
- R2 在 E=4 dev 的最后问题位置，目标权重 0.983，argmax 全部命中目标，EM 却只有 8.2%；
- R5 在 E=16 上的 oracle_value 只有 10.7%；
- R1 的 oracle_value 从 E=1 的 83.6% 降到 E=16 的 5.8%。

E-0014 已有的分层数据还表明：R1 在 E=16 dev 上的 oracle_value，目标为第 0 条事实时 EM 为 87%（45/52），其余位置合计约 1.4%（AD-0001 指出，协调者已核对 metrics.json 的 target_fact_position 分层）。也就是说，同一个 value 映射对没有前文的事实有效，对前面已有其他事实的事实失效。

本实验不训练，只在已有 checkpoint 上加对照和探针，把下面几种解释分开：
- value 内容丢失；
- 解码失败（融合与冻结的上层）；
- 非末位问题位置的混合读取干扰解码；
- 支持侧上下文改变了写入位置的特征，E=1 学到的 value 映射因此不能迁移（上下文迁移）。

结果用于设计下一轮训练筛选（E-0016），不改变 H-0009 的状态。

修订 2（AD-0001 建议，在任何 E-0015 运行之前）：
- 诊断改在 calibration 上做，dev 留给 E-0016 的门槛；
- 加错误事实 value 负对照、与只读最后位置的协议匹配的 shuffled 对照、小型增量幅度扫描、探针基线和跨编码的探针测试。

### 读取替换对照

都在第 14 层的单次读取上做，算术与现有 oracle 对照相同：增量为 η·(read·gain)·Ro，只在有效问题 token 上加。“最后位置”指预测答案的那个问题 token（answer_logits 用的位置）。

| 对照 | 最后位置 | 其他问题位置 | 状态 |
| --- | --- | --- | --- |
| normal | 正常读取 | 正常读取 | 已有 |
| zero、shuffled | | | 已有 |
| oracle_value | 目标 value | 目标 value | 已有 |
| last_only | 正常读取 | 不加增量（读取置零） | 新 |
| oracle_last | 目标 value | 正常读取 | 新 |
| oracle_last_only | 目标 value | 不加增量 | 新 |
| uniform | 本 episode 所有有效槽位 value 的等权平均 | 同左 | 新（不寻址的读取） |

| last_only_shuffled | 打乱记忆（同 shuffled 的 donor 规则）下的正常读取 | 不加增量 | 新（与 last_only 协议匹配的负对照） |
| wrong_oracle | 同一 episode 中第 (target+1) mod E 条事实的 value | 同左 | 新（错误事实负对照） |

四个 checkpoint 在三个 split 上各跑全部对照。E=1 时，oracle 与 uniform 都等于 normal，只作一致性检查；wrong_oracle 不适用；shuffled 照旧。

### 增量幅度扫描（只在 R1@E=1、R2@E=4、R5@E=16）

增量乘以 α ∈ {0.1, 0.3}，与 α=1（即原对照）比较。三种方式：
- 所有问题位置都缩放，读取为 normal；
- 所有问题位置都缩放，读取为 oracle_value；
- 只缩放非末位位置、最后位置不变，读取为 normal。

R1@E=1 作正对照，用来确认缩放本身不会直接破坏可用的解码。

### 单独编码替换（E=4、E=16 calibration）

把 episode 中的每条事实单独编码：支持序列只含这一条事实，格式与 E=1 数据完全相同（"Head relation Tail ;\n"）。在它的分隔符处取 key 与 value，按原支持顺序放回同一槽位，组成“单独编码记忆”。

| 对照 | key | value | 读取 |
| --- | --- | --- | --- |
| iso_kv | 单独编码 | 单独编码 | 正常读取 |
| iso_v | 上下文编码（原协议） | 单独编码 | 正常读取（保留已训练的寻址，只换 value） |
| iso_oracle_value | | 单独编码的目标 value | 所有问题位置都用它 |
| iso_wrong_oracle | | 单独编码的第 (target+1) mod E 条事实的 value | 所有问题位置都用它（负对照） |

因果编码下，把目标事实移到支持首位再编码，与单独编码在目标分隔符处的特征相同，所以不另设“移到首位”的对照。RoPE 只依赖相对位置，没有前文时整体平移 position id 不改变注意力，所以“块对角 mask、保留原 position id”的变体也等同于单独编码（数值误差除外），不另设。实现中要检查：单独编码到分隔符为止的 token 与 E=1 数据格式逐 token 一致。

### 分隔符特征与 value 的幅度（AD-0002 建议，零成本）

按事实位置（第 0 条、第 1–3 条、第 4 条及以后）报告，上下文编码与单独编码各一份，四个 checkpoint 的训练出的 value 都要报：
- 冻结特征（direct_hidden）的 L2 范数与最大维绝对值；
- 训练出的 value 的 L2 范数与最大维绝对值。

用途是检查第 0 条事实的分隔符是否带有 massive activation 一类的特殊幅度。这一项只作描述，不设判定规则。

### 按目标位置分层

所有 EM 与 NLL 同时按目标事实在支持中的位置报告：第 0 条与第 1 条及以后，并附逐位置计数。

### 线性探针

- 闭式 ridge 分类器，λ=1，同 src/v2_memory.py 的 independent_probes。在 train 前 4,096 条上拟合，在 calibration 上报告准确率。
- 标签是尾实体的答案 token。类别取拟合集中出现过的尾实体；测试集中未出现在拟合集的类别记为错误，并单独报告其数量。
- 基线（与每个探针用同样的样本与规则）：
  - 答案先验：总是预测拟合集最常见的类别；
  - 标签打乱：拟合前随机打乱标签，种子固定；
  - 随机投影：Pf 的输入先乘一个固定种子的高斯随机矩阵，降到与 Pv 相同的 128 维，再拟合。
- 探针准确率是闭集分类准确率，不等同于全词表 EM；探针失败不能证明信息不存在。

| 探针 | 输入 | 样本 | 意义 |
| --- | --- | --- | --- |
| Pv | 训练出的 value 向量（r128，写入后、读取前） | 每个写入槽位一个，标签为该事实的尾实体 | value 内容是否携带尾实体 |
| Pf | 写入位置上进入投影前的冻结特征（direct_hidden） | 同 Pv | 与 checkpoint 无关，每个 split 一次；复现 V2 的探针，作参照 |
| Pz | 最后位置的融合增量（d=1024，即 F_out 加到残差上的量） | 每个 episode 一个，标签为目标尾实体 | 信息是否穿过融合出口 |

Pz 分别在 normal 与 oracle_value 下报告。

Pv 与 Pf 还要在单独编码上各算一次，并按事实位置分层（第 0 条、第 1–3 条、第 4 条及以后）报告。

另对 R1 的 Pv 做跨编码测试：单独→单独、单独→上下文、上下文→上下文、上下文→单独（箭头左边为拟合用的编码，右边为测试用的编码）。

### 判定规则（diagnostic，只用于设计 E-0016）

1. value 内容在、解码失败：R2@E=4 或 R5@E=16 的 Pv ≥ 80%，且 oracle_value EM < 30%。下一轮针对解码侧，例如融合增量的幅度、读取位置协议、热启动后继续训练解码。
2. value 内容丢失：Pv < 50%，而 Pf ≥ 90%。下一轮针对 value 学习，例如从 R1 热启动、E=1 与 E=16 混合 batch。
3. 非末位混合读取干扰：在 R2@E=4 或 R5@E=16 上，last_only − normal ≥ 10 pp，或 oracle_last_only − oracle_value ≥ 10 pp，同时 NLL 同向改善，且 last_only_shuffled 不出现同样的提升。下一轮加入只在最后问题位置读取的训练协议。
4. 跨上下文迁移失败：R1 的 oracle_value 在 E=4 与 E=16 上远低于 E=1（低 ≥ 30 pp），而 Pf ≥ 90%。热启动时 value 须保持可训练，并优先混合 E 训练。
5. 上下文迁移得到确认：R1 在 E=16 上的 iso_oracle_value 在第 0 条与第 1 条及以后都 ≥ 70%，而上下文编码的 oracle_value 只在第 0 条高，iso_wrong_oracle 接近先验。下一轮加入“每条事实单独编码后写入”的协议 arm：寻址仍须从答案 CE 学，单独编码只改变写入时的上下文。
6. R2 或 R5 的 iso_v 比其 normal 高 ≥ 10 pp：多事实训练出的 value 映射也受上下文拖累。
7. 幅度：在 R2@E=4 或 R5@E=16 上，某个 α < 1 使 EM 比 α=1 高 ≥ 10 pp，且 NLL 同向改善，同时 R1@E=1 在同一 α 下仍可用（EM ≥ 50%）。下一轮把增量幅度控制作为单独 arm，与读取位置协议分开测试。
8. 以上都不成立时，按数字如实报告。

所有“≥ 10 pp”的比较都要求 NLL 同向改善；只有 1–2 pp 的变化不作为机制信号。

几条可以同时成立。报告时同时给出 Pv、Pz、各 oracle 对照的数字，不只给判定。

### 实现、审核与预算

- 新代码只在诊断路径：
  - 新对照：src/v2_memory.py 的 read_vectors 与 evaluate_batch；
  - 单独编码记忆的构造；
  - 探针收集；

- 新对照与探针请求一次代码审核，范围：
  - 各对照只替换声明的位置，缩放只作用于声明的位置；

  - 增量算术同 oracle；
  - 探针的拟合（train）与测试（calibration）不重叠，标签对齐槽位顺序，基线与探针使用同样的样本；
  - 已有对照不变。
- 评估很便宜，可以在审核答复前先跑。只有审核通过后才记录结果；审核要求的修改若改变代码，就重跑。
