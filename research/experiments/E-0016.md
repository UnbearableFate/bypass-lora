## Design

依据：E-0014 的六个单改动 arm 都没有在 E=16 上达到 H3（EV-0080–EV-0085）。顾问轮次 1（AD-0001、AD-0002）与协调者的核对给出几点：
- 同一 value 映射对“第 0 条事实”和“有前文的事实”互不迁移：
  - R1 的 oracle_value 在目标为第 0 条时是 45/52，其余位置 13/948；
  - R5 正相反，位置 0 是 1/52，其余位置 106/948。
- 没有一个 E=16 arm 的解码器在干净读取上训练过。R2 在 E=4 上最后位置的寻址已到位，EM 仍只有 5–12%。
- 在 S=1、increment、F_out 下，从 value 到残差的路径是线性的（W = A_v·R_o·P），唯一的非线性在寻址 softmax。
- 增量幅度与梯度裁剪不能解释失败：R1 在 E=1 上成功时增量约为残差的 9 倍，几乎每步都被裁剪。

另外更正一处读法：EV-0083 的末句“吸收答案先验仍不能阻止槽位 0 塌缩”超出了证据。R4 的先验通路在零记忆下只到 NLL 4.74，而塌缩解是 4.42，先验没有被完全吸收（AD-0002 §1.3）。

本实验把解码器学习与寻址学习在训练中分开，检验三条机制不同的路线（H-0010、H-0011、H-0012）。E-0015 只做评估，与本实验并行；D4/D5 是否运行取决于 E-0015 规则 5。

### 共同配置

- V2-03 基础配置，同 E-0014：
  - M 线协议，冻结 Qwen3-0.6B-Base，第 14 层，direct_hidden，r128，S=1，SoftmaxSlot，F_out；
  - 分隔符位置写入，只对答案 token 计算 CE；
  - 优化器、warmup（300 步）/cosine 与 dtype 同 E-0009 的正式训练程序；
  - LR 3e-3；每段 6000 步、每步 8 个 episode；seed 0。
- 数据：E=16 的 train、calibration、dev 用 ATT-0039-1；E=1 dev 用 ATT-0112-1。
- 只用最终 checkpoint，保存后重新加载，评估须逐例一致。
- 续训（D2a、D2b、D5）的规则：
  - 只加载 adapter 参数；
  - AdamW 状态重置，重新 warmup 300 步再 cosine；
  - 数据顺序用新的命名空间种子：derive_seed(20261029, "concat_loop_v2", "V2R16", arm, 0)。
- 所有新选项默认关闭。关闭时输出与梯度须与当前 master 一致，用回归测试确认。

### Arms

| arm | 假设 | 改动 | 起点 | 标签 |
| --- | --- | --- | --- | --- |
| D1 | H-0010 阶段 1 | teacher-forced 单槽读取：训练时记忆的有效槽位只留目标槽位（用 slot_columns 定位），所有问题位置读到的就是目标 value | 从零 | 用目标索引（额外监督） |
| D2a | H-0010 阶段 2 | 恢复全部槽位，正常读取，只用答案 CE；只训练寻址参数，value 与出口参数冻结 | D1 最终 adapter | 本段不用标签 |
| D2b | H-0010 阶段 2 | 同 D2a，但所有 adapter 参数都训练 | D1 最终 adapter | 本段不用标签 |
| D3 | H-0011 | 槽位隐变量边际似然，只在最后问题位置读取（见下） | 从零 | 不用标签 |
| D4 | H-0012 | 每条事实单独编码后写入（见下），读取协议不变，只用答案 CE | 从零 | 不用标签 |
| D5 | H-0012 | 同 D4 | R1 最终 adapter（ATT-0122-1） | 不用标签 |

参数分组（实现时用测试断言哪些参数名拿到非零梯度）：
- 寻址参数：query 与 key 的投影、reader 的 Rq；
- value 与出口参数：value 的投影、reader 的 Ro、融合的 P。

D2a 回答“解码器固定且可用时，寻址能否只从答案 CE 发现”；D2b 回答“联合训练时解码器会不会在寻址学成前被混合读取拖垮”。

D3 的目标：L = −log Σ_i w_i·p(answer | 最后位置只读 v_i)。
- w_i 是最后问题位置正常 SoftmaxSlot 的权重。
- p(answer | 只读 v_i)：最后位置的读取替换为 v_i、其他问题位置不加增量时，冻结下游给出的答案概率。
- 每个 episode 的 16 个槽位各做一次问题侧前向（只有问题部分，支持侧只前向一次）。
- 梯度同时流向寻址（w）与 value/融合参数。
- 实现前先做冒烟，量出步时；步时超过 V2-03 的 3 倍就停下报告。

D4/D5 的单独编码写入：
- 支持中每条事实单独编码，格式与 E=1 数据完全相同（"Head relation Tail ;\n"）；
- 在其分隔符处取 key 与 value，按原支持顺序写入同一槽位；
- 问题侧不变；
- 与 E-0015 的单独编码共用同一实现。

D4/D5 只在 E-0015 规则 5 成立时运行：R1 的 iso_oracle_value 在第 0 条与第 1 条及以后都 ≥ 70%。规则 5 不成立时不跑，并记录原因。

### 评估

每个 arm 的最终 checkpoint 在 E=16 dev（1,000）上评估：
- EM 与 NLL，覆盖 normal、zero、shuffled、permuted、oracle_key、oracle_value；
- 目标权重：全问题位置平均与最后位置各报；
- n_eff；
- 最后位置的 argmax 槽位分布；
- 融合增量与残差的范数比；
- 以上都按目标位置分层（第 0 条与第 1 条及以后）。
- 每 500 步记录训练 CE；在 25%、50%、75% 处记录 E=16 dev 学习曲线（同 E-0014）。

另外：
- D1：teacher-forced 对照。
  - tf_normal：记忆只留目标槽位；
  - tf_shuffled：只留 donor episode 同一索引的槽位，donor 规则同 shuffled；
  - tf_wrong：只留本 episode 第 (target+1) mod 16 条的槽位；
  - zero 照旧。
  - D1、D2a、D2b 另在 E=1 dev 上报 normal、zero、shuffled。
- D3：
  - 硬读取：最后位置读 argmax 槽位的 value，其他位置不加增量；
  - 软读取：最后位置读 Σ w_i v_i，其他位置不加增量；
  - 边际 NLL；
  - zero、shuffled、permuted 都在同一只读最后位置的协议下做。
- D4/D5：所有对照都在单独编码写入下做；shuffled 的 donor 规则不变。

### 判定（screening，seed 0）

- D1（解码器可学）：EM(tf_normal) − max(EM(zero), EM(tf_shuffled)) ≥ 50 pp。
  - 未达标的情况：差 < 20 pp，且最后 1000 步训练 CE 下降 < 0.05 nat（平台）。
  - 20–50 pp 之间记为部分。
- D2a、D2b、D4、D5：E-0010@2 的 H3 门槛。在标准读取协议下同时满足三条：
  - EM_normal − max(EM_zero, EM_shuffled) ≥ 10 pp；
  - NLL_normal < min(NLL_zero, NLL_shuffled)；
  - 目标平均地址权重 ≥ 0.125（全问题位置平均，与 E-0014 相同）。
  - 另报最后位置的权重。
- D3：硬读取协议下的 H3。同时满足三条：
  - EM_hard − max(EM_zero, EM_shuffled-hard) ≥ 10 pp；
  - NLL_hard < min(NLL_zero, NLL_shuffled-hard)；
  - 最后位置目标权重 ≥ 0.125。
  - 这是新协议的统计量，不称为通过 E-0010 的同一 H3；软读取的结果并列报告。
- 只报告点估计与正确数/样本数。区间按 V2 的配对 bootstrap 只作描述。
- 后续动作见 outcome_actions。任何达标都只是单 seed 的 screening 信号，复现前不改变 H-0003 的路线状态。

### 实现、审核与预算

- 新代码路径：
  - teacher-forced 单槽训练与评估对照；
  - 从 checkpoint 续训（只载 adapter、重置优化器、新调度）；
  - 槽位边际似然损失与只读最后位置的读取；
  - 硬读取与软读取评估；
  - 单独编码写入（与 E-0015 共用）。
- 全量运行前请求代码审核，审核范围：
  - 默认关闭时与当前 master 一致；
  - teacher-forced 掩码只留目标槽位，评估对照的掩码正确；
  - 续训不带入优化器状态，调度从头开始；D2a 只有寻址参数拿到梯度；
  - 边际似然在 log 空间计算且数值稳定，每个槽位的前向只替换最后位置；
  - 硬/软读取的定义；
  - 单独编码的格式与槽位顺序。
- 冒烟与单元测试可以先跑。
- 计算全部经 miyabi-mcp 走 MIG 队列。按 E-0014 实测（每 6000 步约 0.28–0.41 MIG-h），D1、D2a、D2b、D4、D5 各约 0.1 node·h，D3 约 0.15–0.2 node·h，合计约 0.65 node·h；上限 0.9 node·h，计入项目总额。
