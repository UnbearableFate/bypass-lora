## Design

### 分段协议

- 每个样本拆成两段，各自独立做 backbone 前向：段间不传原 attention 的 KV，第 2 段位置从 0 开始；attention mask 与 RB1 相同（因果，不用 sliding window）。
- PIQA：第 1 段 'Goal: {goal}\n'；第 2 段 'Solution:' 加候选（候选 tokens 与 V1 编码相同，即 ' ' + solution）。
- BoolQ：第 1 段 'Passage: {passage}\n'，passage tokens 与 RB1 中该样本截断后的 tokens 相同；第 2 段 'Question: {question}\nAnswer:' 加 ' yes' / ' no'。
- 分段编码与 RB1 的整段编码在段界处的 token 差异逐条计数并报告；第 2 段的候选 tokens 不得改变。
- SEG-02：第 1 段照常经过四层旁路（写入、读取并写回残差），第 1 段结束时的四层状态作为第 2 段的初始状态（process_prefix(state=...)）。训练时保留计算图，梯度经状态回到第 1 段；样本之间清空状态；第 1 段不计 loss。
- SEG-00、SEG-01、SEG-03、SEG-04 没有跨段通道，实现上可以只跑第 2 段；要有测试证明这些 arm 跑与不跑第 1 段时，第 2 段的输出逐位相同。
- loss：与 RB1 相同的候选 loss，只在第 2 段的 gold 候选 tokens 上。

### 共同设置（与 E-0021 相同，除非这里另写）

- 结构：layers [6,13,20,27]；tap qknorm_pre_rope；backend kernel_matrix（prefix）；mode inclusive；update accumulate；readout increment；η=0.25；g=1；出口零初始化。
- 初始化与顺序：与 RB1 相同，init 用 derive_seed(20261101, "residual_la_v21", "R1", "init", 0)，训练顺序用 derive_seed(20261101, "residual_la_v21", "R1", "train", 0)（plan.order_sha256 33759bc20322d0c9981128dd8574438546fc3439194ab32b7c79e35e0f0fc2bf）。样本与步数同 RB1（26,230 个样本，13,115 步，有效 batch 2）。这样 SEG 与 RB1 同 arm 的差只来自分段。SEG-01、SEG-02、SEG-03 的初始参数逐元素相同。
- tokens：不按 tokens 改步数；每个 arm 报告实际前向的非 padding tokens（SEG-02 含第 1 段）。
- LR：research/artifacts/T-0024/lr-lock.json（SHA256 38b8ee24af3ded8aee398a4cc3dfaa5a1dfece4737a6cde34642fbff7bf1012d）。r128 组用同家族的 LR，不另校准。
- 评估：dev 每任务 1,000 条（V1 切分）；25/50/75% 只评 dev，作曲线；主结果用最终 checkpoint；重载后复评逐条一致。

### 干预（只对 SEG-02 与释放后的 SEG-05，dev）

- iv_off：旁路出口在两段都置零，应与 SEG-00 逐条预测一致（实现检查）。
- iv_swap：第 2 段的初始状态换成同任务另一个 dev 样本第 1 段末的状态（固定 seed 的 derangement，donor 规则与 RB1 同口径）。
- iv_reset：同一权重，评估时在段界清空状态。
- 报告每种干预下的每任务准确率、宏平均，以及对正常路径的配对差与描述性区间。

### 预登记规则（运行前锁定；dev 点估计，单位 pp；阈值含等号，按精确分数计算）

1. 实现：(a) SEG-02 在 iv_off 下与 SEG-00 逐条一致；(b) 初始化时 SEG-02 的 dev 预测与 SEG-00 逐条一致；(c) 无跨段通道的 arm 跑与不跑第 1 段，第 2 段输出逐位相同；(d) 重载一致。任何一项不成立：修实现，不下结论。
2. 动态范围：任务 t 有信息量，当且仅当 RB1-07（全上下文 LoRA）− SEG-04（LoRA_seg）在 t 上 ≥ 3。Base − SEG-00 只作描述。
3. 主任务：PIQA 有信息量时为 PIQA；否则 BoolQ 有信息量时为 BoolQ；两者都没有：停止，记为分段没有拿走训练后可用的信息，不作机制结论。
4. 可学性：各训练 arm 在主任务上 ≥ SEG-00 + 1 只作描述；SEG-01 与 SEG-04 都达不到时，另记“无历史对照未学成”，主比较照算，证据记 diagnostic。
5. 主比较（r32）：gain = SEG-02 − max(SEG-01, SEG-03)，在主任务上计算。gain ≥ +3 且 iv_swap 使 SEG-02 在主任务上下降 ≥ gain/2：supports（screening）。gain ≥ +3 但 swap 降幅 < gain/2：只作描述（收益不来自第 1 段的内容）。
6. 0 < gain < +3：释放一次 SEG-05、SEG-06、SEG-07（r128，同初始化规则、顺序与样本），gain128 = SEG-05 − max(SEG-06, SEG-07)。gain128 ≥ +3 且 swap 降幅 ≥ gain128/2：supports（只限 r128）；gain128 < +1：challenges（r32 与 r128 都没有 ≥ +1 的收益）；其余只作描述。r128 之后不再加宽、换 tap 或加循环。
7. gain ≤ 0（r32）：challenges（screening），不释放 r128。
8. 次要任务（另一个有信息量的任务）用同一门槛，只在任务层面陈述。主任务不成立而次要任务成立：记 inconclusive，先做该任务两个新 seed 的复现，再下结论。
9. 宏平均与 NLL 只作描述。每条规则的结果记一条 screening 证据（实现检查记 diagnostic）；假设状态在结论审核后再改。
10. 后续：supports 时下一步是主任务两个新 seed 的复现；之后再考虑只在分隔符处写入的组（AD-0006 proposal 2）与字节匹配的显式记忆基线（AD-0005）。challenges 时停止侧支状态这条线，写机制性的阶段报告，不再做 rank、tap 或循环级联。

### 跨线（运行前固定，不改变上面的规则）

- 与 RB1（E-0021）：RB1 中 R_res 与同参数 T0 相差 −0.20 pp，信息都在 backbone 内。本契约用同一初始化、顺序与 LR，把信息移出 backbone；SEG 与 RB1 同 arm 的差只作描述（协议不同）。
- 与 M 线（H-0012）：M 线在单独编码写入下单跳读取可用；本契约是上下文中逐 token 写入，结论不互相推广。
- 不与 E-0013（V5）的官方 validation 数字比较。

### 成本、审核与记录

- 冒烟（PBS）：测两段前向的训练步时、峰值显存、评估时间与状态字节；按实测更新成本表后再放正式训练。预测超过 3 node·h 时先修订契约。
- 代码审核：分段前向与跨段状态、iv_swap/iv_reset 与分析脚本在正式训练和读取任何 SEG dev 结果之前通过代码审核；冒烟与确定性检查可以先跑。
- 记录：每个 arm 的实际前向 tokens（分段）、步数、参数（stored/trainable/有梯度）、状态 shape/dtype/字节、每段写入与读取次数、LR、源码 commit、环境 lock、模型与 tokenizer revision、node·h。
