## Findings

1. **Duplicate-write and padding-write negative controls are tautological** (`src/test_rb_core.py:180-185`).
   - **What the tests do:** lines 180-182 build a fake `accounting` with `writes=2·valid.sum()` and assert that `2n == n` fails. Lines 183-185 run the *correct* `process_prefix` with an all-true mask and assert that its counts differ from `valid.sum`.
   - **What is missing:** neither test passes a broken implementation through a gate. E-0019's 负对照 row requires it, and the package says "duplicate-write accounting and padding writes rejected".
   - **Why it matters:** duplicated writes double M and c together, which leaves the normalized KernelMatrix read unchanged up to ε. So only the M/c/counts comparison catches them, not an output check.
   - **Real protection exists:**
     - `test_prefix_reference_slot_outputs_and_all_gradients` compares M, c and counts against the reference.
     - `rb_train.train` asserts writes = input tokens.

   The conclusion is unchanged; this is about evidence quality.
   - **Fix:** monkeypatch two broken variants of `bypass_core.kernel_prefix_states`:
     - (a) every active write added twice;
     - (b) the write mask taken as all-true, ignoring `valid`.

     Assert that the prefix-vs-reference comparison (outputs plus M/c/counts) raises for each. For accounting, feed a doubled `writes` value through `TrainingAccounting`/`train`'s assertion.

2. **History interventions use physical positions** (`src/rb_history.py:69-72, 81-92`).
   - **Where:** `iv_permute` seeds with the physical `t` (`derive_seed(..., example_id, t)`). `iv_swap` takes the donor's first `min(t, T_donor)` physical positions, with `index = arange(T).clamp_max(T_donor)`.
   - **Effect:** with left padding, either in the recipient's batch or in the batch where the donor history was captured, both shift by the pad offset. The intervention then depends on batch composition and departs from the registered per-example definition.
   - **Nothing run so far is affected:** V1 scoring is one unpadded candidate per forward, the intervention tests use unpadded fixtures, and the RB1 intervention runner does not exist yet.
   - **Fix:** in `run_history`, for `iv_swap` and `iv_permute`, either:
     - reject any row (and donor row) whose valid tokens are not a contiguous block starting at 0, or
     - use logical positions `valid.cumsum(1)-1` for the seed and the donor prefix length.
   - **Verify:** one example evaluated alone and left-padded in a batch of 2 gives identical intervention outputs at its valid positions, or the guard raises.

3. **RBc candidates pay for an export plus a full fresh-reload calibration pass that E-0020 does not require** (resource; `src/rb_train.py:244-262` with `split_names=('calibration',)`).
   - **Why it isn't needed:** only the NLL feeds `lock_lrs`, and RB1 trains from scratch. The E-0013 calibration path (`v5_train.py`) also returned before saving and reloading.
   - **Cost:** from `cost-summary.json`, one calibration pass is estimated at 362-387 s per candidate (0.025-0.027 node·h). Over 12-16 candidates that is 0.31-0.42 node·h, about 38 % of the 0.82-1.09 node·h RBc forecast.
   - **Why only low:** the total stays inside E-0020's 1.5 node·h cap.
   - **Fix:** either skip export and reload for `stage=='calibration'`, or keep them and record why. Recompute the RBc row with the chosen pass count.

4. **The RBc/RB1 entry point has never executed** (`src/rb_train.py:191-278`, `main`).
   - **Evidence:** no test calls `run`. None of the seven T-0022 jobs invoked `rb_train.py`:
     - their scripts call `rb_check`, `rb0_run`/`rb_benchmark`, `rb5_cost` and `rb_report`;
     - those drive `make_model`, `train`, `evaluate` and `export_adapter` directly.
   - **Lines exercised for the first time by RBc:**
     - stage gating
     - `config.json`
     - the LR-lock and split checks
     - monitor wiring
     - final eval → fresh reload → equality assert
     - `checkpoint.json`
     - the manifest fields that `lock_lrs` reads (`family`, `stage`, `phase`, `seed`, `failed`, `calibration.nll`, `plan.order_sha256`, `split_manifest.sha256`, `train.*`)
   - **Risk:** I found no silent-wrong-result bug in this code; the risk is a crash after a full candidate has trained.
   - **Fix:** run one short PBS smoke before RBc: `rb_train.py run --stage smoke --smoke-steps 4 --eval-limit 2` for RB1-02, RB1-01 and RB1-07. Check that each manifest is complete and has the keys `lock_lrs` needs.
