# RV-0111 结论审核（reviewer-3）

结论：规则判定、证据层级、数字与路线触发都有记录支持。H-0030、H-0031 记为 inconclusive（screening），按规则 10 停止普通设置下的这条线，都与锁定契约 E-0031@1 一致。需要先改一处解释措辞（medium）再记录；另有两处 low。

## 发现

### F1（medium，unruled_alternative）解释段把 H-QVU 对 X-01 的比较写成了同预算比较；rank 与写入位置是一起改变的

- 证据：X-01 是 r32、只写 up 的 C_up S1，有 794,624 个参数（E-0028.md 第 63 行；E-0028 的 run 记录 params.stored = 794624）。H-QVU 是 r17，有 629,000 个参数（E-0031.md 的 Arms 表；RES-0405 rules.1）。所以 d_X 比较的是一个更窄（r17）、参数少 21% 的三位置写入，和一个更宽（r32）的只写 up 写入。同预算、只写 up 的对照是 U-25（619,400），但规则 6 没有触发，U-25 没有训练（EV-0190；analysis.json rules.6_conditional_controls.triggered = false）。契约自己也把 U-25 称为“预算分配的对照，不是纯位置效应”。另外，E-0031 的 scope 写明 q/v 写入的 LR 没有单独校准，而解释段没有提到这一点。
- 影响：“把同一预算分到 q、v、up 三个写入位置，没有让 X tap 侧支比只写 up 的 X-01 更准”会被读成同预算下的位置对比，这不准确。“这个解释在 q、v、up 这一粒度上没有得到支持”作为“未得到支持”可以成立，但 d_X ≈ 0 也符合“写入覆盖带来增益，被 rank 从 32 降到 17 的损失抵消”。E-0026 只测过加宽（r128），没有测过变窄，所以这个替代解释没有被排除。这一点不改变规则 3/4 的判定，也不改变规则 10 的路线，但这句解释以后可能被引用来否定覆盖解释（重开条件里就提到“写入分配”）。
- 最小修改（替换解释段第一、二句）：“r17、629,000 参数、同一读取写到 q、v、up 的 H-QVU，与 r32、794,624 参数、只写 up 的 X-01 持平（d_X = +0.016 pp）；在与 LoRA r7 相当的预算下，它仍低于 RB1-07（−0.57 pp，区间 [−1.21, +0.05]）。rank 与写入位置同时改变；同预算只写 up 的 U-25 按规则 6 没有训练；q/v 写入的 LR 也没有单独校准。因此本实验不能把写入覆盖的作用与 rank 变窄分开：顾问的覆盖解释在这一配置（共享读取、q/v/up、LR 1e-3、seed 0）下没有得到支持，但也没有被排除。”
- 验证：对照 E-0028.md 第 63 行、E-0031.md 的 Arms 表与规则 6、EV-0190；改后的解释段不再出现“同一预算……比只写 up 的 X-01”的说法。

### F2（low，out_of_scope）“D-0076 对这条线的有界重开到此结束”可能被读成 D-0076 的全部重开都已结束

- 证据：D-0076 的标题是“有界重开 RB1-09 改进线，开始 E-0031 与 E-0032”，它同时 decides E-0032、H-0032@2、H-0033@3。T-0035（E-0032）仍未验收。
- 影响：将要记录的阶段交付 stop 如果不限定对象，可能被读成分段协议下的 E-0032 也已停止。
- 最小修改：在路线段加一句“D-0076 下分段协议的 E-0032（H-0032@2、H-0033@3）不受本结论影响”；route 与 stage 两条决定的 --targets 只写 H-0030@1、H-0031@1（以及 E-0031）。
- 验证：`rl show D-0076` 的 decides 列表；`rl task list` 中 T-0035 的状态；记录后用 `rl show` 查看新决定的 decides 边，确认不含 E-0032、H-0032、H-0033。

### F3（low，data_mismatch）阶段交付说“都经审核并在 2g 上运行”，但 RB1-02 的复评在 1g 上

- 证据：RES-0405 rules.1_implementation.checkpoint_compatibility.RB1-02.evaluation_hardware = “MIG 1g.24gb”，这与它训练时的规格相同，是 RV-0107 审过的规格 guard 的设计行为。H-QVU（ATT-0409-3）、T0-QVU（ATT-0410-2）、干预（ATT-0421-1）以及 RB1-01/07/09 的复评都在 2g 上。
- 最小修改：“新 arm 的训练、干预与 RB1-01/07/09 复评在 2g 上，RB1-02 按其训练规格在 1g 上复评”。
- 验证：RES-0405 中的 checkpoint_compatibility 字段。

- 实现与配对：两臂 stored、trainable、with_grad 都是 629,000，initial_sha256 相同，order sha256 相同，iv_off 与同分配 Base 一致，重载一致，出口第一步梯度非零。四个旧 checkpoint 都在训练时的规格上复评，翻转为 0；RB1-02 的两个成功作业逐字节相同，所以选哪一个都不带来选择效应。
- 成本：T-0034 记录的最终用量是 1.04520925 node·h，包括全部失败与重复，低于 1.3/2.0。
- 路线：停止这条线、不开 AD-0007 的提案 2 和 3，与规则 10 的锁定文本一致。AD-0007 自己对提案 1 的停止条件（实用门失败就放弃这个配置；一次失败不说明所有注意力写入都无效）也与结论的范围句一致。H-0014 是 paused/challenged，H-0021 是 paused/inconclusive，与包中所述一致。
- 证据层级：都是 screening、单 seed、只含行抽样，没有越级。结论没有把工程失败当作反证：失败的 attempt 都是规格 guard 在开始前退出或被取消，没有进入比较。
