## New finding

**Low — H-0023/24/25 are left pending without X-01 even when the available contrasts already decide them** (`src/rb_improve_analysis.py:44-46`, and `activate_*` at :55 and :58).

The preregistered rules decide some outcomes from a single contrast:
- "任一 >= +1 -> challenges" (any ≥ +1 → challenges) for H-0023;
- "任一 >= +1 -> supports" (any ≥ +1 → supports) for H-0024 and H-0025.

So a qualifying contrast decides the outcome whatever the missing X-01 contrast turns out to be:
- L-56 − RB1-09 ≥ +1 pp;
- G-T − RB1-09 or G-QN − Q-N ≥ +1 pp;
- P-T − RB1-09 ≥ +1 pp.

Only the "all < +1 / all ≤ 0" branches need the X-01 comparison. Example: drop X-01 and set L-56 = RB1-09 + 1 pp. The code returns `outcome: 'pending_X01'` and `activate_H0027: False`; the contract gives `challenges` and activates H-0027.

This changes nothing while X-01 is valid. If E-0028's rule 1 were overturned, it would hold back a decided outcome and its follow-up trigger. That would delay a decision, not reverse one.

Fix:
```python
def gain_partial(deltas, complete):
    deltas = list(deltas)
    if any(d >= ONE_PP for d in deltas):
        return 'supports'
    return any_gain(deltas) if complete else 'pending_X01'

h23 = 'challenges' if any(d >= ONE_PP for d in up.values()) else 'supports' if x_available else 'pending_X01'
h24 = gain_partial(ig.values(), x_available)
h25 = gain_partial(pair.values(), x_available)
```
Keep the `pending_comparisons` lists. Accepting the current, stricter behaviour explicitly is also reasonable while X-01 is valid.

- L-56 − RB1-09 = +1 pp gives H-0023 `challenges` with `activate_H0027` true.
- G-T − RB1-09 = +1 pp gives H-0024 `supports` with `activate_H0028` true; P-T = +1 pp gives H-0025 `supports`.
- With every available delta ≤ 0, all three stay `pending_X01`.
