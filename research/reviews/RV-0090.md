## Findings

### 1. LR calibration treats a non-finite candidate as a stop, not as an exclusion (low)
- **Location:** `src/rb_improve_lr.py:39-41`, `src/rb_improve_lr.py:69-71`; `src/rb_improve_train.py:214`, where a `TrainingDiverged` exception propagates and the stage leaves only a `partial` manifest.
- **Evidence:** The E-0029 design says the LR is "按 E-0020 短训练规则单独校准 … 在有限候选中取 (NLL − min)/min <= 0.01 的最小 LR". E-0020's rule (E-0020.md:43) is "非有限候选淘汰；按初始网格中有限值的原始最小 NLL 决定扩展". `candidate_grid` raises on any `failed` candidate, and `endpoint` requires all three initial LRs to be present and finite. A diverged candidate, plausibly the 3e-3 extension, would therefore make the lock impossible and halt E-0029.
  - Plausibility: RB1-07's own minimum sat at the 1e-3 endpoint and its 3e-3 extension was already much worse (NLL 1.706 vs 1.583; T-0024 lock inputs).
  - Cost if triggered: there is no wrong result, but a code change after calibration would force re-running every calibration candidate (the lock requires one common `source.commit` equal to the training source), plus the smoke and the three I-G collections.
- **Impact:** resource_waste (conditional).
- **Fix:** Either explicitly accept the stricter reading, citing the contract's stop line "工程失败（…非有限…）时停下报告", or implement the E-0020 rule before calibration starts:
  1. In the calibration stage, catch `TrainingDiverged` / `EvaluationNonfinite`, record `failed=True`, `calibration.nll=None` and `failure_reason`, and mark the stage complete with `validator.passed=True`. Other exceptions still fail.
  2. In `candidate_grid`, accept such candidates as `None` only when `failed is True` and a failure reason is present.
  3. Make `endpoint` decide the extension from the finite initial-grid values, and raise if all are non-finite.
  4. Make `lock` choose among finite candidates.
- **Verify:** Add a unit case to `test_rb_improve_lr.py`: a candidate at 1e-3 marked failed should still lock among the finite candidates without an extension. A second case: with 3e-4 the finite minimum at the endpoint of the finite set, the extension should follow E-0020's raw-minimum rule. Then check that `verify_lock` reconstructs.

  ```python
  if diagnostic['training_inputs'] != sources[arm]:
      raise ValueError('reference diagnostics replayed a different checkpoint')
  ```
- **Verify:** Run the analysis on the eventual inputs, then mutate one byte of a copied X-01 manifest reference in the spec; the analysis should reject it.
