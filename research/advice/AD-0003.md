**1. Assessment and the actual bottleneck**

The original gate failed. That fact must remain unchanged. The same checkpoint nevertheless provides substantial diagnostic evidence of useful T2 hop1 memory use: 89/334 correct versus 0 zero-memory, 4 shuffled, and 9 permuted; normal NLL 3.626 versus 9.582/8.175 for zero/shuffled. The learned key/value pairing matters at least at this intervention level. This is one adapted seed, not confirmation of H-0005.

The all-position criterion is poorly matched to this causal question format. For a representative 24-token question, holding the non-final mean at 0.052 gives approximately (0.384 + 23*0.052)/24 = 0.066. Even a final-position weight of 1 would produce only 0.092. Thus training the last read to perfection would not pass 0.125 without also changing earlier reads. Some early causal positions do not yet contain the complete subject/relation query. The T1-to-T2 difference therefore changes what the average demands, not just its measurement noise. This arithmetic illustrates the mismatch; it is not an independently recomputed corpus statistic.

There is stronger transfer evidence than the question emphasizes. In ATT-0196-1/run/metrics.json, evaluation.by_hop gives final-position target weights 0.383877, 0.423922, and 0.361573 for hops1, 2, and 3. The target is the FIRST path fact, not the terminal edge: src/v3_loop.py:check_path explicitly enforces target_fact_index == path.fact_indices[0]. The template in src/v3_data.py contains no hop count. First-edge addressing therefore already transfers to longer paths at a descriptive level, despite endpoint EM of 4.2%/0.9%.

Two cautions change the interpretation:

- src/v2_memory.py:read_vectors implements oracle_key by using the stored key as the query. It is not a perfect address oracle or a key-separability upper bound. Its lower accuracy than normal does not establish that keys are unusable.
- oracle_value inserts the value of target_fact_index at all read positions. On hops2–3 this is the first bridge value, not the answer-bearing terminal value. Its almost-zero endpoint accuracy is not evidence that the endpoint decoder cannot work. On hop1, the decline from 75.8% to 66.8% is a real descriptive change, but does not by itself prove catastrophic forgetting: the normal soft-read distribution and the forced one-slot intervention differ, and both projection and fusion were updated.

The bottleneck is now whether an answer-trained first read can be turned into a useful next query, with a decoder that can consume the resulting state. In src/bypass_core.py:LatentReader, S1 trains the read and its output increment; it never requires z1 to serve as input to a second read. The same value/Ro path is used for decoding and for moving the next query. That representational compatibility has not yet been trained or tested under the intended mixed-hop objective. The prior frozen S_eval>1 failures do not answer that question.

Final-position attention is a sensible readiness diagnostic because src/v2_memory.py:answer_logits scores the final valid question token. It is not a complete causal explanation: later backbone layers can use earlier question positions. Keep behavioral memory interventions and report all-position statistics rather than replacing the entire interpretation with one favorable attention number.

**2. A prospective T2 readiness rule**

Amend the contract before another evaluation or training decision. Call this “T2 readiness,” not “the original H3 passed.” Preserve EV-0111 and the old gate output. The current dev results motivated this amendment and must be described as such.

For S=1, E=16, define W_h as the episode mean of the first-path-fact weight at the final valid question token, separately for each hop h. Use this fixed rule:

1. On hop1, EM_normal - max(EM_zero, EM_shuffled) >= 10 pp.
2. On hop1, NLL_normal < min(NLL_zero, NLL_shuffled).
3. W_h >= 2/E = 0.125 for each h in {1,2,3}. This checks access to the first edge across the relevant inputs; it does not require correct multi-hop answers from S1.
4. Existing implementation, finite-output, provenance, and reload checks remain required. Report target-slot histograms, natural/shuffled support-order strata, and normal-versus-permuted behavior to detect a position or pairing shortcut. Keep the old all-position mean explicitly descriptive.

The 0.125 choice preserves the original twice-uniform address enrichment, while changing the position/stratum being measured. It is not a theoretically sufficient threshold for solving a chain. Do not tune it to 0.38, introduce a 50% argmax threshold because the observation is 50.6%, or pick a different checkpoint after looking.

Apply the locked rule once to the existing released T2 calibration split, provided its D5/start-checkpoint results have not already been inspected. If they have, use a predeclared fresh diagnostic split with the same generator; it is not a replacement confirmation set. This is an independent diagnostic check of an amended rule, not a retroactive preregistration. No need to consume confirmation or OOD slices. In V4 the rule, warm-start schedule, and handling of failed seeds must be locked before the three new seeds; do not silently discard failed starts.

The observed dev checkpoint satisfies the numerical parts of this proposed rule. That is a retrospective observation, not an already completed prospective check.

**Is a hop1-only warm start valid?** Yes, for the comparison E-0022 actually specifies: all arms inherit the same checkpoint and subsequently receive identical hops1–3 examples, order, optimizer reset, and 6,000-step budget, with training unrolled at their respective S. The comparison estimates the value of trained recurrence conditional on this initialization. Hop1-only training would be insufficient if the whole experiment merely increased S at inference, or continued training only on hop1 and claimed supervised multi-hop competence. Neither is the proposed matrix. Requiring mixed-hop S1 competence beforehand risks selecting against precisely the limitation recurrence is intended to address. A mixed-hop warm start is a later optimization alternative, not a validity requirement.

**3. Related research checked**

All “checked” entries mean I inspected the cited primary text, not that I reproduced its experiments. Transfer to this frozen-Qwen adapter is my inference, not a finding of those papers.

1. Sukhbaatar et al., *End-To-End Memory Networks*, arXiv:1503.08895v5, §§2.2, 4.2–4.4. Checked the residual hop update, adjacent and layer-wise tying, linear-start training, and trained hop comparisons. This is the closest precedent: repeated reads are trained end to end, and compatibility between output and next-input spaces is explicitly addressed. It supplies no theorem that an S1 checkpoint should improve when reused at larger S. [Primary text](https://arxiv.org/html/1503.08895v5).
2. Miller et al., *Key-Value Memory Networks for Directly Reading Documents*, EMNLP 2016, §3.1, pp. 1402–1403; arXiv:1606.03126; DOI 10.18653/v1/D16-1147. Checked distinct addressing/value representations and the learned query update between memory accesses. This supports treating retrieval, value decoding, and query transition as separate diagnostic questions. It does not validate this project's “oracle_key” as an optimum. [Paper](https://aclanthology.org/D16-1147.pdf).
3. Hudson and Manning, *Compositional Attention Networks for Machine Reasoning*, arXiv:1803.03067v2, §§2.2, 4.3. Checked the separate control/memory states and their ablation. It motivates a conditional investigation of interference between task control, retrieved content, and output decoding; it is not evidence to replace the current reader with a full MAC architecture. [Primary text](https://arxiv.org/html/1803.03067v2).
4. Geiping et al., *Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach*, arXiv:2502.05171v1, §3.3. Checked training over sampled recurrent depths and unrolling. The relevant lesson is that useful extra inference depth is trained into the model. Their model, scale, and changing transformer representations differ from fixed-memory adapter reads, so their reported gains do not predict V3 gains. [Primary text](https://arxiv.org/html/2502.05171v1).
5. Jain and Wallace, *Attention is not Explanation*, NAACL 2019, DOI 10.18653/v1/N19-1357, abstract. Checked the authors' report that different attention distributions can produce equivalent predictions; I did not inspect or reproduce every experiment. This cautions against treating the revised attention gate as the mechanism claim. [Primary abstract](https://aclanthology.org/N19-1357/).
6. Wiegreffe and Pinter, *Attention is not not Explanation*, EMNLP 2019, DOI 10.18653/v1/D19-1002, abstract. Checked the proposed uniform baseline, seed calibration, frozen-model diagnostics, and adversarial training tests. Together with the preceding paper, it supports testing attention in the actual computation instead of either dismissing it or declaring it sufficient. [Primary abstract](https://aclanthology.org/D19-1002/).

Distinguishing prediction: a trained S2/S4 improves equal-weight hop2/3 EM over independently trained S1. Use the existing +3 pp and hop1 >= -1 pp criteria for advancing. If promising, release fixed-query at the winning S, fixed-total-step-size, T0, and wider S1 before any independent-iteration claim. Proposal 2 — Test whether unnecessary prefix reads interfere with useful final-position access.

Explains: T2 adds many low-target-weight positions; their branch outputs could interfere with the final answer even when the last read is useful. This is a causal interference hypothesis, distinct from denominator dilution. The latter alone does not justify changing the read mask.

Difference from tried routes: previous last-position interventions concerned T1/contextual or E=1 settings, not this adapted, isolated-write T2 checkpoint. Change the read mask while holding the text, memory, and parameters fixed; do not change the question template at the same time.

Cheapest test: on a predeclared calibration sample, compare normal all-position reads, last-only reads, non-last-only reads, and donor-memory counterparts. At S1, zero the branch increment at the excluded positions. Predict that last-only improves hop1 EM by at least 10 pp with lower NLL while the corresponding donor-memory change does not produce the same benefit. This threshold is a proposed prospective diagnostic decision rule. Inspect both removal directions; final-position weight alone cannot identify where useful information entered.

Expected cost: approximately 0.01–0.02 node-h of frozen evaluation, or up to 0.04 including new-path checks, scaled from ATT-0196-1's 56.9-second six-control/1,000-row evaluation. It can share the readiness job. Only if the diagnostic succeeds and the main screen needs repair, consider a matched S1/S4 retraining pair with last-only reads, about 0.30–0.40 node-h. That changes the read protocol and needs a distinct registered scope; it cannot be mixed into the original comparison.

Drop condition: no predeclared EM/NLL improvement, a matching donor-memory improvement, or loss of the normal-memory advantage. Keep all-position reading in those cases. This is a bounded alternative to trying several shorter prompts after seeing scores.

Proposal 3 — Diagnose and, only if supported, supervise value-to-next-query compatibility.

Explains: a value vector that decodes the first answer need not move z into a state that addresses the next head. This is distinct from prefix interference and from simply extending the hop1 optimizer schedule.

Cheapest test: if the trained triad fails, use fixed-memory diagnostic interventions on a locked hops2–3 calibration subset. Compare the learned transition with (i) a forced correct first-edge value followed by the native update/read, (ii) the query-side state from the same T2 template with the head replaced by the gold bridge entity, and (iii) a terminal-edge value oracle for endpoint decoding. Include a wrong bridge with the same relation and an unrelated donor bridge; record read weights and answer NLL, not just norms. The bridge query and terminal oracle use gold path information and are diagnostic-only. Do not call the current first-edge oracle a terminal oracle, and do not interpret an oracle intervention as an attainable upper bound.

Distinguishing prediction: terminal values remain decodable, and the explicit bridge query addresses the next edge, while the native update after a correct first value does not. That identifies a transition-representation problem worth targeting. If both native and bridge queries fail, the evidence instead points toward address/feature limitations and does not justify an alignment loss. If endpoint-value forcing also fails, decoder/fusion needs attention first.

Conditional improvement: one small S4 pilot adding successor-slot cross-entropy on the actual subsequent reads, with coefficient 1 fixed in advance, against an otherwise identical pilot with permuted successor labels. Use the existing mixed-hop sample order and count the additional labels. Two 2,000-step pilots should cost approximately 0.15–0.25 node-h including evaluation/checks, after remeasurement; the frozen diagnostic approximately 0.02–0.04 node-h. This tests whether explicit transition supervision rescues the circuit. It is a different, supervised hypothesis, not evidence for the answer-CE-only H-0005 claim. It does not authorize another full matrix automatically.

Drop condition: the prerequisite bridge/terminal controls fail, or correct successor labels do not improve held-out path access and endpoint behavior over the permuted-label control within that fixed pilot. Stop this rescue rather than repeatedly changing losses, widths, and prompts. A positive pilot earns a new scoped proposal, not an unsupervised success label.
