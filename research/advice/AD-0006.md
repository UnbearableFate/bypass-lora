## 1. State: what the evidence supports, at which level, and what it does not

**RB1 (screening, seed 0, dev 1,000 rows/task) establishes three things.**

- Every adapter is "effective" (Base +7 to +9 pp), but 12.3-15.5 of those points are BoolQ (68.0 -> 80.3-83.5) and 0.1-2.1 are PIQA (72.3 -> 72.4-74.4). The gain is mostly BoolQ template calibration. The dynamic range left for mechanism differences on this benchmark is about 2 pp per task.
- R_res S1 minus T0 is -0.20 pp [-1.30, +0.90]: the causal side state adds nothing measurable over the same parameters used tokenwise (T0 is `silu(norm(z)Rq + k) * v`, the identical Aq/Ak/Av/Rq/Ro/P_R with no state). R_res minus LoRA r7 is -1.85 pp [-3.00, -0.70]. With E-0013 (3 seeds, official validation: tokenwise C_up minus all-28-layer LoRA r1 = -0.42 pp [-1.02, +0.20]) the interface family has now been measured at or below a near-budget LoRA in two independent settings. Nothing in RB1 suggests the sign flips with width.
- Loop (+0.35) and concat (+0.40) sit inside one interval half-width (about 1.1 pp at 1,000 rows/task) and inside the spread the project has measured across seeds (EV-0110 per-seed paired differences span 0.3 pp). A +1 pp single-seed gate is at the noise floor; "inconclusive" is the expected verdict of this design for any true effect below about 2 pp. It is not information about the mechanism.

**What the intervention grid actually says.** My reading differs from "sensitivity to frozen interventions / distribution shift" (DOC-0263, D-0042):

- Residual arms (RB1-02, RB1-03): answer-position reads are concentrated (n_eff 1.1-1.8 on PIQA at all four layers; 1.2-4.8 on BoolQ layers 13/20/27; only BoolQ layer 6 is diffuse, n_eff 111 of 145). Current-token weight is 0.001-0.01 and `iv_strict` (drop the current token) is a no-op (+0.05). `iv_swap` (another episode's whole past, same task) costs only -1.85 pp, while `iv_permute` (own past, values reassigned among positions) costs -17.15 pp, `iv_window8` -14.0 and `iv_window1` -30.1. A read that sits on one non-current position, survives replacing the entire past by another episode's past, but not permuting values within its own past, must sit on a position whose write is identical in every episode of the task. The only such position is the first prompt token ("Goal" / "Passage"): by causality its Q/K/V at every layer depend on that token alone, and the tap is pre-RoPE, so its key/value write is bit-identical across episodes of a task. The residual branch's state read is therefore, to first order, a per-task constant: a positive-kernel attention sink, the linear-attention analogue of the sinks in Xiao et al. A constant plus the tokenwise nonlinearity is a function T0 represents as well, which explains the T0 parity without any history content. This is a hypothesis from the summary statistics; proposal 3 checks it at zero training cost.
- Concat arms (RB1-08, RB1-09): reads are near-uniform over the prefix (relative n_eff 0.73-0.96 at layers 6/13/20; current weight 0.01-0.05). Permuting values under a uniform read is an identity by construction, and the grid shows exactly that (-0.35 and -0.65, intervals include 0); window and swap change the prefix mean and cost 1-5 pp. Their state read is a bag-of-tokens mean of low-rank values, a summary the frozen attention already has in a richer form.
- Consequence: the "swap and permute each drop >= 1 pp" clause of GH is met by mechanisms that use no episode-specific history, so D-0042's "dynamic or nonlinear adaptation" is already the most that can be said, and the sentence "the trained memory arm's output depends on the side state" should not be read as "depends on history content".

**What the records do not support:** that the side history is useful on PIQA/BoolQ; that r32 lacks capacity (the state is unused, not full); that loop or concat differ from S1 by less than about 2 pp in either direction; any cross-line pooling.

**The M line in one sentence:** when the information is outside the backbone, the reader works only with isolated writes (H-0012, 3 seeds, single hop) and the multi-hop and repair routes failed under every change tried (D-0033, D-0036, D-0035). That is the opposite regime from RB1 (information fully inside the backbone), and the two lines bracket the coordinator's question: the state is readable when the backbone cannot see the facts, and unused when it can.

## 2. Related work (locator; what I checked; what it adds here)

1. **Infini-attention**, Munkhdalai, Faruqui, Gopal 2024, arXiv:2404.07143 §3.2 eqs. 7-10, §4, Table 2. Checked (v2 HTML read verbatim by a subagent). The compressive memory is this project's state: M <- M + sigma(K)^T V, z <- z + sum sigma(K), retrieval sigma(Q) M / (sigma(Q) z), sigma = ELU+1, reusing the attention's own Q/K/V; local softmax attention is computed within a segment (N = 2048) and the memory is the only route to earlier segments; one learned scalar gate per head blends the two. Every reported result uses inputs longer than one segment (passkey 32K-1M, PG19/arXiv-math at 32K, BookSum at 500K); no short-context result is reported. RB1 tested an Infini-attention-style memory in the one regime its authors never evaluate: a single segment that local attention already covers.
2. **LoLCATs**, Zhang et al. 2024, arXiv:2410.10254 v3, §3.3.1, Table 5, App. B.4. Checked. Softmax window w = 64 plus linear attention, LoRA r = 8 to correct. Table 5 (Llama 3 8B, average LM-eval): pure linear attention with attention transfer 55.3, window + linear 70.7, window alone 68.8. Linear-attention features are a poor substitute for in-window softmax attention and no feature map closes that gap; what the linear part adds is reach beyond the window. This bears on option (b) (taps) and (a) (width): neither changes the regime.
3. **Based**, Arora et al. 2024, arXiv:2402.18668 §3.1-3.2 (Thm 3.1), §4.2. Checked. "linear attention alone struggles to solve associative recall"; recall capacity of any causal model is bounded by its recurrent state size (Omega(N) bits for MQAR); the hybrid uses 64-128-token softmax windows for precise local recall and linear attention for long range. Implication: an r32 state (4,224 floats per layer) cannot hold a 110-token passage for exact recall but can hold a 7-word goal; this orders the tasks in proposal 1 and makes a width ladder interpretable there.
4. **Zoology**, Arora et al. 2023, arXiv:2312.04927 §3.1, Def. 3.1. Checked. 82% of the gated-convolution vs attention perplexity gap is associative recall; MQAR defined. Supports a recall-type readout as the sharp test of whether a state carries content.
5. **Dodge et al. 2020**, arXiv:2002.06305 Table 3. Checked. Seed standard deviation of validation performance for BERT fine-tuning on small tasks: MRPC .061, RTE .069, CoLA .101 (0-1 scale). Background for the noise floor; the project's own adapter seed spread (EV-0110) is smaller, about 0.3 pp, but the row-level interval at 1,000 rows/task is +-1.1 pp.
6. **StreamingLLM / attention sinks**, Xiao et al. 2023, arXiv:2309.17453 §3. Not checked beyond abstract and search snippets. Autoregressive LMs put large attention on the first tokens regardless of content; window attention collapses when they are evicted. Supports the sink reading of RB1-02 and argues against implementing proposal 1 with a sliding-window mask (sinks evicted); two-pass segmentation avoids it.
7. **Activation Beacon**, Zhang et al. 2024, arXiv:2401.03462. Not checked beyond abstract. Frozen LLM, trained module condenses past chunks into beacon activations; short-context ability preserved; 4K -> 400K. Precedent for proposal 2 (summary writes at few positions) with a frozen backbone.
8. **Recurrent Memory Transformer**, Bulatov et al. 2022, arXiv:2207.06881. Not checked. Memory tokens carried across segments; the protocol family of proposal 1.

## 3. Bottleneck

The tasks give the state nothing to carry. On PIQA/BoolQ every token the side state could summarize is already visible to the frozen softmax attention at the same layer, so the branch can only act as a tokenwise adapter (T0 shows it does) or as a sink/mean summary (the grid shows it does). In that role its differences from T0, loop, concat and LoRA are at most about 2 pp, below what one seed at 1,000 rows/task resolves. No same-layout probe changes either fact. The project is blocked not by capacity or features but by the absence of a setting in which "history" and "no history" predict accuracies that differ by more than the noise floor. H-0018's pass criterion (R_res >= Base+1 and within 1 pp of a matched LoRA) has no T0 and cannot move H-0014; and because both R_res and a matched LoRA scale with width, a pass or fail at r64 would not move H-0013 beyond "within 1-2 pp of LoRA", which two settings already show.

## 4. Proposals (at most three, different mechanisms)

### Proposal 1. Segmented information access on the existing tasks: cross-segment side state with a same-parameter T0

1. **Explains:** why R_res = T0 in RB1 and why the M-line reader works with isolated writes: the state matters only when the backbone cannot attend to the information.
2. **Difference from routes tried:** not a new layout, tap, width, loop or interface. A new information-access protocol on the F-line tasks (the Infini-attention regime): each example is processed as two backbone passes with the backbone KV discarded between them, exactly the M-line support/query machinery (`process_prefix(state=...)` already continues the KernelMatrix state across chunks). PIQA: segment 1 = "Goal: ...", segment 2 = "Solution: <candidate>". BoolQ: segment 1 = "Passage: ...", segment 2 = "Question: ... Answer:". Only the four-layer side state crosses the boundary; original attention is untouched within each segment. Register it as a third protocol (segmented F line), reported separately from F- and M-line results (plan §2.3). It is the bounded-KV / streaming use case, which is also the honest form of claim (4).
3. **Distinguishing prediction and controls:** arms at seed 0, 2M tokens each, locked LR families: Base_seg (eval only; floor), T0_seg (same parameters, no history; recalibrates the template but cannot see segment 1), R_res_seg r32 S1 (history), R_res_seg with the state reset at the boundary (same mechanism, history confined to the current segment: separates cross-segment history from in-segment linear mixing), LoRA_seg r7 (standard adapter, no channel). Full-context Base and the RB1 arms are the ceiling. If the mechanism works: R_res_seg minus T0_seg on PIQA is several pp (the goal is 7 words median, 12 at p90, **recomputed**; it fits an r32 state), `iv_swap` of the segment-1 state removes most of the gain and `iv_off` returns to Base_seg; on BoolQ (passage about 110-120 tokens, larger than r) the gain is smaller and grows with r. Pre-registered gates: PIQA R_res_seg minus T0_seg >= +3 pp (about three interval half-widths) and swap drop >= half the gain -> history supported in this protocol; r128 R_res/T0 pair released only if the r32 gain is positive but below 3 pp. Report write and read counts, state bytes and the two-pass cost.
4. **Cheapest test and cost:** four training arms plus one evaluation at 0.27 node-h per 2M-token arm (RB1 measured; two shorter passes cost about the same as one), interventions and smoke about 0.4 -> about 2 node-h in total, one implementation task plus code review (segment index in the data adapter, two-pass training step from the M-line code, four-layer state carry, segment-1 swap donor). Do not use a sliding-window mask on the frozen backbone (transformers 4.57.1 would allow `layer_types = sliding_attention` on all layers, but eviction of the first tokens breaks the frozen model for reasons unrelated to information, Xiao et al.); two passes avoid that.
5. **Drop if:** R_res_seg minus T0_seg < +1 pp on PIQA at r32 and again at r128. That would mean a contextually written low-dimensional causal state cannot carry even a 7-word segment to a frozen backbone; stop the whole side-state program with a mechanistic stage report. Also drop if `iv_off` of R_res_seg does not match Base_seg (implementation) or if Base_seg on PIQA is not clearly below full-context Base (then the segmentation removed nothing and the test has no dynamic range).

### Proposal 2. Summary writes instead of per-token contextual writes (inside the segmented protocol)

1. **Explains:** the M-line finding that contextual per-token values do not read back (value context shift, EV-0087 to EV-0091) and the capacity bound: a 110-token passage written token by token exceeds what an r32 state can hold for recall (Based, Thm 3.1), while a few summary writes do not.
2. **Difference:** changes what is stored, not how it is read: write only at segment-final or delimiter positions (sentence ends and the newline before "Question:"), the Activation Beacon / RMT idea, using the existing `write=` mask of `process_prefix`; plan2 §12.1 lists this axis ("写入范围") and asks for the real write count to be reported.
3. **Prediction and controls:** on BoolQ-segmented, delimiter-only writes beat all-token writes by >= 1 pp with the same T0_seg control, and swap removes the gain. Controls: all-token-write R_res_seg (proposal 1), T0_seg, write counts.
4. **Cheapest test:** one or two extra arms in the proposal-1 matrix, 0.3-0.6 node-h; only after proposal 1 shows a PIQA gain (otherwise the reader, not the write set, is the problem).
5. **Drop if:** delimiter writes do not beat all-token writes on BoolQ-segmented by >= 1 pp, or lose on PIQA-segmented.

### Proposal 3. Zero-training diagnostic that settles what the RB1 state read is (for the stage report, not a probe)

1. **Explains:** the swap-versus-permute asymmetry of the residual arms and the permutation immunity of the concat arms (section 1).
2. **Difference:** no training, no new arm. Two numbers from the existing tracing path (`prefix_read_metrics` already forms the per-position eligible weights): per task and layer, the mean share of answer-position read weight on prompt position 0 (and on positions 0-2), and a constant-read index, the mean pairwise cosine of the read vector a_t across episodes at answer positions. Run on RB1-02/03/08/09 dev with the same evaluator and checkpoints.
3. **Prediction:** RB1-02/03 position-0 share > 0.5 at layers with n_eff < 2 and cross-episode cosine > 0.9; RB1-08/09 share about 1/n (uniform) and cosine moderate. Controls: the same numbers under `iv_strict` (unchanged) and `iv_window8` (position 0 excluded).
4. **Cost:** about 0.05 node-h (one evaluation job per arm; the six-condition intervention job cost 0.13 node-h per arm).
5. **Drop if:** the position-0 share is < 0.2 at the concentrated layers; the read then sits on content positions, the swap result needs another explanation (same-task donors carrying similar content), and the stage report should say so.

## 5. Recommendation

**Rule 9: option (d), no same-layout probe.** (a) A width probe inherits the T0 parity (both sides scale with r) and the practical question is already answered in two settings at the resolution the project can afford. (b) Taps change T0 and R_res alike, and the residual reads are already concentrated, so feature selectivity is not what is missing. (c) Reads are diffuse only at BoolQ layer 6, and the concat arms are near-uniform everywhere yet score the same. Record H-0018 as not worth its cost, close RB1 with the stage report, and in the report state the intervention table as sink/mean reads after proposal 3 has been run (0.05 node-h).

**M line: close with a stage report now.** H-0012 supported (single hop, isolated writes, 3 seeds); multi-hop transfer and the repair routes challenged or inconclusive; no further repair round.

**Then continue with one bounded contract** (proposal 1, about 2 node-h of the 183 remaining, proposals 2 and 3 attached), because it is the only setting in which a causal low-dimensional side state should help in principle, the literature (Infini-attention, Based, LoLCATs) locates the value of such memories exactly there, the project's own M line shows the reader can work, and the design yields a large effect in either direction with a same-parameter T0 and the existing swap/off interventions. If its drop condition triggers, stop the side-state program; do not open a second backbone, more layers or a confirmation stage before a positive exists in this protocol.
