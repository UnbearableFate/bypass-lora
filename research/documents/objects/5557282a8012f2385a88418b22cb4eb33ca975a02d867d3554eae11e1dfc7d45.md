## test_rb_read_diagnostics.py — checked against `rb_read_diagnostics.prefix_read_metrics` and `rb_history.run_history`

### Shares in the explicit-distribution test (:61-69)

Each expected value is built independently from the eligible slot list and matches production `rb_read_diagnostics.py:87-96`:

| Metric | Test expectation | Production |
|---|---|---|
| `share0` | prob of history index 0 | `probability[..., :min(1,L)]` |
| `share0_2` | prob summed over history indices < 3 | `probability[..., :min(3,L)]` |
| `argmax0` | argmax over all slots, gated on slot 0 being eligible | same |
| `uniform0` | eligible slots at index 0 / readable | same |
| `uniform0_2` | eligible slots below index 3 / readable | same |

- **iv_swap:** history is the donor, and the appended recipient-current slot never enters the shares, on either side.
- **iv_window1 and iv_window8 at late t:** index set below 3 is empty, and both sides give 0.
- **iv_permute:** reassigns values only, and keys and c stay fixed (`rb_history.py:83-100`). Its read weights therefore equal the None case, as both the test and production assume.

- under iv_window1, index 0 is ineligible for t ≥ 1, so `share0` and `argmax0` are 0.

### Actual read vector (:178-215)

- **Read before the exit.** The trace computes `observed.read(query)*read_gain` from the same intervened M, c and counts that the reader consumes (`rb_history.py:114-127`).
- **Tracing changes nothing.** The traced and untraced paths call the same `state.read`, and iv_permute's seeded `Random` is deterministic. This is what makes `outputs` bitwise equal with and without tracing.
- **Identity with the output.** For inclusive S1 with the `increment` readout, `LatentReader.forward` gives z−z0 = η·(a@Ro) (`bypass_core.py:256-278`). That is the identity the test asserts. The `AdapterConfig(branch='memory', rank=4, steps=1, impl='prefix')` defaults are inclusive, accumulate, increment and no fixed query, and the config is still valid at f46a13d.
- **Independent slot form.** It checks `q·k` weighted values divided by (q·c + eps_read), with query = elu1(rmsnorm(q)@Rq) and key = elu1(rmsnorm(k)). This matches KernelMatrix in `kernel_prefix_states`. The windows also match: window8 covers t−7..t, matching the cumulative-sum differencing, and strict covers positions < t.
