## Findings

### 1. medium (result_error): three of four negative controls are tautological — `src/test_core.py:176-199`
Evidence: the E-0001 Design requires a deliberately broken implementation for kernel_identity, causality, reset_padding and rw_counts, and requires that "对应测试会失败". Only `test_kernel_identity_negative_control` (202-212) runs the real identity assertion (same `assert_close`, same 2e-5) against a broken read. The other three never call the check they control:
- Future leak (178-185) compares two hand-computed scalars `(k*v).sum(1)[:,0]` that differ by construction. It never runs `process_sequence` or the prefix assertion in `test_sequence_padding_causality_and_accounting`.
- Repeated write (188-192) shows that M after 3 writes differs from M after 1 write. It never runs `test_depth_does_not_multiply_write_count` against a writer that writes once per loop step.
- Padding write (195-199) shows that `write(valid=False)` differs from `write(valid=True)`. It never runs any padding/count assertion against a writer that ignores `valid`.
These three controls pass whether or not the causal, padding and count checks can detect anything, so they do not establish what the contract asks for.
Fix: move each assertion into a helper and run it against the real implementation (must pass) and a broken one (must raise). Sketch:
```python
def _assert_prefix_invariant(run, v):
    changed = v.clone(); changed[:, 3] += 1000
    torch.testing.assert_close(run(v)[:, :3], run(changed)[:, :3], atol=2e-5, rtol=2e-5)

def test_negative_control_future_leak():
    torch.manual_seed(9); q, k, v = (torch.randn(2, 4, 32) for _ in range(3))
    reader, valid = LatentReader(32), torch.ones(2, 4, dtype=torch.bool)
    def leaky(vv):   # full-sequence K^T V, then read at every t
        full = process_sequence(q, k, vv, reader, valid=valid, read=torch.zeros_like(valid)).state
        return process_sequence(q, k, vv, reader, state=full, valid=valid,
                                write=torch.zeros_like(valid)).outputs
    _assert_prefix_invariant(lambda vv: process_sequence(q, k, vv, reader, valid=valid).outputs, v)
    with pytest.raises(AssertionError):
        _assert_prefix_invariant(leaky, v)

@pytest.mark.parametrize('steps', [2, 4])
def test_negative_control_repeated_write(monkeypatch, steps):
    original = MemoryState.write
    def per_step(self, k, v, valid=None):
        for _ in range(steps): self = original(self, k, v, valid)
        return self
    monkeypatch.setattr(MemoryState, 'write', per_step)
    with pytest.raises(AssertionError):
        test_depth_does_not_multiply_write_count(steps)

def test_negative_control_padding_write(monkeypatch):
    original = MemoryState.write
    monkeypatch.setattr(MemoryState, 'write', lambda self, k, v, valid=None: original(self, k, v, None))
    with pytest.raises(AssertionError):
        test_sequence_padding_causality_and_accounting('inclusive')
```
Verify: the new controls pass, which means each broken variant is rejected. Temporarily removing `pytest.raises` makes each control fail. CPU only, seconds.

### 2. medium (invalid_experiment for V2; does not block V1): the support phase writes every valid token and has no write-scope input — `src/bypass_model.py:146-148`, `:235-258`
Evidence: `SideBranch.forward` passes `write=valid` in every non-query phase. `BranchModel.forward` has no argument that narrows the write positions. Plan §8.1 locks the first M-line round to `write_scope=visible_fact_delimiter`: one write per fact at the delimiter, so E=16 writes. §16.4 also sets `slot_capacity: 16`, `slot_overflow: error`. The handoff note documents `support = model(ids, phase='support')` as the M-line API. Used as documented, V2 would write every support token (hundreds of writes), which changes n_write, the state load and the protocol the arms are preregistered on. Nothing would report it. `process_sequence` already accepts a `write` mask; only the adapter fails to expose it.
Fix: add `write_mask=None` to `BranchModel.forward`. Accept it only in the support phase, and require it to be a subset of `valid`. Pass `valid & write_mask[:, -T:]` through `layer.request` to `SideBranch` as the `write` mask. Optionally enforce a configured slot capacity for slot backends: raise when `state.counts.max() > capacity`. If this is deferred, record it as a V2 prerequisite and remove the plain `phase='support'` usage from the V2-facing note.
Verify: run support with a delimiter mask of 2 positions per row. Expect `accounting[14]['side']['writes'] == 4`, `cache.memory[14].counts == [2, 2]`, and slot_count 2 for the slot backends. Passing `write_mask` in the query or F phase must raise.

### 3. low (nonblocking): model-level checks have no positive control, and query-phase reads are never asserted — `src/test_model.py:149-169`, `:194-223`
Evidence: the side-branch logit effect with `nonzero_exits` (std 0.02) is never measured. The model-level passes in ATT-0004-1 are `cache.chunk3` 0.0, `causal` 0.0, `owner_reorder` 0.0, `shared_support` 0.0, and `cache.chunk1` / `query.cache*` ≤ 0.25 against atol 0.50002. A side branch that contributed nothing at layer 14 in the cached or query path would produce the same numbers. `test_m_line_access_ownership` asserts support reads == 0 and query writes == 0, but never asserts query reads == steps·tokens. It also never shows that query logits depend on which support memory is supplied. The step-2 gradients in the two-step test do show the branch is live in the uncached F path, and the code is correct by inspection (`bypass_model.py:148`), so I am not claiming a current failure. The point is that these checks would not catch a regression. For the tokenwise-decode comparisons, detection power also depends on the effect being well above 0.5.
Fix: compute Base logits before entering `adapted(...)`, because a direct Base call inside the context raises. Record `side_effect.max_abs = |full.logits - base_logits|` over valid positions and assert it is > 2·bf16_atol. If it is smaller, raise the nonzero_exits std rather than the tolerance. In the M-line test, add `assert query.accounting[14]['side']['reads'] == 2 * ids[:, :4].numel()`, and assert that a swapped-owner query (`memory=support.cache.reorder(tensor([1, 0])).memory`) differs from `query.logits` by more than bf16_atol.
Verify: the new metrics appear in the manifest. Forcing `read=zeros` in the query phase makes the M-line test fail.

### 4. low (nonblocking): kernel_identity does not exercise masks, several write counts or empty rows — `src/test_core.py:20-47`
Evidence: the contract row says "随机 k/v/q 与 mask；多种写入数". The test writes 5 all-valid slots in every row and nothing else. The two backends mask in different ways: KernelMatrix zeroes `m_add`/`k_add`, while the slot backends store a zeroed key plus a `slot_valid` flag and multiply the weights by it. Their agreement under mixed masks, rows with zero writes, and partial resets has not been tested. By inspection they agree, because invalid slot keys are zero and empty rows are handled by `torch.where`, so this is a coverage gap rather than a defect.
Fix: parametrize over slot counts {1, 5, 17} and per-row random valid masks, including one row with no valid writes and one row reset in the middle of the sequence. Compare outputs and q/k/v gradients at the same 2e-5 tolerance.
Verify: the new cases pass. The existing normalization-drop negative control still fails.

### 5. low (nonblocking): BranchCache backbone is mutated in place, and missing query memory reads as empty — `src/bypass_model.py:240-267`
Evidence: `past_key_values=cache.backbone` is passed to HF, and `DynamicLayer.update` reassigns `self.keys`/`self.values` on that same object (transformers cache_utils.py:119-120). The returned BranchCache shares the object. After `model(x, cache=c)`, `c.backbone` has therefore advanced while `c.memory` has not. Reusing `c`, for example to score several candidate answers from one cached query prefix, silently desynchronizes backbone and memory. Separately, `memory={}`, or a memory dict from a config with different layers, passes the `memory is None` guard. `process_sequence` then builds an empty state, and the query reads zeros without any error.
Fix: (a) when `cache.backbone` is set, require `cache.backbone.get_seq_length() == attention_mask.shape[1] - input_ids.shape[1]`, otherwise raise 'stale or reused cache; reorder/copy before reuse'. (b) In the query phase, raise if any memory-branch adapter has `states.get(i) is None`.
Verify: a second forward with the same cache raises, and a query with `memory={}` raises.

### 6. low (nonblocking): key normalization ignores the configured `eps_norm` — `src/bypass_core.py:269`, `:281`
Evidence: `elu_plus_one(rmsnorm_no_affine(kbar[:, t]))` uses the default 1e-6. Only the query side uses `reader.eps_norm` (line 209/212). The default equals the plan value, so nothing is wrong today. A registered eps variant, or a reload with a non-default `eps_norm`, would normalize k and q differently.
Fix: pass `reader.eps_norm` at both write sites.
Verify: a core test with `eps_norm=1e-2` gives different keys and state.M than the default.

### 7. low (nonblocking): "all backbone parameters requires_grad=False" is asserted tautologically — `src/test_model.py:71`
Evidence: `originals` collects only the parameters that already have `requires_grad=False`. A backbone parameter that was accidentally left trainable would be excluded and never checked. The SGD optimizer only receives adapter parameters, so the zero-change assertion cannot catch it either.
Fix: `backbone = {n: p for n, p in base.named_parameters() if '.side.' not in n}; assert not any(p.requires_grad for p in backbone.values())`, then use `backbone` for the before/after comparison.
Verify: temporarily setting `requires_grad_(True)` on one backbone weight makes the test fail.

### 8. low (nonblocking): the gradient identity is checked on hand-written expressions, not on the hook-based Fusion path — `src/test_model.py:120-125`
Evidence: the gradient with respect to P is compared only between the hand-written `pre` and `dual` expressions (110-118). The actual `Fusion('C_dual')` hook path is compared on output only. `Fusion('F_pre')` is never used in the identity test.
Fix: build `fusion.C_g, fusion.C_u` from a fresh leaf `p2` and compute the target from `Fusion('F_pre')` with `P=p2`. Compare `autograd.grad` with respect to `p2` through both Fusion objects at the fp32 tolerances.
Verify: the gradient metric is recorded for the implementation path.

### 9. low (nonblocking): read accounting is derived from the config, not counted — `src/bypass_core.py:276`
Evidence: `reads += read_rows.numel() * steps` comes from the requested steps. Plan §16.1 asks the Accounting module to "记录实际路径，不只从配置推算". Writes are cross-checked through `state.counts`, but reads have no observed counter.
Fix: count `state.read` calls inside `LatentReader.forward` (for example, return the number of reads or add to a counter) and accumulate the actual value.
Verify: the accounting test values stay the same; a reader that skips a step makes them fail.
