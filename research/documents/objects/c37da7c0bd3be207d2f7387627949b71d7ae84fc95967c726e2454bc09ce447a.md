## 发现

### L1（low，result_error 的潜在路径）：同规格复评只在启动脚本里强制，分析会接受跨规格的 RB1-07 复评
- 位置：src/rb_qvu_analysis.py:160-171（只在 same_profile 为 True 且有翻转时报错）；research/notes/T-0034-run.pbs:33-38（guard 只在 reevaluate 作业里）。
- 证据：每次 smoke 都会生成一个完整的 `reference-RB1-07` 复评（不加 eval-limit）。runs/ATT-0404-1/reference-RB1-07/manifest.json 的状态是 complete，
  stage 为 checkpoint_evaluation，hardware 为 1g.24gb，compatibility 为 {flips: 18, same_profile: false}。即将运行的最终 smoke 会在 49f7009 上产生同样的目录，
  source.commit 也正确。如果 analysis spec 的 reevaluations.RB1-07 指向它，analyze() 会全部通过：合并的 RB1-07 分数将用 1g 上的 calibration 预测，
  而 d_L = H-QVU − RB1-07 >= 0 是一个精确门槛。dev 上 18 条翻转约占 2,000 行的 0.9%，足以让临界情形改变 H-0030 的结果。
  协调者的口径（T-0034-cost.md：RB1-01/07/09 必须 2g、RB1-02 必须 1g，“1g smoke 的跨规格检查不能替代”）没有反映在分析的输入检查里。
- 修复（最小）：在 :167-169 之后加上
  `if m['metrics']['compatibility']['same_profile'] is not True: raise ValueError('legacy reevaluation must use the training MIG profile')`；
  也可以再读取 rerun/'mig-profile.json'，要求 passed 为 True、expected_profile 等于该 arm 规定的规格。
- 验证：在 analysis_fixture 中把 RB1-07 复评的 same_profile 改成 False，断言报错；把真实 spec 指向 ATT-0404-1/reference-RB1-07 时也应报错。

### L2（low，nonblocking）：unavailable 的原因是无法核查的自由文本
- 位置：src/rb_qvu_analysis.py:109-125；src/rb_qvu_eval.py:87-94（复评失败时，manifest 只写 partial，不记录异常）。
- 证据：契约规则 8 的豁免只适用于“无法用当前代码载入”；成本表也写明，同规格的预测不一致属于实现失败，不得当作 unavailable。
  但 `legacy_inputs` 接受任何非空字符串，也不要求指向失败的那次尝试，所以同规格翻转（rb_qvu_eval.py:70-71 报错）可以被写成 unavailable，分析照常通过。
  失败的复评 manifest 里也没有错误信息，结论审核无法用机器核对原因。
- 修复：在 unavailable 条目中要求 `attempt`（失败复评的输出目录）；分析检查该目录的 manifest 是 partial，arm 与 source.commit 一致，并把 manifest 与日志的 reference 写入 sources；
  rb_qvu_eval 的 finally 中加上 `metrics['error'] = repr(exc)`（用 except 捕获后重新抛出），使原因可以核对。
- 验证：fixture 中缺少 attempt，或 attempt 指向 complete 的复评时报错；指向一个 partial、带 load 错误的复评时通过。
