## Design

协议来源：plan §9.1（T2 链终点任务：关系含义、终止规则与答案由可见图决定，问题不给出真实跳数）、§13.1（phase 身份与 seed）、§13.2（路径长度、负载、名字与顺序分离；Base 与 LoRA 小 pilot 做难度检查）。生成器与 V2 T1 共用渲染方式与名字池，便于 V3 沿用 V2 选定的配置。

### 任务（T2 链终点，phase V3）

- 每个 episode 有 E=16 条事实，渲染与 V2 相同：`{head} {relation} {tail} ;\n`；关系标签沿用 V2 的 4 个；每条事实在可见分隔符处有一个写入位置（write_scope=visible_fact_delimiter，位置只由文本决定）。
- 问题：查询关系 r 在 4 个标签中均匀选取。问题模板对所有 hop 相同，只给出起点 X 与 r，不给出跳数，例如 `Starting from X, keep following the r facts until there is no further r fact. Who is reached?\nAnswer:`。措辞由实现者确定，固定后写入数据 metadata；单 token 答案与答案边界不变性按 V2 的方式检查。
- 图结构：
  - 关系 r 的 12 条事实组成不相交的简单链：每个实体对 r 至多一条出边、至多一条入边，无环。答案是从 X 沿 r 走到没有 r 出边的实体。答案永远不等于 X。
  - 其余 4 条是其他关系 r' ≠ r 的干扰事实：头实体取自 r 链上的实体，尾实体从名字池抽取（可以与链上实体重名）；任何实体对同一关系至多一条出边。
  - 恰好一半 episode 的查询链终点带有一条干扰出边（按下标交替），使“忽略关系类型走到底”在这一半 episode 中出错；其余干扰事实的头实体从其他 r 链实体中抽取。
- 链长构成（train、calibration、dev 与 confirmation，hops 1–3 共用同一分布）：12 条 r 事实分成若干条链，每条长度 1–4，至少两条链长度 ≥ 3；在满足条件的构成中均匀抽样。hop h 只由起点决定：在所有“到所在链终点距离恰为 h”的实体中均匀选取起点。这样 hops 1–3 的图结构分布相同。
- 封存外推切片（hops 4/6/8）：同样 12 条 r 事实与 4 条干扰事实，链长上限放宽到 8，至少一条链长度 ≥ h；其余规则不变。结构分布与训练不同（链更长、链更少），在 metadata 中报告。
- hop 分配：train、calibration、dev 与 confirmation 中按下标轮换 hops 1/2/3（各 hop 计数相差 ≤ 1）；支持顺序按下标交替：偶数为“链顺序”（逐条链沿 r 正向列出，干扰事实插在随机位置），奇数为预先固定的随机顺序。两个轴的组合均衡。
- 名字：train、calibration 与 dev 只用 V2 的 seen 名字池；unseen 名字池只用于封存切片。名字池必须与 V2 的 `name_pools.json` 完全相同（核对 sha256）。链上实体在 episode 内不放回地按 V2 的抽样权重（高频层与低频层 3:1）抽取；答案的频率层作为分层轴报告。

### 切片、身份与独立性

- 大小（phase V3）：train 的大小使 3 个 epoch 覆盖至少 5.5M 输入 tokens（按 V2 的计数：support + question，按实测取 1,024 的倍数）；calibration 2,048；dev 1,000；confirmation 2,000（hops 1–3，seen）只登记身份与内容哈希。
- 封存 OOD 切片只登记身份与内容哈希，不生成可读文本，不做任何模型评估：hops 4/6/8（seen 名字）各 1,000；hops 1–3（unseen 名字）1,000。
- 身份包含 study_id、phase、生成器版本、task/layout、base seed、split 与 index；seed 由 `derive_seed(20261029, "concat_loop_v2", phase, purpose)` 派生（`derive_seed` 来自 `src/v1_data.py`）。生成器以 phase 为参数，以便 V4 用 phase V4 生成独立数据；本实验只生成 phase V3。
- 每个 episode 记录完整路径（起点、各桥实体、终点）以及路径上每条事实在支持顺序中的下标，供 V3 的每步寻址诊断、key/value oracle 与中间状态干预使用；这些字段不进入模型输入。
- 独立性：语义内容哈希（事实集合 + 问题，忽略顺序与渲染）在所有切片之间不重复，与 V2 T1 数据（`runs/ATT-0039-1/data/`）的实际哈希比较重叠为 0；与旧 LoopLora registry 的不重叠沿用 T-0005 的构造证明（新关系标签），并说明它对 T2 同样成立。
- 两次独立生成的文件哈希必须一致。

### 结构捷径基线（无模型，calibration 与 dev，分 hop）

逐项报告：先验（train 最佳常数答案）；随机 r 终点猜测的期望 EM（每个 episode 为 1/r 链数）；忽略关系类型走到底；最长 r 链的终点（并列时取期望）；支持文本中最后出现的 r 终点；首个桥实体（起点的直接 r 后继）。

按上述构成（12 拆成长度 1–4、至少两条链 ≥ 3，构成均匀抽样）的期望值：随机 r 终点猜测约 17%（平均 6 条 r 链）；最长 r 链终点在 hops 1/2/3 约 17%/33%/47%。后者要求先知道链长，本身就要沿链走，只报告，不设门槛。

门槛（只检查数据，任何模型评估之前）：hops 2–3 上，先验 ≤ 5%，随机 r 终点猜测 ≤ 30%，忽略关系类型走到底 ≤ 55%。不满足时，在本实验内调整链长构成或干扰事实位置并重新生成，记录理由与前后数值。

### 难度检查（模型）

- 所有模型指标同时按支持顺序分层报告：链顺序下，写入端在上下文中能看到整条链，可能在写入时就组合出终点；随机顺序下这种组合大多不可用。
- M 线 Base：只给问题，在 dev 上评估完整词表 EM 与答案 NLL（分 hop），检查 ≤ 先验 + 5 pp。
- F 线 Base：support + question，在 dev 上评估 EM、NLL 与问题主语复制率（分 hop），只作难度信息。
- F 线 LoRA 小 pilot：复用 T-0009 合并后的 `src/v2_fline.py` 的训练与评估路径（如需支持 T2 数据，只加数据选择参数，V2 默认行为与测试不变）；V2 共同配方的样本顺序规则用于 T2 train（purpose 换成 V3 的 train-order），batch 8，0.2M tokens，学习率用 E-0008 选出的值；在 calibration 上报告分 hop 的 EM 与 NLL，并重载复评。pilot 只说明任务可学性，不作为 V3 的配置选择依据。
