### H1 (high): the analysis marks every real SEG-X7 run as a rule-1 failure, so every outcome becomes invalid_implementation
- Location: src/seg_w_analysis.py:86-87.
- Evidence: the check `segment2_writes_all_tokens` requires `writes == reads == train.segment2_tokens` in every segment-2 layer. For a T0 arm the side branch reports `writes: 0, reads: 0` (bypass_model.py:202-203), and seg_train asserts exactly that: `expected = 0 if branch == 'kernel_tokenwise'`.
  - A real SEG-07 run shows it: runs/ATT-0292-1/manifest.json has `train.segment2_tokens` 566756 and segment2 layer 6 `{'writes': 0, 'reads': 0, 'valid_tokens': 566756}`. SEG-X7 uses the same T0 branch.
  - So `rule1['seed0.SEG-X7.segment2_writes_all_tokens']` will be False. `analyze` then sets implementation_ok = False, both hypotheses become 'invalid_implementation', and `selected` becomes None. This would happen for every real seed-0 analysis, and again at seeds 1-2 if X is replicated.
  - The test does not catch it: test_seg_w_analysis.py:54 writes segment-2 writes = reads = 500 for every synthetic arm, SEG-X7 included.
- Impact: result_error. The rule-1 gate wrongly fails, and the analysis records "fix the implementation, no conclusion" instead of the real screening outcome.
- Fix: mirror seg_train's convention and also check valid tokens:
  ```python

  seg2 = m['train.segment2_tokens']; io = 0 if arm in T0 else seg2
  checks['segment2_accounting'] = all(c['valid_tokens'] == seg2 and c['writes'] == c['reads'] == io
                                      for c in m['runtime.accounting']['segment2'].values())
  ```
  Optionally also require `set(m['runtime.accounting']) == ({'segment1', 'segment2'} if arm in KEEP else {'segment2'})`.
  In the test, make `write_run` realistic: valid_tokens = 500 for all arms, and writes = reads = 0 for SEG-X7.

  - Once the seed-0 SEG-X7 run exists, run `run_rows` on it before the screening analysis.
