## Design

依据：E-0022 规则 1。起点阶段 ATT-0196-1 没有通过原门槛（EV-0111）。这个结果保留，不改写。随后做了顾问轮次 2（AD-0003、AD-0004），两位都建议继续，见 D-0031。

两位顾问都核对了：失败的只有“全部问题位置平均目标权重”这一条，而这一条量的是问题长度，不是读取质量。

- 每行的全位置均值为 `((T−1)·非末位均值 + 末位权重)/T`。
- T2 问题有 23 或 25 个 token，非末位均值为 0.052。即使答案位置的读权重达到 1，全位置均值也只有约 0.09，低于 0.125。
- T1 问题只有 7 个 token，所以同一条款在 T1 上能通过。
- AD-0004 核对了记录中全部有门槛判定的结果：改用答案位置不改变任何一条已有判定。

起点在 dev 上的情况：hop1 的 EM 差 25.4 pp；答案位置目标权重 0.384，argmax 等于目标占 50.6%；最常见的末位槽位占 7.8%。hops 2、3 在答案位置对第一条路径事实的权重为 0.424 与 0.362。

两点结构事实决定了本契约的顺序：

1. 读取只依赖问题文本。查询特征取自第 14 层输入，读出加在第 14 层 FFN 之后（`src/bypass_model.py`）。所以 S=1 时没有一次读取能依赖另一次读取。V3-01、V3-05、V3-06、V3-07 在 hops2-3 上按构造不能串联两跳，它们的主量是地板。
2. 现有 oracle_value 在 hops2-3 上插入的是第一条边的 value，不是终点边（`src/v3_loop.py` 的 check_path 要求 target_fact_index 等于 path.fact_indices[0]）。所以它在 hops2-3 上接近 0，不说明终点解码不可行。

因此本契约先检查准备度，再训练回答 H-0005 主问题所需的三组（S1/S2/S4）；其余对照只在有增益需要解释时才训练。

### 共同设置

同 E-0022 的“共同设置”与“十组”定义，包括：

- 共同起点：ATT-0196-1 的最终 checkpoint，adapter 按已记录的 digest 在加载前后核对；
- 每组在 T2 train hops1-3 上续训 6,000 步，数据顺序与样本相同；
- AdamW 重置，warmup 300 步后 cosine，每步 8 个 episode，最终 checkpoint，重载一致；
- 计时作业只在 2g.24gb 上运行（fail-fast），训练与评估可用任意 MIG 切片（D-0018、D-0019）。

V3-05b 是本契约新增的一组：S2，query 固定为第 1 步（fixed_query，Z = 2·η·a⁰·Ro），其余同 V3-02。它只在 S_M*=2 时训练，作同深度的幅度对照。

### 阶段 0：T2 准备度（不训练）

在 T2 calibration（2,048 条，hops1-3，此前没有任何 V3 运行评估过）上，用已审核的评估器评估 ATT-0196-1（S=1，六个对照）。准备度规则 R 在评估前固定，四条同时满足才成立：

1. hop1：EM_normal − max(EM_zero, EM_shuffled) ≥ 10 pp；
2. hop1：NLL_normal < min(NLL_zero, NLL_shuffled)；
3. hops 1、2、3 各自满足：答案位置（最后一个有效问题 token）上第一条路径事实的平均读权重 W_h ≥ 0.125；
4. hop1：答案位置 argmax 槽位中最常见槽位的占比 ≤ 0.25。

全位置平均目标权重只作描述。R 只检查一次，阈值不再调整。证据注明：“准备度规则在看到起点 dev 结果后制定，在未用过的 calibration 上检查”。

R 不成立时，不训练任何 arm，并做一次第二起点周期：

- 从 ATT-0196-1 在 T2 train hop1 上热重启 6,000 步（AdamW 重置，warmup 300，cosine，其余同起点阶段）；
- 在 calibration 上按 R 判定；成立则以它作共同起点进入阶段 A。

仍不成立：H-0005 暂停，重开条件写为 T2 准备度成立的新起点配方（候选如 AD-0004 的事实头 token key）。

### 阶段 A：V3-01、V3-02、V3-03

三组放进同一个通知组。评估同 E-0022，另加下面的新增诊断。S_M* 的取法与主量同 E-0022 规则 2-3。

### 阶段 B：其余对照（按规则释放）

V3-04、V3-05（S_M*=4 时）或 V3-05b（S_M*=2 时）、V3-06、V3-07、V3-08、V3-09、V3-10，放进同一个通知组。

### 新增诊断（只作描述，不进入规则）

- 每步路径权重：答案位置上第 s 步对第 s 条路径事实（path.fact_indices[s−1]）的读权重，按 hop 与 s 报告，S≥2 的各组都报。它和 E-0022 的中间状态干预一起，区分真实的串联与读出伪迹。
- 终点边 value oracle（hops2-3）：把读取换成终点边（path.fact_indices[−1]）的 value。原 oracle_value 改称“第一条边 value oracle”。两者都只是诊断，不是可达上界。
- 按答案名频率分层的 EM：用训练集中的出现次数，按中位数分高低两层。
- 这些诊断的代码在阶段 A 的评估之前过代码审核。阶段 A 的训练可以先用已审核的代码开始，诊断在审核通过后对保存的 checkpoint 运行。

### 预登记规则（运行前锁定；dev 点估计，单位 pp；阈值含等号，按精确分数计算）

1. 准备度 R 同上。R 成立才进入阶段 A。
2. 主量、S_M* 同 E-0022 规则 2-3。
3. 阶段 A 之后的四种情形：
   - A1：S_M* − V3-01 ≥ +3，且 hop1 差（S_M* − V3-01）≥ −1。释放阶段 B。阶段 B 完成后按 E-0022 规则 4 判定 GL_M，其中 (e) 在 S_M* 的深度上用 V3-05（S4）或 V3-05b（S2）：同深度固定 query 组的主量比 S_M* 低至少 3。
   - A2：S_M* − V3-01 ≥ +3，但 hop1 差 < −1。先训练 V3-09、V3-10。其中任一组对 V3-01 同时满足 (a) 与 (b) 时，释放阶段 B 其余各组，并以该组作 S_M* 的候选（另行说明）。否则只作描述，H-0005 暂停（E-0022 规则 8）。
   - A3：0 < S_M* − V3-01 < +3。只作描述，不释放阶段 B。做一次冻结转移诊断与至多一个修复 arm（见规则 4），然后写结论。
   - A4：S_M* − V3-01 ≤ 0。screening 证据 challenges H-0005@2（E-0022 规则 7）。同 A3，先做一次冻结转移诊断与至多一个修复 arm，再做结论审核。
4. 冻结转移诊断与修复：
   - 诊断（≤ 0.04 node·h），在 hops2-3 的 calibration 子集上对 S_M* 所在组运行，比较五种读取：
     - 原生转移；
     - 第 1 步强制为正确的第一条边 value 后的原生更新与读取；
     - 显式桥查询：问题主语换成金标准桥实体；
     - 错误桥（同关系）与无关 donor 桥；
     - 终点边 value oracle。
   - 修复 arm 由诊断结果按下面的对应关系决定，至多一个（≤ 0.25 node·h）：
     - 桥查询能寻址到下一条边、终点 value 能解码，而原生转移不能：后继槽位 CE 的 S4 pilot（系数 1，2,000 步），与置换后继标签的对照各一组（AD-0003 提案 3）。它属额外监督，结论单独陈述，不作 H-0005 的无监督证据。
     - 桥查询也寻址不到：线性起步的 S4（AD-0004；前段训练把读温度从平坦逐步退火），1 组。
     - 终点 value 不能解码：不做修复，只作描述。
5. 次要机制结果（报告，不判定）：hop2 行上，S_M* 组第 2 步在答案位置对第 2 条路径事实的读权重，与 1/16 和 0.125 比较；S4 同时报第 3 步对第 3 条事实的读权重。
6. 证据方向同 E-0022 规则 10。GL_M 成立记 supports；S_M* − V3-01 ≤ 0 记 challenges；其余只作描述；假设状态在结论审核后再改。每条证据都注明准备度规则的来由（见阶段 0）。
7. GL_M 成立 -> 起草 V4（E3）契约，先做结论审核。V4 从一开始就登记答案位置的准备度规则；各 seed 的起点失败时怎样处理，也在 V4 契约中预先写定。
