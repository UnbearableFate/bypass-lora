## Design

协议与指标来源：plan §8.1（M 线协议）、§8.3（诊断表与 n_eff、读误差定义）、§8.4（oracle 诊断）、§5.3（V2 默认：单层 index14、r128）、§16（模块边界）。复用 V0 的 `BranchModel` 记忆阶段（support / query）与 T-0004 合并后的容量保护；不修改 `src/v1_*.py` 与 `src/v2_data.py`。

数据接口：episode 来自 E-0005 的生成器（researcher-3，T-0005）。流水线需要的字段：支持文本与每条事实的分隔符位置、问题文本、答案 token id，以及只用于离线诊断的 target fact index 与每条事实的 (head, relation, tail)。T-0005 合并之前，用字段相同的小型 fixture 测试；合并之后，再用少量 E-0005 数据做一次端到端冒烟。

检查：
- 出口零初始化时，四种（特征 × 读算子）组合在 F_out 与 C_dual 下的 logits 都与 Base 完全相同；冻结主干无梯度。
- support 阶段只写不读，问题阶段只读不写；每个问题从同一只读快照开始；batch 内按 episode owner 索引，打乱 batch 顺序后结果不变。
- 每条事实恰好写一次（visible_fact_delimiter），写入数与 E 一致。
- 训练几步后，在一个可学的正对照 fixture（例如复制或单跳查表）上，normal memory 的答案 NLL 低于 zero memory 与 shuffled memory。
- 诊断量在构造的小例子上与手算一致（top-1、margin、目标权重、熵、n_eff、读误差）。
- oracle 开关只在评估中生效，不进入训练 forward。

冒烟：每种（特征 × 读算子 × 融合）组合跑几十步，记录步时、显存与吞吐，用于估算记忆家族校准与 V2 的成本。不做正式训练；V2 训练与记忆家族校准需另立契约。
