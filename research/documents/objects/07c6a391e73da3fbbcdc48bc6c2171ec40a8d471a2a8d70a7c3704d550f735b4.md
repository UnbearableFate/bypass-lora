## Design

来源：用户 2026-11-02 的要求（D-0052）：“我们当前项目给侧分支的低秩设为32是不是小了点, 测试一下r=128 呢”。这是 H-0018 的 r 探针，只做 r128，并按 D-0043 加同参数 T0。

### Arms

| arm | 结构 | 侧支历史 | 参数 | LR 家族 |
|---|---|---|---|---|
| W-01 | R_res + T0，S1，r128 | 无 | 按实现计，训练前登记（与 W-02 相同） | RBc-T，3e-3 |
| W-02 | R_res + KernelMatrix，S1，r128 | 有 | 按实现计，训练前登记 | RBc-R，3e-3 |
| W-03 | 同四层 all-7 LoRA，alpha=rank | 无 | rank 取参数数最接近 W-02 的整数 | RBc-L，3e-4 |

参数估计（只作核对，以实现计数为准）：RB1 的 r32 R_res 为 663,552，即每层 5·1024·r + 2r²；r128 时为每层 688,128，四层 2,752,512。四层 all-7 LoRA 每个 rank 90,112 个参数，最接近的是 rank 31（2,793,472）。参考 arm 不重跑：Base 70.15%，RB1-01（r32 T0）77.30%，RB1-02（r32 R_res）77.10%，RB1-07（LoRA r7）78.95%。

### 共同设置（与 E-0021 相同，除非这里另写）

- 结构：layers [6,13,20,27]；tap qknorm_pre_rope；backend kernel_matrix（prefix）；mode inclusive；update accumulate；readout increment；η=0.25；g=1；出口零初始化。只把 rank 从 32 改为 128。
- 初始化与顺序：与 RB1 相同，init 用 derive_seed(20261101, "residual_la_v21", "R1", "init", 0)，训练顺序用 derive_seed(20261101, "residual_la_v21", "R1", "train", 0)（plan.order_sha256 33759bc20322d0c9981128dd8574438546fc3439194ab32b7c79e35e0f0fc2bf）；26,230 个样本，13,115 步，有效 batch 2；A2 确认集的行不进入训练。W-01 与 W-02 的初始参数逐元素相同。
- LR：research/artifacts/T-0024/lr-lock.json（SHA256 38b8ee24af3ded8aee398a4cc3dfaa5a1dfece4737a6cde34642fbff7bf1012d），不另校准。
- 评估：dev 每任务 1,000 条（V1 切分）；25/50/75% 只评 dev，作曲线；主结果用最终 checkpoint；重载后复评逐条一致。

### 干预（只对 W-02，dev）

- iv_off：旁路出口置零，应与 Base 逐条预测一致（实现检查）。
- iv_swap：侧支历史换成同任务另一个 dev 样本的历史（固定 seed 的 derangement，donor 规则与 E-0021 同口径）。
- iv_permute：历史内打乱 key/value 配对（与 E-0021 同口径）。
- 报告每种干预下的每任务准确率、宏平均，以及对正常路径的配对差与描述性区间。

### 预登记规则（运行前锁定；dev 点估计，单位 pp；阈值含等号，按精确分数计算）

1. 实现：(a) W-02 在 iv_off 下与 Base 逐条一致；(b) 初始化时三个 arm 的 dev 预测与 Base 逐条一致；(c) 重载一致；(d) 参数计数与登记一致，W-01 = W-02。任何一项不成立：修实现，不下结论。
2. 可学性：各 arm 宏平均 >= Base + 1 只作描述。W-03 达不到时另记“LoRA 对照未学成”，主比较照算，证据记 diagnostic。
3. 主比较（H-0018）：d_L = W-02 − W-03（宏平均）。W-02 >= Base + 1 且 d_L >= −1：supports（screening，只限 r128）；否则 challenges（screening，只限 r128）。
4. 实用优势：d_L >= +1 且每任务差都 >= −1 时，另记“r128 侧分支在 dev 上高于参数匹配 LoRA”（screening）。下一步是 W-02 与 W-03 两个新 seed 的复现，再规划 A2 确认；开封 A2 前先报用户。
5. 历史依赖：d_T = W-02 − W-01。d_T >= +1 且 iv_swap 使 W-02 宏平均下降 >= 1：满足 D-0042 的重开条件，重开 H-0014；d_T <= 0：记“r128 下侧支历史仍没有可测贡献”；其余只作描述。iv_permute 的降幅只作描述（可能主要来自分布偏移）。
6. 宽度效应只作描述：W-02 − RB1-02、W-01 − RB1-01、W-03 − RB1-07，配对区间只作描述。
7. 每任务准确率、NLL 与曲线只作描述。每条规则的结果记一条 screening 证据（实现检查记 diagnostic）；假设状态在结论审核后再改。
8. 规则 3 为 challenges 时，普通设置下不再加宽或换 tap；本契约不测 r128 以外的宽度。

### 跨线（运行前固定，不改变上面的规则）

- 与 E-0025：分段协议里的 r128（SEG-05..07）另行登记，两份结果不合并。
- 与 E-0013（V5）：不与官方 validation 的数字比较。
- 限制：单 seed，dev 每任务 1,000 条只能分辨约 2 pp 以上的差别；r128 沿用 r32 的 LR；T0 是当前 token 的非线性门控（D-0043），不是去掉历史的同一注意力。

### 成本、审核与记录

- 冒烟（PBS）：测三个 arm 的 r128 训练步时、峰值显存与评估时间；按实测更新成本表后再放正式训练。预测超过 1.5 node·h 时先修订契约。
- 代码审核：rb_train 的 arm 表、干预与分析脚本的改动在正式训练和读取任何 W-arm dev 结果之前通过代码审核（只审改动，复用 E-0021 已审核的路径）；冒烟与确定性检查可以先跑。
- 记录：每个 arm 的实际前向 tokens、步数、参数（stored/trainable/有梯度）、状态 shape/dtype/字节、LR、源码 commit、环境 lock、模型与 tokenizer revision、node·h。
