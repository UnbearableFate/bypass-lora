## Design

来源：H-0029（用户 2026-11-02 同意为分段协议动用 A2，见 docs/constraints.md）。E-0027 的 H-0020 停在 inconclusive（D-0062：三个 seed 的 BoolQ 平均 gain 为 +2.933 pp，低于 +3 pp 的门槛，两个新 seed 的 gain 都为正）。E-0028、E-0029 没有胜出并复现的更强侧支算子（D-0066 至 D-0071，EV-0162、EV-0172），所以沿用 E-0027 的配置。这是 A2 唯一的一次开封。

### Arms（每个新 seed s = 3、4、5）

| arm | 结构 | 跨段通道 | 参数 | LR 家族 |
|---|---|---|---|---|
| SEG-05 | Keep：R_res + KernelMatrix，S1，r128 | 四层 (M, c, counts) | 2,752,512 | RBc-R，3e-3 |
| SEG-06 | Reset：同 SEG-05，段界清空状态 | 无 | 2,752,512 | RBc-R，3e-3 |
| SEG-07 | T0：R_res + T0，S1，r128 | 无 | 2,752,512 | RBc-T，3e-3 |
| SEG-04 | LoRA_seg：同四层 all-7，rank7，alpha=rank | 无 | 630,784 | RBc-L，3e-4 |
| SEG-00 | Base_seg，只评估 | 无 | 0 | 无 |

### 共同设置（与 E-0027 相同，除非这里另写）

- 分段协议、模板、候选 loss、PIQA+BoolQ 训练混合、26,230 个样本、13,115 步、有效 batch 2、LR 锁定值（research/artifacts/T-0024/lr-lock.json，SHA256 38b8ee24af3ded8aee398a4cc3dfaa5a1dfece4737a6cde34642fbff7bf1012d）都同 E-0027。训练行是 RB 训练行：按 research/artifacts/T-0022/rb-confirmation.json（SHA256 34277aa4627271dbf4e0bcb9592e3014c6130d87b1766caad17c2d6b97a8a7cc）排除 A2 的 2,000 个 id。
- seed：s = 3、4、5。研究者在训练前核对记录，确认这三个 seed 没有在 R1 阶段用过；每个 seed 的训练顺序 sha256 在训练前登记。同一 seed 的 SEG-05、SEG-06、SEG-07 初始参数逐元素相同。
- 所有判定都用最终 checkpoint（第 13,115 步），不按 dev 或 A2 选 checkpoint。25/50/75% 只评 dev，作曲线。
- 源码从 E-0027 的 054a54a 出发。为新 seed、A2 读取、A2 评估与锁定分析改动的代码，在正式训练之前通过代码审核；之后再改这些路径，要在锁定之前重新审核。

### 开封前（只用 dev、calibration 与合成数据）

- 每个训练 run 照 E-0027：初始化时的 dev 评估，25/50/75/100% 的 dev 曲线，重载后复评逐条一致。
- 每个 seed 的 SEG-05 在 dev 上做 iv_off（实现检查）；dev 上不做 iv_swap 与 iv_reset。
- 任何测试、冒烟与开封前检查都不在 A2 的行上评估模型，也不读取或汇总 A2 的文本与标签。A2 读取器的测试用合成切分；在真实数据上只核对 id 与哈希。

### A2 锁定与开封

1. 12 个训练 run 与规则 1 的检查都通过后，研究者写锁定文件 research/artifacts/<task>/a2-lock.json 并提交。内容：E-0030 契约版本；A2 读取、评估与分析所用的源码 commit；12 个最终 adapter、其训练 manifest 与最终 dev 预测文件的 SHA256；模型与 tokenizer revision；A2 id 清单文件的 SHA256 与 ids_sha256；评估设置；bootstrap 与 derangement 的种子和方法；规则 3 至 6 的摘要。研究者把锁定文件的 SHA256 报给协调者。
2. 协调者核对后以一个 decision 记录确认。确认之前，不提交任何读取 A2 的作业。
3. 开封：一批 PBS 作业，每个 seed 一个：先在 dev 上复评该 seed 的 SEG-05，再在 A2 上评估 SEG-00、SEG-05、SEG-06、SEG-07、SEG-04，以及 SEG-05 的 iv_swap 与 iv_off。每个作业启动时核对锁定文件与各 checkpoint 的 SHA256，记下分配到的硬件，并写一条 A2 读取记录（时间、作业号、锁定文件 SHA256）。全部作业结束后，在 PBS 中运行锁定的分析。
4. A2 只开封这一次。作业因工程原因失败时，只能按同一锁定文件原样重跑，每次尝试都登记；不改配置、checkpoint、规则或分析。开封之后，A2 不再用于任何确认。

### 预登记规则（开封前锁定；A2 BoolQ 点估计，单位 pp；按精确分数计算）

1. 实现（开封前，每个新 seed；diagnostic）：(a) SEG-05 在 iv_off 下的 dev 预测与 SEG-00 逐条一致；(b) 初始化时 SEG-05 的 dev 预测与 SEG-00 逐条一致（(a)、(b) 的参照按 D-0060：硬件不同时用同一分配里的 SEG-00）；(c) SEG-06、SEG-07、SEG-04 跑与不跑第 1 段，第 2 段的输出逐位相同；(d) 重载一致；(e) SEG-05、SEG-06、SEG-07 的初始参数逐元素相同；(f) 训练行与 A2 的 id 不相交；(g) A2 读取器重新生成的 id 清单与封存清单一致（ids_sha256 与文件 SHA256 都相同）。任何一项不成立：修实现，不开封。
2. 开封时的路径检查（diagnostic）：(a) 每个作业在读 A2 之前做的 dev 复评：分配到的 MIG 规格与该 checkpoint 的训练作业相同时，预测必须与训练记录的 dev 预测逐条一致；规格不同时，不一致的条数不超过 10（dev 2,000 条的 0.5%），条数另作描述。不满足时，作业不读 A2；查明并修复、重新审核后，重写锁定文件，再经协调者确认（A2 没有被读取，不算开封）。(b) 每个 seed 的 SEG-05 iv_off 在 A2 上的预测必须与同一作业里 SEG-00 在 A2 上的预测逐条一致。不一致时，A2 的结果记为无效，H-0029 不下结论，由协调者报告用户；A2 已经开封，不能再作确认。分析中的 SEG-00 取 seed 3 作业的结果；三个作业之间 SEG-00 预测不一致的条数只作描述。
3. 每个 seed 的量（A2 BoolQ）：gain_s = SEG-05_s − max(SEG-06_s, SEG-07_s)，lora_s = SEG-05_s − SEG-04_s，swap_s = SEG-05_s − SEG-05_s(iv_swap)。iv_swap 把第 2 段的初始状态换成 A2 同任务另一样本第 1 段末的状态，按 E-0025 的规则做固定 derangement，种子为 derive_seed(20261101, "residual_la_v21", "A2", "iv_swap")。
4. 汇总与区间：G = (gain_3 + gain_4 + gain_5)/3，L = (lora_3 + lora_4 + lora_5)/3。区间沿用 E-0027 已审核的口径（seg_seed_analysis.max_control_intervals）：numpy.random.default_rng(20261101)，10,000 次有放回重采样，每次从 A2 BoolQ 的 1,000 行中抽 1,000 个下标；三个 seed 与所有 arm 共用同一组下标；每次重采样中重算每个 seed 的准确率、两个对照中的较大者、G* 与 L*；95% 区间取 numpy.quantile 默认线性插值下的 2.5% 与 97.5% 分位数。
5. H-0029：G > 0 且 G 的区间下界 > 0：supported（confirmatory）。G <= 0：challenged（confirmatory）。其余：inconclusive（A2 上未确认）。
6. 次要比较（固定顺序）：只在规则 5 为 supported 时作确认。L > 0 且 L 的区间下界 > 0：另记 Keep 在 A2 的 BoolQ 上也高于分段 LoRA 参照（confirmatory）。LoRA_seg 的参数为 630,784，约为 Keep 的 23%，这不是参数匹配的比较。规则 5 不是 supported 时，L 只作描述。
7. 描述（不改变规则 5、6）：每个 seed 的 gain、lora、swap，gain > 0 的 seed 数与 seed 间标准差。规则 5 为 supported，但 gain > 0 的 seed 少于两个时，结论写明平均值主要来自一个 seed。可学性：各 arm 在 A2 BoolQ 上是否 >= SEG-00 + 1；某个 seed 的 SEG-06 与 SEG-07 都达不到时，另记“该 seed 的 r128 无历史对照未学成”，并写进结论。另报 PIQA、宏平均与 NLL，dev 上的同一组量，以及与 E-0027 dev 数字的对照。
8. 证据：规则 5、6 各记一条 confirmatory 证据，规则 1、2 记 diagnostic，其余只作描述。假设状态在结论审核之后再改。

### 跨线（运行前固定，不改变上面的规则）

- E-0025、E-0027 的 dev 数字不并入判定，只作对照描述。
- 不与 RB1、E-0026、E-0028、E-0029 的普通设置数字比较；全上下文 LoRA 只作上限参考。
- 没有其他需要在 A2 上确认的 RB 线比较：E-0028、E-0029 都没有达到复现条件（EV-0162、EV-0172），RB1 也没有（D-0045）。
- 限制：区间只含 A2 行的抽样不确定性，不含 seed 间的变化；只有三个 seed；LR 没有为 r128 或分段重新校准；A2 与 dev 都从 V1 的官方 train 中切出，分布相同。

### 成本、审核与记录

- 冒烟（PBS）：确认新 seed 的初始化与顺序、四组的步时与显存，以及 A2 读取器在合成切分上的行为；按实测更新成本表，预测超过 5.5 node·h 时先修订契约。
- 代码审核：新 seed、A2 读取、A2 评估与锁定分析，在正式训练之前通过只审改动的审核；冒烟与确定性检查可以先跑。
- 记录：每个 arm 的实际前向 tokens（分段）、步数、参数（stored/trainable/有梯度）、状态 shape/dtype/字节、LR、seed 与顺序 sha256、源码 commit、环境 lock、模型与 tokenizer revision、node·h；锁定文件与每次 A2 读取记录。
