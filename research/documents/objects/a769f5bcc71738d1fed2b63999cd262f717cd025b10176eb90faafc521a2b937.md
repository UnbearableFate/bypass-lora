E-0019 RB0 检查 ATT-0186-1（RES-0177，393 项中 390 项通过）的三项失败，按封存契约这样处理。不放宽任何锁定容差，阈值与已通过的断言都不动。

(1) 残差拓扑。契约要求“每层输出减去 H+F(U) 等于 Z·P_R（容差内）”。测试中的逐位恒等 torch.equal(Y, (X+o+F) + bf16(Z·P_R)) 在四层都成立，第 6 层 FFN 的输入与 Base 逐位相同。失败的是额外的一项比较：在 FP32 中算 Y−(H+F)，再拿 logits 的 BF16 容差 0.50002 与 Z·P_R 比。BF16 加法会吞掉小于半个 ulp(Y) 的加数，第 27 层的大激活上相对差为 1.0，即整个加数被吞掉。任何正确实现都过不了这项比较，它测到的是 BF16 舍入，不是接线；0.50002 也是按 Base logits 校准的，不适用于隐状态。通过条件改为逐位恒等，即零容差，比原比较更严。另在每个适配层逐位检查 U_i == post_attention_layernorm_i(X_i + o_i)，确保第 13、20、27 层的 FFN 输入不含侧支项。相减量只作诊断记录，以 ulp(Y) 为单位，应 ≤ 0.5。

(2)(3) cache。四层 S4、强出口夹具（std 0.5）下，chunk3 在 BF16 锁定容差内通过。逐 token decode 的 logits 差为 0.8203，超过 0.50002，prefix 与未改动的 reference 的结果相同。Base 自身 decode 的差为 0.25，锁定容差是它的 2 倍加 2e-5；强出口经过四层与 S4，把这部分舍入放大了。所以这不是 prefix 与参考不一致。BF16 容差不变，chunk1 的超出照实记录。另加一项决定性检查：同一测试在 FP32（关闭 TF32）下运行，full、chunk3、chunk1 两两比较。prefix 与 reference 都用 E-0019 的 FP32 门槛，即逐张量 max|a−r| ≤ 1e-5 + 1e-4·max|r|。再加一个负对照：在 chunk 边界清空状态 (M,c,n) 的实现，在 FP32 下必须被拒绝。BF16 下另报 prefix 与 reference 在 chunk1 上的 logits 差，应 ≤ 0.50002。FP32 检查不过，就按真实的状态续接问题处理：修复后重测，不进入训练。
