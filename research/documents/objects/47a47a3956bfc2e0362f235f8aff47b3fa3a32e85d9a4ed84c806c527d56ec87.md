## Design

依据：plan2 §6.4、§13.3、§13.5、§14.3；E-0002 与 E-0013 的校准规则和结果（T-0013 分支 research/notes/T-0013-lr-selection.md：三个 arm 的初始最小都在 1e-3，扩展到 3e-3 更差，锁定 1e-3）；E-0009（M 线 KernelMatrix 选到 1e-2）。

| 家族 | 代表 arm（锁定后用于） | 参数 | 初始网格 | 端点扩展 |
| --- | --- | ---: | --- | --- |
| RBc-L | 同四层 all-7 LoRA rank7（RB1-07） | 630,784 | 1e-4, 3e-4, 1e-3 | 3e-5 / 3e-3 |
| RBc-T | R_res+T0 S1（RB1-01） | 663,552 | 1e-4, 3e-4, 1e-3 | 3e-5 / 3e-3 |
| RBc-R | R_res+KernelMatrix S1（RB1-02..06） | 663,552 | 3e-4, 1e-3, 3e-3 | 1e-4 / 1e-2 |
| RBc-C | C_dual+KernelMatrix S1（RB1-08、RB1-09） | 1,318,912 | 3e-4, 1e-3, 3e-3 | 1e-4 / 1e-2 |

- 偏离 plan2 §6.4 的理由：§6.4 每家族 2 点（LoRA/逐 token {1e-4,3e-4}，记忆 {3e-4,3e-3}）。E-0002 三族都停在 {1e-4,3e-4} 的上端；E-0013 三个 arm 都停在 1e-3，扩展到 3e-3 更差；E-0009 的 KernelMatrix 在 M 线选到 1e-2。两点网格很可能落在边界。plan2 建议的点都在初始网格内；四个家族的候选数相同，满足 §6.4“各家族获得相同数量的候选与 token 预算”。
- 样本量：12–16 个短 run，共 2.4–3.2M 输入 tokens。plan2 §6.4 的总上限是 2M（五家族×2 点；本线四家族按原文为 1.6M），超出部分记入 §14.3 的“公平 LR 补校准”储备。
- 每个候选：seed 0；初始化 derive_seed(20261101, "residual_la_v21", "V0", "init", 0)（同家族各候选的初始参数相同）；训练顺序 derive_seed(20261101, "residual_la_v21", "V0", "train", 0)；在首次累计达到 200,000 非 padding 输入 tokens 的完整步停止；日程形状、loss 与优化器同 RB1。
- 数据：RB train；NLL 在完整的 V1 calibration（每任务 2,048 条）上计算；train 为 V1 train 去掉 RB 确认集行（D-0025，方案 A2）。不看 dev 与任何确认集。
- 规则（同 E-0013）：非有限候选淘汰；按初始网格中有限值的原始最小 NLL 决定扩展：最小在上端时追加上扩展点，在下端时追加下扩展点，只扩一次；然后在最终有限候选中取 (NLL−min)/min ≤ 0.01 的最小 LR。写 lr-lock 文件（含各 manifest 的 SHA256），在 RB1 训练前锁定。
- 已知局限：S2/S4、固定 query 与 η/4 的 arm 用 RBc-R 的 LR（plan2 按家族校准）；C_up（RB1-09）用 RBc-C（concat 家族）。写进 RB1 报告。
- 成本：每 run 约 0.05 node·h（E-0013 校准实测约 0.046 node·h/run），12–16 个 run 约 0.6–0.8 node·h；以 RB0 计时为准。
