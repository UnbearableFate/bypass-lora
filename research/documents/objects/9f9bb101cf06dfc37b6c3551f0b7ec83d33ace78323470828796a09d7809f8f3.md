# T-0035：E-0032 分段协议下的改进筛选（第 1 段写入范围与 X tap）

按封存的 E-0032 契约（research/experiments/E-0032.md）实现、审核、运行并分析。契约的预登记规则 1 至 8 已锁定，不改阈值与判定；需要改契约时先停下，告诉协调者。

## 要做的事

1. 实现（从 E-0030 的分段训练代码出发，src/seg_model.py、src/seg_train.py 等）：
   - SEG-W1：第 1 段只在最后一个有效 token 写入状态；SEG-W2：第 1 段只在句末 token 与最后一个有效 token 写入。第 2 段的写入与读取、读取函数本身都与 SEG-05 相同。
   - 句末规则按契约原文实现，训练前冻结，并用固定样例测试；报告每条样本第 1 段的写入次数（均值、最小、最大）。
   - SEG-X5、SEG-X6、SEG-X7：X tap（input_layernorm 输出）的 Keep、Reset、T0，r128，R_res；参数 2,228,224；三臂初值在 CPU 上抽取并逐元素相同。
2. 测试（PBS 上运行），规则 1 的全部检查：
   - 第 0 步与 iv_off 的 dev 预测等于 Base_seg；参数计数等于契约的表；
   - W1、W2 的初始 adapter digest 等于同 seed SEG-05 的记录值（RES-0281：seed 0 为 f3fc8b76…，seed 1 为 cfe01ba0…，seed 2 为 5fe32303…，全文见契约）；
   - 第 1 段写入掩码全为 true 时，输出与梯度和不带掩码的路径逐位相同；
   - W1 每条样本第 1 段恰好写入 1 次，W2 的位置符合句末规则，第 2 段的写入与 SEG-05 相同；
   - 在本任务的源码上复评保留的 E-0030 SEG-05 checkpoint（seed 3，research/artifacts/ATT-0379-2/adapter，2g 训练，ATT-0394-1 在 2g 上逐条复现过），用 2g，dev 预测与记录逐条一致；
   - X 三臂初值逐元素相同；Reset 在段边界清空状态；保存后重载预测逐条一致。
3. 正式训练前，按 research-review 请求代码审核（写入掩码、句末规则与分段 X tap 配置）；冒烟与确定性检查可以先跑。
4. seed 0：训练五个 arm（训练数据、顺序、步数与 LR 同 E-0025 的 SEG-05），SEG-W1、SEG-W2、SEG-X5 做 iv_swap（定义同 E-0025、E-0027）。seed 0 至 2 的 SEG-05 都在 2g 上训练，新 arm 能选时也用 2g，并记录 torch 报告的实际规格。
5. 筛选与复现（规则 2 至 6）：
   - 规则 3：Δ_V(0) >= +1.5 且 Δg_V(0) >= +1.5 才通过筛选（W 变体的 Δg = Δ）。
   - 规则 4：通过的变体中只取 Δg_V(0) 最大的一个（相同时取 Δ_V(0) 较大者）做 seed 1、2，对照用 E-0027 同 seed 的记录。开始 seed 1、2 之前，按实测重算复现成本，并告诉协调者；预测超出剩余上限时先停下，由协调者修订契约，不在中途停下。
   - 规则 5、6：supports 只按新 seed 判定，PIQA 不退化条款按每个 seed 检查；三个 seed 的 Δ 与 Δg 平均只作描述。
   - 没有变体通过时，在 seed 0 结束并报告。
6. 机制描述（规则 7）：措辞用“与……相容”；报告每层第 2 段答案位置上，第 1 段写入在 ρᵀc 中所占的比例（W1、W2，以及上面复评的 E-0030 SEG-05 checkpoint）。
7. 记录：每次 run 先 rl run register 再提交，RunSpec 的 arm 名与契约一致；结果导入、用量按实测入账（MIG-h × 0.25）；每条规则的结果写成 evidence；不改假说状态，由协调者在结论审核后决定。
