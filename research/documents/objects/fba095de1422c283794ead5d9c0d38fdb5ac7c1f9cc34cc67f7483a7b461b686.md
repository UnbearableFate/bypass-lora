## Finding

### 1. Medium: an attempt that dies without a manifest makes the locked analysis impossible to run (src/seg_a2_attempt_audit.py:50-59, 218-243; src/test_seg_a2_attempt_audit.py:93-99)

Every runtime writes its manifest only in a Python `finally` block: seg_a2_eval.py:142-153, seg_train.py and seg_a2_analysis.py. A walltime kill gives no Python exception: PBS sends SIGTERM and then SIGKILL, and Python's default SIGTERM action ends the process without running `finally`. The same holds for a host OOM kill, a node failure, or cancelling a job that has already started. Such an attempt ends with measured scheduler usage but no `manifest.json`.

This creates two contradictory requirements:
- **Cost coverage requires declaring it.** `_complete_cost` requires the declared attempts to equal the set of attempts that have measured usage, and the runbook requires including all terminal attempts, failures too.
- **The audit rejects it once declared.** `audit_attempts` raises "accounted attempt … has no manifest.json" for every declared attempt, whether or not it relates to the lock. The test at lines 93-99 asserts exactly this.

The worst case is an A2 job killed after `read_a2`, at which point `a2-read.jsonl` already names the lock:
- If it is declared, the missing manifest raises.
- If it is left out, discovery finds the matching receipt and raises "unaccounted lock-matching attempt".

Either way the analysis, which is locked before opening, can never complete. That is so even though contract stop rule 4 and D-0072 allow an unchanged rerun. A2 would be consumed with no valid result.

How likely this is:
- It is low per job, since walltime is sized at 1.5× the measurement. But it is irreversible once the lock is confirmed.
- The same blocking affects the 12 formal runs on f741952 now in flight (research/artifacts/ATT-0379-2 … ATT-0389-2 have no manifest yet, as expected while running). It also affects dev replays and analysis reruns.
- For training runs it would show up before the lock, so it could still be fixed then. Fixing it now avoids a forced change to the analysis code later.

U-0388, the "reported" zero usage for the cancelled -1 attempts that were never submitted, is correctly left out: `measured_cost` rejects any basis other than measured. Those attempts need not be declared, so they are not affected.

**Fix.** Accept declared attempts without a manifest, and classify them conservatively:
- In `_manifest_record`, return `manifest=None` instead of raising.
- In `_audit_record`:
  - No manifest and no `a2-read.jsonl`: return category `no_manifest_unopened` with seed None. It is not lock-associated and cannot be selected. Include it in `accounted_metadata_refs` with `manifest: null`.
  - No manifest, and a receipt line naming this lock: return category `partial_opened_no_manifest`, with seed taken from the receipt, `opened=True` and `status=None`. Validate the receipt's seed, D-NNNN decision (equal to the expected one), opening protocol and time, as now. It counts as a non-selected opened attempt; a complete selected attempt for that seed is still required.
  - Treat a malformed last receipt line in a manifest-less directory (a write cut off by the kill) as opened under this lock. Classify it the same way, recording `receipt_truncated=True`, rather than raising.
- Keep raising for an *unaccounted* directory whose receipt names the lock.
- Keep raising for a manifest-less directory that is selected as a seed's evaluation root (`_verify_eval` already requires a complete manifest).

**Verify.** Replace test lines 93-99 with tests that check:
- (a) A declared ATT with no directory or no manifest is accepted and listed as `no_manifest_unopened`.
- (b) A declared ATT with only a matching receipt plus a complete selected attempt for that seed is accepted and listed as `partial_opened_no_manifest`.
- (c) Case (b) without the complete selected attempt is rejected.
- (d) Case (b) left undeclared is still rejected as unaccounted.
- (e) A truncated receipt line in a manifest-less ATT is classified as opened.

## Other points checked (no finding)

- **Selected roots.** Each must be an absolute, distinct, immediate ATT directory under research/artifacts and must be in `accounted_attempts`. It must be the only complete opened attempt for its seed. Any other opened attempt must be partial. Two complete attempts for one seed are rejected; a partial plus a complete is accepted and listed.
- **Consistency checks.** `opened` is derived from the manifest flag, the `a2.opened` metric and the receipt, and any conflict raises. A receipt whose manifest does not name the lock raises, as do several receipts naming the lock in one attempt. Receipt job ID, hardware and decisions must match the manifest. The confirmation decision must be the same across all attempts that name the lock and must equal the decision shared across seeds.
- **Stage rules.**
  - retry_profile_miss must be unopened, partial and stage `a2_evaluation`, which matches seg_a2_eval.py:95-98.
  - dev_replay must be unopened.
  - analysis attempts (manifest `stage: analysis`, now written) are never openings. This lets a previous failed analysis be declared, so an unchanged analysis retry is possible.
  - Any other stage that names the lock raises.
- **Discovery.**
  - It scans only immediate, non-symlink ATT directories, within a 10,000 bound; there are 71 today. Every existing `manifest.json` under research/artifacts parses as a JSON object.
  - A matching unaccounted manifest or receipt raises.
  - The running analysis job's own directory has no manifest yet, so it is not matched.
  - It reads only manifests and receipts, never predictions or A2 text.
- **Integration.** The audit runs after `_verify_eval` with the shared decision, and its output goes into `analysis.json`. `test_seg_a2_attempt_audit.py` is in the smoke test list, and ATT-0391-1 ran it.
- **Unchanged since RV-0098.** Rules and statistics, the training path, the A2 evaluation and gate, the lock and the descriptives.
