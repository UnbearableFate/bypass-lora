## Question
E-0014（H-0009 的六个单改动 arm，seed 0，各 6000 步×8 episode）都没有在 T1 E=16 dev 上达到 H3 门槛。我要决定下一轮筛选测哪些机制，或者暂停这条路线。现有证据分不开以下几种解释：
(a) 寻址与 value 耦合学习太慢：寻址集中之前，value 拿不到干净梯度，6000 步不够；
(b) 非末位问题位置读到的是混合值，其增量是残差的 18–51 倍，干扰下游的冻结层；
(c) 多事实上下文改变了支持侧特征，value 映射难以学成，也难以迁移；
(d) 融合出口过大，或优化设置（LR 3e-3、clip 1.0、约一半的步被裁剪）让解码难学。

已核对的关键观察：
- R1 只用 E=1 训练，在 E=1 dev 上 EM 83.6%，置零、打乱约 1%。但 R3 课程在第 1000 步时 E=1 calibration EM 只有 15.3%：即使 E=1，value 通路也要数千步才学会。
- R2 用 E=4 训练。在 E=4 dev 的最后问题位置，目标权重 0.983，argmax 全部命中目标，EM 却只有 8.2%。在 E=16 上它按关系寻址：同关系 99.8%，命中目标 24%。它的 E=16 学习曲线显示，关系寻址在训练后半段才出现。
- R5 加了地址监督：最后位置目标权重 0.52，argmax 命中目标 60%，EM 6.2%；oracle_value（所有问题位置都换成目标 value）只有 10.7%；答案 CE 到第 6000 步仍在下降。
- R1 在 E=16 dev 上 oracle_value 只有 5.8%（在 E=1 上是 83.6%）。
- R3 课程、R4 先验通路、R6 去中心化余弦和 V2-03 一样，最后位置的 argmax 在 86–100% 的样本中落在槽位 0。

请回答：
1. 哪种解释最可能，能否从已有数据推断？
2. 下一轮最便宜、最能区分这些解释的筛选怎么设计？候选有：
   - 只在已有 checkpoint 上做评估诊断：只在最后位置读取、最后位置 oracle、对目标 value 的线性探针；
   - R1 checkpoint 热启动后在 E=16 上训练；
   - E=1 与 E=16 混合 batch；
   - 只在最后问题位置读取的训练协议；
   - 更长的训练；
   - 限制融合增量的幅度；
   - 其他。
3. 键值记忆网络、快速权重、检索增强里的寻址与 value 共同学习，有哪些相关工作直接相关？
4. 如果这些都不值得，是否应暂停？
