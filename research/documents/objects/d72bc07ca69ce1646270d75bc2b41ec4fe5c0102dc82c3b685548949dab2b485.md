## RV-0099 finding 1: fixed

- **Declared attempts without a manifest are accepted.** `_manifest_record` returns `manifest=None` instead of raising (lines 97-106), and `_without_manifest` (lines 136-161) classifies the attempt:
  - **No receipt**, or a receipt for another lock: category `no_manifest_unopened`, `lock_associated=False`, seed None, manifest reference null. The grouping step skips it (line 346), so it can never count as a seed result. A missing directory works too: `resolve` and `is_file` handle a path that does not exist. Test case (a) covers both the missing-directory and present-directory variants.
  - **A receipt that names this lock**: category `partial_opened_no_manifest`, `opened=True`, status None, seed taken from the receipt. `_validate_receipt` checks that seed is 3, 4 or 5, that the decision is D-NNNN and equals the shared decision, that the opening protocol is D-0072, and that the time is ISO. Test case (b) and the invalid-metadata tests cover this.
- **Such an attempt can never be the selected result.**
  - The per-seed rule still requires exactly one attempt with status `complete` that is opened and equals the selected root (lines 365-371). A receipt-only attempt has status None, so it never qualifies.
  - `_verify_eval` still requires the selected root to have a complete manifest and exactly one receipt.
  - Non-selected openings must be either partial or this category (lines 372-375).
  - Test case (c) shows a receipt-only attempt cannot stand in for the complete result.
- **Undeclared openings are still rejected.** Discovery (lines 313-330) still raises for an unaccounted directory whose manifest or receipt names the lock. It also raises when a manifest-less directory's truncated receipt cannot be attributed to a lock: a missing `lock_sha256` counts as matching (`_truncated_matches`, line 133). Test case (d) and the unattributable-receipt test cover this.
- **Truncated receipts are handled conservatively.**
  - A malformed line is tolerated only when there is no manifest, and only on the last non-blank line (lines 78-94). It counts as an opening.
  - `_receipt_prefix_fields` keeps a field only if a complete JSON key and value are followed by `,` or `}`, so a number cut by the kill is never mistaken for a complete value.
  - Receipts are written with sorted keys. A cut before `seed` therefore leaves the seed unknown. That attempt is listed under `opened_attempts_unknown_seed` without inventing a seed, and the complete selected root for every seed is still required. Test case (e) covers this.
  - A cut field that conflicts with an earlier complete receipt raises.
  - Attempts that have a manifest still reject any malformed receipt line, and a malformed line that is not the last one still raises in either case. Tests cover both.
- **Reporting.** Declared manifest-less attempts are listed (`no_manifest_attempts`, with null manifest references in `accounted_metadata_refs`). So accounting can stay complete (`_complete_cost` declared set equals the measured-usage set) while an unchanged analysis retry stays possible.
- **The earlier rules hold.** Validation of attempts that have a manifest is unchanged: opened/flag/receipt consistency, the stage rules, the decision rules, duplicate-complete rejection and acceptance of a partial plus a complete attempt. Those tests still pass in ATT-0392-1.
