我的机制排序是：R1 的 E1→E16 失败，首先考虑 (c)；R2/R5 的低答案准确率，优先区分 (b)、value/融合适配不足及其与 (a) 的交互；(d) 的特定优化指控目前最弱。不存在足够证据给六个 arm 共同指定一个唯一原因。

就简化的 softmax 读出 r=Σ_i w_i v_i 而言，令 g=∂L/∂r，则 ∂L/∂s_i=w_i gᵀ(v_i−r)，∂L/∂v_i=w_i g。这是结构推导，不是实测：value 没有形成有用差异时，地址梯度也可能无用；寻址混合时，value 又承受混合监督。E1 中 w=1，地址梯度为零。因此 R1 热启动只预训练 value/出口，没有预训练 retriever。

2. 当前真正的瓶颈与最先做的筛选

缺的不是另一个相关性指标，而是固定 checkpoint、固定问题与答案后，独立改变“value 从哪里来”“哪些位置注入”“最后位置是否选对”的配对结果。三种因素现在混在一起。先锁定一个 256 例 calibration 子集，覆盖原目标位置；用 R1、R2、R5，没必要把全部坍塌 arm 都重跑。选择与阈值在 calibration 完成，候选锁定后才在 dev 做一次完整筛选；confirmation 不读取。

先做 R1 的配对支持侧干预。在同一个 E16 episode 上保持原问题、答案、融合参数与所有问题位置的 oracle 注入不变，只比较目标 value 来自：(i) 原 E16 support 的目标分隔符；(ii) 同一个事实按相同格式独立编码的分隔符；(iii) 将该事实移到 support 首位后编码的分隔符。都保留原始幅度。另用同位置的错误事实 value 作为负对照。比较目标第一槽与后续槽，保存逐例 EM、NLL、value 及融合范数。若 (ii)/(iii) 恢复，而 (i) 不恢复，(c) 的局部因果证据很强。必要时再做保持目标位置的前缀置换及明确 position_ids 的控制，区分前缀与位置；不用先把这一控制网格展开到所有 arm。

随后对 R2 的 E4、R5 的 E16 做以下位置干预。记 t* 为实际输出答案的最后一个有效问题 token，早期位置均指 t<t*：

| 条件 | 早期位置增量 | t* 增量 | 主要比较 |
|---|---|---|---|
| N | 原 normal | 原 normal | 原路径基准 |
| L | 0 | 原 normal | L−N：删除早期 memory 注入 |
| O | 原 normal | 目标 learned value 的 oracle 增量 | O−N：只纠正最后地址 |
| LO | 0 | 同一 oracle 增量 | LO−O：最后已正确时的早期干扰 |
| AO | 同一目标 value 的 oracle 增量 | 同一 oracle 增量 | 与原 oracle 定义对齐；与 LO 比较重复注入 |

只屏蔽侧分支增量，保留完整问题 token、attention mask、position_ids、答案评分位置与冻结主干计算。正常/置零/打乱 controls 用相同读位置协议；改 read_mask 后不能只拿旧协议 shuffled 当对照。先复现 N/AO 的已有行为和零 memory Base 恒等式。oracle 仅限诊断，不能计作部署成功或 H3 达标。

幅度只做小型预定扫描，例如 α∈{0.1,0.3,1} 加 α=0 的关闭对照，分别缩放早期增量与最后增量，其余固定；只在上述有辨别力的 checkpoint/条件上展开。若 LO 在未缩放时成功而 O 失败，更支持 (b)；若无混合的 oracle 条件也被缩放显著改善，更支持出口幅度问题。若评估时缩放或 last-only 无效，不能否定相应训练方案：预训练权重可能依赖原注入模式。

线性探针排在这些直接干预后，作为未决时的定位工具。用分离的 train/calibration episode，在相同答案类别、样本数和探针训练规则下比较原始 delimiter 特征、投影后目标 value、最后实际 read；对 R1 做 isolated→isolated、isolated→contextual、contextual→contextual 的交叉测试。原始特征好而 value 差，指向投影；contextual 自域好但跨域差，指向表示迁移；value 探针好但匹配读位置的 oracle 解码差，指向桥接/冻结解码路径。加入随机投影、答案先验与标签打乱基线。同一原 episode 的多个诊断视图不能跨 train/test。探针的闭集分类精度不能当成全词表 EM，也不能用探针失败宣布信息不存在。

所有新推理、探针和统计均由协调者安排 Miyabi 作业。成本参考是实测 R5 6000 步训练 1210.93 秒、稳定步长 0.2018 秒、最终六控制评估 58.48 秒；[原始计时](/work/xg24i002/x10041/bypass-lora/runs/ATT-0126-1/direct_hidden.soft_slot.F_out/metrics.json:10346)。据此，256 例的顺序诊断预计约 0.01–0.03 node·h；若增加特征抽取与探针，约 0.02–0.06 node·h。它们是规划估计，不是新实测，支持侧独立编码和实现检查可能增加开销；先测实际运行时间再按约束申请 walltime。

3. 最多三条机制不同的后续路线

路线一：让 value 对支持前缀稳定。优先级最高，前提是配对支持侧干预阳性。

它解释 R1 第一槽 oracle 高、后续槽低。最小改动是保留原上下文 key 和 query，只把所有事实的 value 改为逐事实独立编码后投影；每个事实都处理，槽位配对保持不变，查询前构建全部 memory，不用目标标签挑出部署时的事实。这与 R1 单纯减少槽数、R3 课程、R6 改地址几何不同。先冻结 R1 的 value/出口，在配对 oracle 条件下确认可迁移性，再决定是否训练 E16 寻址；不要一开始同时改 K、V、读位置和损失。

可区分预测：同一后续事实独立编码后，R1 oracle 恢复接近同分布 E1 水平，且目标位置差距缩小；仅缩小原 contextual value 的范数不应同样彻底恢复。负控制是错误事实、错误槽位配对及相同读位置下 shuffled。最低成本就是上述无训练替换；若进入可部署训练，只比较一个新 writer 与匹配的旧 writer 对照，先 1000 步，预留至 2000 步。两个 arm 的该阶段按原步时约 0.03–0.08 node·h 含小量评估，独立编码需 smoke 重估；允许缓存冻结 backbone 特征，但可训练投影必须每步重算。

若配对独立/首位编码没有恢复，而格式与正对照通过，则放弃“前缀稳定化即可救 R1”的方案。若 oracle 恢复而 normal 不恢复，不把它写成成功：这只解决 value 分布，尚需地址或读取协议。若部署性能只靠目标元数据才能恢复，该部署路线不成立。

路线二：只在完整问题的输出位置注入 memory，并按证据控制增量。

它解释 R2 最后地址几乎完美仍低 EM，以及 R5 的额外地址监督不能保证下游使用。不同于地址温度、先验通路，它改变的是冻结后续层接收信息的位置。首先做 N/L/O/LO/AO；若删除早期增量明显改善，训练与评估同时采用 last-only。若主要是幅度有效，先保持读位置，只试固定输出 gain 或实际融合增量的范数控制；这两个因素不能同时改变后再宣称定位了原因。限制的是 ∆=zP 的实际幅度，而不是仅限制 P 的参数范数。

可区分预测：LO−O 的改善在相同 value 下出现，L−N 也改善；若纯幅度主导，oracle 条件的 α 扫描也会改善。沿用 R1 E1 作为可用解码正对照，避免把所有成功都误判为“变回 Base”。读位置或 gain 只能在 calibration 选择。评估正结果后，做同起点、同样本与同 LR 的 1000→2000 步成对试验。成本与路线一同数量级，无训练面板单独约 0.01–0.03 node·h。

若无训练干预没有收益，它只是降低此路优先级；如果再做一次匹配的短训练，正常 memory 的差值仍不改善、oracle 解码也无改善，则按成本停止这一实现。不能因短试验失败断言任何 last-only 训练都无效。

不建议直接套一个“增量≤残差”的上限：R1 成功时已约 9 倍。Flamingo 的 tanh gate 也不是实际输出范数的硬上限。此外，本实现 P 已零初始化，若再把乘在 P 分支外的 gate 也初始化为零，会令 gate 和 P 两侧的启动梯度都为零；不能照搬双零乘积。

路线三：在 E16 分布内拆开 value 学习与地址学习。

它检验 (a)，同时避免 E1 预训练引入的支持侧分布差异。只有在前两项诊断后仍显示“目标 value/冻结桥接需要学习”时启动。选择一个已锁定的读位置协议，从 R5 checkpoint 出发，冻结地址参数，只训练 A_v、R_o、P；训练时直接提供同一 E16 support 的目标 learned value。与同起点、同冻结参数、同样本、同 LR、同更新数的普通 read 续训比较。先检查 500/1000/2000 步的 held-out oracle EM/NLL。如果 value 真正可用，再冻结 value/出口，单独训练地址，最后进行有限联合微调；同关系错误实体是必须保留的困难负例。

这是新的额外监督课程，必须单列，不能归到 answer-only 成功。它与 R5 从头同时优化答案 CE 和地址 CE 的关键差别，是不给尚不可用的另一个模块继续污染当前模块的学习信号。可区分预测：相同 E16 特征与相同训练预算下，oracle 训练让 value 解码显著快于普通 read；其后 normal 与 shuffled 的差距随地址学习出现。若只提高 oracle、normal 仍不提高，说明组合/寻址仍是瓶颈。

最低成本为上述两臂 1000 步，约 0.03–0.05 node·h 含评估；2000 步约 0.06–0.08 node·h，均待 smoke 验证。若在正对照通过、原始特征探针有效的情况下，这个最干净监督也没有有用 held-out 趋势，则不批准普通 CE 的长训练；若继续仅有 oracle 改善而 normal 没有趋势，也暂停。它们是经济停止规则，不是学习不可能性的证明。

对所列候选的直接取舍：现有 checkpoint 干预最先；R1 普通热启动到原 E16 不排前列，因为原数据已显示后续位置的 value 不迁移；混合 E1/E16 只在确有遗忘证据后用于保留能力，不会自动教会同关系实体区分，比较时必须报告 E16 暴露量，不能把一半 E16 更新换成 E1 后声称训练预算等价；last-only 的部署训练按路线二；更长训练只给出现验证趋势的一个 arm。当前 cosine 在最后一步降到零，见 [lr_multiplier](/work/xg24i002/x10041/bypass-lora/src/v2_schedule.py:117)，而 export 只保存 adapter；从最终 checkpoint 再训要明确重启 optimizer 和非零 LR。这是新的续训配方，不是原训练的无缝自然延长。不要同时扫 LR、clip、gain、warm-start 和混合比例。

5. 继续、暂停与证据边界

现在不建议彻底停止。R1 已经证明某个实际 value/冻结桥接可用，而现成位置分层给出此前未利用的强线索；用几组配对干预获得信息，预期价值高于重跑完整训练网格。建议先为整个诊断与至多一条条件触发的短训练路线设约 0.15 node·h 的初始额度，协调者按 smoke 和真实账本调整；这不是要求用满，也不是总项目预算的重新授权。三个建议是条件分支，不是同时开跑的三组网格。

可预先采用的继续标准：配对诊断出现方向一致、NLL 同时改善且 EM 提升至少约 10 pp 的大效应，或最干净 oracle 训练达到 ≥50% held-out EM 并能进一步转化为 normal−max(zero,shuffled) 的明确改善。阈值是建议的筛选规则，必须运行前登记，不是事后确认性显著性标准。若只有 1–2 pp 的不稳定变化或 CE 小幅下降、没有分解后的机制信号，就停止扩大训练；一个经过干净正对照验证的短训练仍无正常 memory 改善时，暂停这一单层 learned-memory 配方，优先推进已有独立价值的 F 线。

成功后也不能改写 E-0010 的失败。特别是 last-only 把原 token-mean 地址量改成只读一个位置；应新登记协议，同时报告实际读取位置的权重和兼容的全问题诊断，不能把新的末位平均数直接称为通过旧 H3 的同一统计量。额外 target labels、不同 writer、重启 LR 和额外训练预算都必须单列。尚无新 seed 或 confirmation，所有下一轮结论仍是筛选/诊断。
