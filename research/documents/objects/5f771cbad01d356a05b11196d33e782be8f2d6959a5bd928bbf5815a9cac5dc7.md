## 1. 状态评估：证据支持什么，不支持什么

### 1.1 先把架构的一个事实放在前面

在 V2-03 配置下（direct_hidden、SoftmaxSlot、F_out、S=1、readout=increment），从 value 到残差流的整条解码路是**线性**的：
value_i = A_v·n_i（n_i 为分隔符处 input_layernorm 之后的 hidden），读取 a = Σ_i w_i value_i，增量 Z = η·a·R_o，融合输出加 Z·P。唯一的非线性在寻址 softmax 里。因此"解码器"= 一个秩 ≤128 的线性映射 W = A_v R_o P，作用在分隔符 hidden 上，再被冻结的第 15–27 层和 lm_head 读出。这解释了几件事：
- E=1 能学会（R1 83.6%），因为尾实体在分隔符 hidden 上线性可解码（E-0012 L1：99.6%）。
- 融合增量 9–50 倍于残差不是异常，而是这个线性"覆写"解在冻结下游上的正常形态：R1 在 E=1 上成功时也是 9.0 倍（我核对）。所以幅度本身不能解释失败（见 1.4）。
- 读到混合值时，增量就是各 value 解码方向的混合；寻址塌缩到一个固定槽位时，增量近似常量，解码器把它学成答案先验（NLL 4.42 ≈ 先验熵）。

### 1.2 对四种解释各自有多少证据

**(c) 多事实上下文改变了支持侧特征：对"迁移"是直接证实的；对"难学成"尚未测。**
我核对 R1 在 E=16 dev 的 oracle_value（所有问题位置换成目标 value）按目标位置分层：目标是第 0 条事实时 45/52 = 87%（NLL 0.37）；第 1 条及以后合计 13/948 = 1.4%（NLL 16.8），第 1 条就只有 3/57。同一条事实，有前文时写出的 value 对 E=1 学到的 W 完全不可用，而且不是渐变。R1 的 oracle_value 增量/残差比：位置 0 为 8.8（与 E=1 的 9.0 一致），位置 ≥1 为 22.0——E=1 学到的 W 在位置 ≥1 的 value 里放大了某些在位置 0 几乎恒定、因此从未被训练约束过的分量。这是典型的欠定线性映射下的协变量偏移。R5（在 E=16 训练）正相反：oracle_value 在位置 0 只有 1/52，位置 ≥1 为 106/948（11.2%）；R5 的 normal 在位置 0 也只有 2/52，最后位置目标权重位置 0 为 0.38、其余 0.48–0.58。即"第 0 条事实"和"有前文的事实"是两种 value 体制，两边学到的映射互不迁移。
不过，(c) 目前只证明了**迁移失败**。E-0012 L1 说尾实体在 E=16 上下文的分隔符 hidden 上仍 99.6% 线性可解码（探针在 E=16 上拟合），所以一个在 E=16 上训练的秩 128 投影原则上能取到它。"E=16 的 value 映射难学成"还没有任何 arm 测过，因为没有一个 E=16 arm 的解码器拿到过干净的读取（见 1.3）。

**(a) 寻址与 value 耦合、6000 步不够：对训练动态有强支持，但在现有 E=16 arm 上与 (c) 不可分。**
- R1 即使在 E=1（无寻址问题、读取恒为目标 value）也要约 4000 步以上：训练 CE 5.1→3.6（1000 步）→1.4（3000 步）→0.43（6000 步）；R3 的 E=1 段 1000 步后 calibration EM 15.3%。解码器本身就慢。
- R2（E=4）训练 CE 在约 4.5 平台停到第 4000 步，4000–6000 步才降到 3.6；对应 E=16 曲线上关系寻址在后半段才出现。我核对 R2 在 E=4 dev：最后位置目标权重在四个位置都是 0.97–0.99，但 EM 按位置只有 12/9/5/7%。寻址已到位、解码器没学成——因为干净信号只在最后约 1500 步出现。注意 E-0014 的 R2 门槛用的"目标权重 0.371"是全部问题位置的平均，最后位置是 0.983。
- R5：answer CE 5.32→4.00 仍在降，地址损失 2.10→0.81 仍在降；学习曲线 EM 1.4%（25%）、1.3%（50%）、4.3%（75%）、6.2%（终）——在加速。
- 但每个 E=16 arm 的解码器都是在混合读取（目标权重 0.05–0.5）上训练的，所以"6000 步不够"与"E=16 value 不可学"在现有数据里分不开。

**(b) 非末位混合读取干扰下游：不是解码失败的主因，可能是训练噪声。**
oracle_value 把所有问题位置都换成目标 value，已经去掉了 (b)，EM 仍只有 R5 10.7%、R2 3.7%、R1 5.8%。所以 (b) 不能解释 oracle 失败。它在训练中会给 A_v/R_o/P 加噪声梯度（非末位读取只能经下游 attention 影响答案），在覆写体制下这部分梯度应较小。E-0015 的 last_only / oracle_last_only 会直接量出评估侧的大小；我预期 <10 pp。

**(d) 融合出口过大或优化设置：现有数据不支持它是原因。**
- 同一体制下 E=1 成功（9 倍）。
- 裁剪比例：R1 0.996、R4 1.0、R5 0.984、R2 0.48、R3 0.24、R6 0.13、V2-03 0.13。学到东西的 arm（R1、R5）恰是几乎每步都被裁剪的；Adam 之前的全局裁剪主要改变步长尺度，不阻止学习。
- LR 3e-3 由 300 步校准选出，这个准则偏向"最快拟合先验"的 LR，可能偏高，但 R5 的地址损失平滑下降，不像 LR 失稳。(d) 最多是修饰因子，不值得单独占一个 arm。

**综合判断：** 最可能的复合解释是——解码器从未在"有前文的事实"的干净 value 上训练过（(c) 的迁移失败 + (a) 的稀释），而在解码器不可用时答案 CE 给不出寻址信号，训练被"固定读第 0 槽位当先验偏置"这个吸引子吸走。第 0 槽位之所以特殊，与 (c) 同源：第一条事实的分隔符特征与其后事实有质的差别（R1/R5 的位置分层互为镜像），它既是最容易被稳定寻址的 key，也是一个近似常量的 value，恰好能被线性解码器用作先验偏置。旁证：E-0012 L4 里随机初始化投影的最后位置 argmax 众数是槽位 2（15.5%），不是槽位 0——塌缩到 0 是训练选出来的，不是初始化给的。Sun et al. 2024 报告 massive activations 出现在起始 token 和第一个分隔符 token（第一个 "." 或 "\n"），作为近似固定的偏置项——与"第一条事实的分隔符特殊"一致，可在 E-0015 里零成本检查（按位置看分隔符特征的范数与最大维幅值）。

### 1.3 现有记录里我认为需要修正或补充的读法

1. **R4 不能说明"吸收先验后塌缩仍发生"。** R4 的先验通路（r32，1000 步，LR 3e-4）在零记忆下只到 NLL 4.74，而塌缩解的 NLL 是 4.42–4.43。记忆通路仍有约 0.3 nat 的先验可抓，塌缩的激励还在。要下这个结论，先验通路得先训练到 ≈4.42。
2. **R1 的 oracle_value 5.8% 是一个掩盖了 87% / 1.4% 两个体制的平均**（协调者在 AD-0001 后已核对，这里确认）。任何"R1 的 value 映射能否迁移"的推理都应按位置分层说。
3. **R2 的 E=4 门槛失败是全位置平均目标权重 0.37 造成的**，最后位置是 0.983；该门槛把寻址与解码混在一起。E=4 的真实状态是"寻址已成、解码器未成"。
4. **H3 的 NLL 条件实际由 shuffled 约束**（zero 的 9.25 是未适配 Base），R5 的 4.10 < 4.97 是真实通过，其余 arm 的 NLL_normal ≈ NLL_shuffled 说明读取内容没被用上。
5. 证据级别：E-0014 全部是 seed 0 的 screening，且 R5 带额外监督。以上所有机制读法都是在 V2 T1 数据、第 14 层、r128、direct_hidden、SoftmaxSlot、F_out、LR 3e-3 条件下的诊断性推断，不是机制确认。

## 3. 瓶颈

项目现在做不了下一步决定，是因为两个问题从未在**训练中**被分开：
(i) 在 E=16 上下文里（有前文的事实占 15/16），value→答案的解码器能否在 6000 步内学成——没有任何 arm 用干净的 E=16 读取训练过解码器；
(ii) 解码器可用之后，寻址能否仅从答案 CE 中被发现——R2 在 E=4 上关系寻址的出现说明"能，但慢"，而 E=16 的实体寻址从未在解码器可用的条件下测过。
E-0015 只做评估，能回答迁移与干扰，不能回答 (i)(ii)。在 (i) 有答案之前，任何寻址改动（含 R5 式监督、R6 式几何）都无法被公正评价，也无法作停线决定。

## 4. 提案（三条，机制不同）

### 提案 1：E=16 上"解码器先行"的两段训练（teacher-forced 读取 → 放开寻址）

- **解释的观察：** R1 的 87%/1.4% 位置分裂；R2 在 E=4 寻址 0.98 而 EM 5–12%；R5 的 CE 仍在降且后段加速；R3 课程失败（E=1 段只 1000 步、EM 15% 就切换）。共同点：解码器从未在干净的多事实 value 上训练到可用。
- **与已试路线的差别：** R1 训练的是 E=1（位置 0）value；R3 的课程在解码器未成时就切 E；R5 监督的是地址**权重**，读取仍约一半混合。本提案在训练时把记忆 state 掩成只有目标槽位有效（`MemoryState.slot_valid` 仅目标列为真，可用现有 `slot_columns`），正常可微读取就恰好返回 v_target，A_v/R_o/P 全部在干净 E=16 value 上训练；stage 2 从该 checkpoint 出发，恢复全部槽位，只用答案 CE（或用提案 2 的目标）。stage 1 用了目标索引，是额外监督（plan §13.5），结论单独标注；stage 2 的寻址不用任何标签。
- **区分性预测与对照：** stage 1 若 (a) 成立：E=16 dev 在 teacher-forced 读取下 EM 差 ≥50 pp（沿用 R1 门槛），训练 CE 曲线与 R1 对比给出"上下文代价"；若 (c)-难学成立：CE 平台在 ~2 以上、EM <20%。stage 2 若 (a) 成立：最后位置目标权重从关系水平（0.25）升到 ≥0.5、EM 差 ≥10 pp、无地址标签；若寻址仍塌到槽位 0 或停在关系水平，则寻址几何是独立瓶颈（转提案 2）。对照：zero/shuffled/permuted；stage 1 checkpoint 在 normal 读取下评估（应像 R1 一样失败，证明寻址未被训练）；位置分层；E=1 dev 作迁移检查；与 V2-03 同 seed、同数据、同步数。
- **最便宜的测试与成本：** stage 1 一个 arm 6000 步（≈0.1 node·h，按 E-0014 实测 0.28–0.41 MIG-h/arm），stage 2 续 6000 步（≈0.1 node·h）。实现量小：单槽位掩码 + 从 checkpoint 续训。
- **放弃条件：** stage 1 在 6000 步时 EM 差 <20 pp 且训练 CE 已平台 → E=16 value 通路本身是瓶颈，转向改变写入（提案 3）或更低层 tap，不再在寻址上花预算；stage 2 在 6000 步后目标权重 ≤0.3 或塌缩 → 寻址需提案 2。

### 提案 2：槽位隐变量的边际似然训练（概率空间混合，EM 式；配合只在最后问题位置读取）

- **解释的观察：** 塌缩到固定槽位作先验偏置、R5 中寻址学习慢、以及"混合读取上训练的解码器永远不干净"——这些都是**在向量空间里混合 value 再解码**的产物。
- **与已试路线的差别：** 六个 arm 与 V2 都是 a = Σ w_i v_i → 解码。这里改为 L = −log Σ_i w_i(q)·p(answer | 读取 = v_i)：每个槽位的 value 单独经融合与冻结下游解码（16 次问题侧前向，可用单槽位掩码实现），地址 w 来自最后位置的正常 softmax。解码器只在干净的单槽 value 上训练（按后验责任加权）；寻址的梯度是（后验 − 先验），是从答案推出的、不用目标索引的监督信号（EMDR²/Atlas 的做法）。塌缩到固定槽位不再有似然优势，因为被塌缩槽位的 value 解释不了答案。配合只在最后问题位置读取，顺便去掉 (b) 的训练噪声；T1 单跳只需最后位置。评估时部署读取定义为 argmax 槽位（硬读）并同时报告软混合；H3 门槛照旧，目标权重取最后位置。
- **区分性预测与对照：** 预测：无槽位 0 塌缩（最后位置 argmax 分布跟随目标而非固定）；后验目标责任先于先验权重集中；6000 步内 E=16 EM 差 ≥10 pp、最后位置目标权重 ≥0.5，或至少在 V2-03 平坦处出现单调上升。对照：zero/shuffled/permuted；"均匀先验"消融（固定 w=1/16、同一边际目标、只训解码器）分离解码器收益与寻址收益；R5 作有监督参照；硬读 vs 软读评估。REALM 的 cold-start 提醒：若从零起步 2000 步内后验仍均匀，可改从提案 1 的 stage 1 checkpoint 起步。
- **最便宜的测试与成本：** 一个 arm 6000 步；每步多 16 次短问题前向（问题约 12 token，支持约 150 token 只前向一次），估计步时 1.5–2 倍，≈0.15–0.2 node·h；需新的 loss 路径与一次代码审核。
- **放弃条件：** 6000 步时 EM 差 <5 pp 且后验目标权重 <0.25；或责任同样塌到固定槽位；或步时 >3 倍 V2-03。

### 提案 3：无上下文写入——每条事实单独编码（块对角 support attention 或 E=1 格式单独编码），读取协议不变

以 E-0015 规则 5 为前提（R1 的 iso_oracle_value 在位置 0 与 ≥1 都 ≥70%）。

- **解释的观察：** R1 的 87%/1.4% 位置分裂；R1 映射下位置 ≥1 的增量范数 2.5 倍于位置 0（22.0 vs 8.8，我核对）；槽位 0 吸引子（第一条事实的特征独特，可充当常量偏置；去掉位置特征后没有槽位特殊）；key 余弦 0.89–0.999 中有一部分来自共享前文。
- **与已试路线的差别：** 所有 arm 都从带前文的分隔符 hidden 写入；R6 改的是读取几何而非写入。本提案改变写入的内容，按构造消除协变量偏移。它是 plan §8.1 意义上须单独声明的"结构化支持输入条件"，对 T1 的任务定义无损；对 T2/V3，事实本就是独立三元组，组合发生在读取。
- **区分性预测与对照：** 预测：E=16 从零训练时无槽位 0 塌缩；实体寻址比 R2 的 ~4500 步更早出现；若 (c) 是主瓶颈则达 H3。再加一个很便宜的 arm：R1 checkpoint 在 iso 写入的 E=16 上续训（其解码器对 iso value 已可用，这才是正确的热启动——对带前文 value 的 R1 热启动没有意义）。对照：iso 写入 vs 上下文写入（V2-03）同步数；iso 保留原位置 id 的块对角 mask 版本 vs 位置重置版本（分开"前文"与"绝对位置"）；zero/shuffled/permuted。
- **最便宜的测试与成本：** 1–2 个 arm × 6000 步 ≈ 0.1–0.2 node·h（16 条短序列，每步更便宜）。
- **放弃条件：** E-0015 规则 5 不成立（iso_oracle_value 在位置 ≥1 <70%，说明问题不在前文而在位置 0 特有特征或 value 学习本身）；或 iso 写入 arm 仍塌缩到固定槽位且 6000 步 EM 差 <5 pp。

### 对协调者列出的其他候选的判断

- **R1 checkpoint 热启动后在 E=16 训练（上下文写入）：** 不建议。R1 的解码器只对位置 0 的 value 有效，在 E=16 上过度自信且错（NLL 18.7），必须重学；它不比从零开始更接近解。热启动只在提案 3 的 iso 写入下有意义。
- **E=1 与 E=16 混合 batch：** 不建议。E=1 部分只训练位置 0 体制的 value，不帮助 15/16 的有前文事实。
- **只在最后问题位置读取的训练协议：** 支持，但作为提案 2 的组成部分，而不是单独一个 arm；E-0015 的 last_only 会先给出评估侧效应大小。
- **更长训练：** 对 R3/R4/R6 无意义（softmax 已饱和、梯度近零）；续训 R5 或 R2 各 6000 步（≈0.2 node·h）能测 (a) 但不能解耦，信息量低于提案 1。
- **限制融合增量幅度：** 不建议作为筛选 arm；成功的 E=1 解在同一体制。只在提案 1 stage 1 失败后作为跟进因子（连同 LR 1e-3）。

## 5. 建议：继续，但只做一轮、带硬性停线规则

理由：(1) 成本极低——E-0014 实测 0.56 node·h，E-0015 ≤0.25，本轮三提案合计 ≤0.6 node·h，项目总量远低于 200 node·h 上限（记录：V2 结束时 4.2 node·h）；(2) 决定性的测量（E=16 value 通路是否可学）尚未做过，现在停线等于在没有该数据的情况下放弃范围内主张 (1) 与 (3)；(3) 三个提案彼此解耦，一轮就能把 (a)/(c) 分开。

- 并行跑提案 1（两段）与提案 2；若 E-0015 规则 5 成立再加提案 3。
- 提案 2 或提案 1 stage 2 或提案 3 任一在无地址标签下过 H3 → 以该配方用 seed 1、2 复现后重开 H-0003 路线。
- 提案 1 stage 1 通过、但 stage 2 与提案 2 都失败 → 瓶颈是寻址的发现，不是容量；此时可选择用声明的额外监督（R5 式）支撑 V3 的机制研究，或暂停。
