## Design

依据：plan §5.1（停止记忆路线后，有效的简单接口仍可确认）、§11、§13.3–13.5、§14.2（循环无信号时，V5 收缩为单读或简单接口对比，并登记实际减少的 arm 与预算）、§15.2。记忆路线已停止（D-0008），V3/V4 已暂停（D-0009），侧支单读也没有可用信号。因此 V5 的七组收缩为三组：V5-03 改为 C* tokenwise（无侧支历史），V5-05 为 LoRA28 all-7 rank1，V5-06 为与 C* 等参数的 F* r64。V5-01/02/04/07 依赖侧支读取或多读，取消；§11.3 的侧支历史干预也不再适用。

先验：V1 E-0003 筛选（seed 0，2M tokens，LR 3e-4，dev）中，C_up 为 77.70%，比 LoRA4 r10 低 1.50 pp [−2.40, −0.60]，比 LoRA28 r2（1,261,568 参数）低 1.35 pp [−2.50, −0.20]（EV-0048）。所以并不预期 C* 胜出。本实验用预登记规则、3 个 seed 和封存的确认集给出确认性估计；结果不论方向如何，都按下面的规则记录。

### Arms

| arm | 接口 | 层 | 可训练参数 |
| --- | --- | --- | ---: |
| V5-C | C_up：Z=SiLU(uA)，r32；Z·C_u 加到冻结 FFN 的 up_proj 输出（u 为 FFN 输入） | 6,13,20,27 | 524,288 |
| V5-F | F_out：同一 tokenwise SiLU 分支，r64；Z·P 加到该层输出（h + mlp(u) + Z·P） | 6,13,20,27 | 524,288 |
| V5-L | LoRA all-7（q,k,v,o,gate,up,down），rank1，alpha=rank（scale 1）；A 用 Kaiming uniform 初始化，B 零初始化 | 全 28 层 | 630,784 |
| Base | 不训练 | – | 0 |

实现沿用 V1（src/bypass_model.py 的 tokenwise 分支与 Fusion，src/v1_lora.py，src/v1_run.py），新配置只改 rank 与层。代码断言上表的参数数，以及可训练参数均为 FP32。C_u 与 P 按 V1 零初始化，所以训练起点等于 Base。

### 数据、模板与训练

- 数据：沿用 V1 的官方 train 切分（种子规则 derive_seed(20261029, concat_loop_v2, V1, {task}-split)；dev 1000、calibration 2048、其余为 train）、模板与候选打分。PIQA 用长度归一化的平均对数似然，BoolQ 用 " yes"/" no" 的对数似然之和。max_length 为 512，BoolQ passage 右截断，PIQA prompt 左截断。沿用 V1 已登记的 PIQA train 行 5528 排除（候选超长）。plan 允许 V5 用 1024，这里保持 512 与 V1 一致，所有 arm 相同。
- seed s ∈ {1, 2, 3}：数据顺序为 Random(derive_seed(20261029, "concat_loop_v2", "V5", "train", s) + epoch)，交替规则同 V1；新参数初始化前调用 torch.manual_seed(derive_seed(20261029, "concat_loop_v2", "V5", "init", s))。同一 seed 下三个 arm 的顺序与初始化种子相同，训练配对进行。
- 每 run 正好 3 epochs（19,443 行 × 3 = 58,329 次样本呈现，约 4.46M 非 padding 输入 tokens）。12M 上限不会起作用，也不为填满上限而重复数据（§13.5）。分批沿用 V1 的 plan_batches：未满的 batch 跨 epoch 边界延续，只在 3 epoch 上限处补出最后一个，共 29,165 步；有效 batch 2、microbatch 1。
- 训练目标与 V1 相同（T-0002 release 中按 MSG-0025 的更正，E-0003 沿用；src/v1_run.py 的 example_mean_objective）：每个样本先对其监督 token 的 CE 取平均，再在一步的样本间平均；microbatch 1 时，每个样本均值在 backward 前除以该步样本数。不用 token 加权。AdamW（betas 0.9/0.999、eps 1e-8、weight decay 0.01）与梯度裁剪 1.0 同 V1；前 5% 步线性 warmup，之后 cosine 降到 0。
- 只用最终 checkpoint。dev 监控在消耗每个 epoch 最后一个样本的那一步之后进行（预计第 9,722、19,443、29,165 步；第一次已含下一 epoch 的一个样本），只作监控，不用于选择。checkpoint 保存后重新加载到新的 Base 上，重复 dev 评估，逐例分数与预测须完全一致（同 V1）。
- 学习率：每个 arm 用校准 seed 0（同上规则，s=0，与确认 seed 不重叠），每个候选跑一次短训练，到第一个累计达到 200,000 非 padding 输入 tokens 的完整步为止（同 V1）；schedule 形状与训练目标同上。初始网格为 {1e-4, 3e-4, 1e-3}。指标为 calibration NLL（V1 定义：各任务 gold CE 按 token 求和后取任务均值，再取两任务的算术平均）。非有限值的候选淘汰。按初始网格中有限值的原始最小 NLL 决定是否扩展：最小值在 1e-3 时追加 3e-3，在 1e-4 时追加 3e-5，每端只扩一次。然后在最终的有限候选集中，取满足 (NLL − 最小 NLL)/最小 NLL ≤ 0.01 的最小 LR。三个 arm 规则相同；选定后在 seed 1 训练前锁定。
- 若实测成本推算超出预算，所有 arm 统一缩短 epoch 或 step，并在训练前登记，不允许各 arm 停在不同的样本预算上（§14.4）。

### 确认集与唯一一次开封

- 官方 validation：PIQA 用 valid.jsonl 与 valid-labels.lst（1,838 条），来自 V1 同一来源与 revision（ybisk/ybisk.github.io @ 21edab439af693b961be2f069e8690a88d3b4e37）；BoolQ 用 validation parquet（3,270 条），来自 google/boolq @ 35b264d03638db9f4ce671b711558bf7ff0f80d5。在登录节点下载到 data/v5-sealed/，记录 SHA256 与字节数，提交哈希清单（不提交数据）。开封前任何代码或会话都不读取其内容，包括长度与标签统计；训练与 dev 评估代码不引用这些路径。
- 开封前须全部满足：(1) 九个训练 run 完成，reload 一致，各 arm 的 LR 与最终 checkpoint 已登记；(2) 确认评估与分析脚本通过代码审核；(3) 用 dev 预测完整演练一遍分析流程；(4) 提交锁定清单：checkpoint 路径与 SHA256、代码 commit、数据与 WikiText 哈希、本合同版本。
- 开封：一个 PBS 作业在 validation 与 WikiText 上评估 Base 与九个 checkpoint，然后运行分析。若在产生完整预测前因工程原因失败，用同一锁定配置重跑并登记；看到任何 validation 输出后，方法、checkpoint、规则一概不改。行数须为 1,838/3,270，否则停下报告。
- 在 max_length 512 下无法编码的行（V1 规则）从所有 arm 中同样剔除并计数；任一任务剔除超过 0.5% 时报告为协议偏离，比较仍保持配对。

### 主分析（H-0008）

- Δ_s = macro(V5-C, s) − macro(V5-L, s)，其中 macro = (PIQA 准确率 + BoolQ 准确率)/2，在官方 validation 上计算；Δ = 三个 seed 的 Δ_s 平均。每任务差 δ_task 为三个 seed 的平均。
- 配对分层 bootstrap：10,000 次，numpy.random.default_rng(20261029)。每次在 PIQA 与 BoolQ 内各自有放回重抽行，所有 arm 与 seed 共用同一组索引，重算 Δ。取百分位 95% 区间。
- supported：Δ ≥ +1.0 pp、区间下界 > 0、三个 Δ_s 都 > 0，且两个 δ_task ≥ −1.0 pp。
- challenged：区间上界 < +1.0 pp（数据排除了预登记的最小实用收益）。
- 其余为 inconclusive。
- 推断范围：bootstrap 只重抽评估样本，三个训练 seed 固定，所以区间只刻画给定 seed 1–3 这三次训练时的数据不确定性，不代表训练过程的分布（plan §13.4）。supported 表示满足预登记的正效应与点估计实用门槛：+1 pp 是对点估计的要求，区间只要求下界 > 0，不表示以 95% 置信保证收益至少 +1 pp；每任务 −1 pp 也是点估计护栏，不是逐任务的非劣检验。challenged 只排除 +1 pp 的最小收益，不表示两者等价。

### 次要比较（Holm，两项）

- S1：V5-C − V5-F（等参数下，concat 的收益是否只是更大的接口预算；两者同时改变接口与 rank，所以这是预算比较，不是对融合位置的孤立干预）；S2：V5-F − V5-L（等参数的加法接口对 LoRA）。两项用同一 bootstrap 给出 seed 平均宏差、95% 区间与双侧 p = min(1, 2·min(P(Δ* ≤ 0), P(Δ* ≥ 0)))，在 α = 0.05 下做 Holm；另报每任务、每 seed 的差。原始 95% 区间不是 Holm 调整后的同时区间，报告中这样标注。
- 描述性报告：各 arm 每任务准确率与 NLL（seed 均值 ± SD）、dev 指标、WikiText NLL 差、成本表。这些都不作判定。

### WikiText-103 能力保持

Salesforce/wikitext，wikitext-103-raw-v1 test split，固定 revision 并记录文件 SHA256。按原顺序直接拼接各行（行内已含换行），不加特殊 token 分词，切成不重叠的 1024-token 块，丢弃最后不满的块，报告所有预测位置的平均 NLL。对 Base 与九个 checkpoint 分别计算，报告各 arm 相对 Base 的 ΔNLL（seed 均值 ± SD）。只用于前后相对比较，不排除与预训练数据重叠，也不作判定。

### 成本

可训练参数；可合并性（LoRA 可合并，tokenwise SiLU 接口不能静态合并）；实测训练墙钟时间、稳定步时（去掉前 10 步）、峰值显存；推理延迟：同一 GPU 类型上，以 batch 1 对固定的 256 个 dev 候选输入做前向，比较 Base、V5-C、V5-F 与 V5-L（合并前与合并后）。只报告，不作判定。

### 实现、审核与预算

- 训练扩展（新 arm、V5 seed 与顺序、LR 网格、3 epoch schedule）在校准与正式训练前请求代码审核；冒烟可以先跑。确认评估、分析脚本与封存流程在开封前请求代码审核，审核时附带用 dev 预测的演练结果。
- 全部计算经 miyabi-mcp 走 MIG 队列。按 V1 实测速度估计（每 run：C 与 F 约 2.0 h，L 约 4.2 h），九个 run 约 26 MIG-h，LR 校准约 1.5，确认评估约 3，冒烟与测试约 1，合计约 31 MIG-h ≈ 7.8 node·h。上限为 12 node·h。
