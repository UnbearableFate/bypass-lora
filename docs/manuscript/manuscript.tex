\begin{abstract}
本文记录 Bypass-LoRA v2 计划第一个里程碑（V0+V1）的结果。研究问题是：在冻结的 Qwen3-0.6B-Base 上加入低维侧分支后，把同一低维信号注入 FFN 的 gate/up（条件融合），是否优于加法写回。方法分两步：先用预先锁定容差的实现检查验证侧分支语义（E-0001 修正后 85/85 项通过，E-0004 130/130 项通过）；再在 PIQA+BoolQ 上用不含记忆的 tokenwise proxy 比较八组接口（E-0003，每组 2M tokens，seed 0）。按运行前固定的规则，最好的 concat 接口 C\_dual（78.15\%）只比加法 F\_out（77.80\%）高 0.35 pp，未达 1 pp 门槛；两个参数相近的 LoRA（79.20\%、79.05\%）都更高。这是单 seed 筛选证据，H-0002 记为 challenged。V2 所需的数据与流水线已就绪；Base 诊断显示，16 条事实同时在上下文中时，Base 几乎总是复制问题主语。主要限制是单 seed、单一 dev 切分、接口之间参数不相等。
\end{abstract}

\section{Introduction}

Bypass-LoRA v2 在冻结主干旁加一条低维循环侧分支：从注意力的 Q/K/V 取特征，压缩成低维状态，经记忆读写与循环更新，再通过 FFN 融合写回主干。计划把研究拆成几个阶段：V0 验证实现语义（H-0001）；V1 在没有记忆与循环的 tokenwise proxy 下比较融合接口，检验把信号注入 FFN 的 gate/up 是否优于加法写回（H-0002）；从 V2 起研究丢弃 support 主干 KV、只保留低维记忆时的单跳读取（H-0003），后续还有读算子选择性（H-0004）、多次读取（H-0005）与实用适配（H-0006）。本文报告 V0 与 V1 的结果，以及为 V2 所做的数据、流水线与 Base 难度准备。各假设的陈述、范围与当前状态如下。

\section{Method}

所有实验都使用 Qwen/Qwen3-0.6B-Base（锁定 revision da87bfb6），BF16 冻结主干、FP32 新参数、eager attention，硬件为 GH200 MIG 2g.24gb；所有工作负载都在 PBS 作业中运行。E-0001 与 E-0004 是不训练的实现检查，容差在检查前由同一 Base 的重复测量锁定（BF16 atol 0.50002，FP32 2e-5），失败后不放宽。E-0002 从 PIQA 与 BoolQ 的官方 train 中切出 train、calibration 与 dev（dev 每任务 1,000 条，官方 validation 封存不读），在三个代表结构上用 0.2M tokens 比较 1e-4 与 3e-4，按 calibration NLL 选学习率，三个家族都选中 3e-4。E-0003 用 seed 0 训练八组：proxy $Z=\mathrm{SiLU}(UA)$（4 层 [6,13,20,27]，r32）分别接 F\_out、F\_pre、C\_gate、C\_up、C\_dual；线性退化组 $Z=UA$ 接 C\_dual；以及 4 层 rank10 与 28 层 rank2 的 LoRA。每组在累计 2M 非 padding 输入 tokens 的那一步停止（13,077 步，batch 2），warmup 5\% 后 cosine；主结果用最终 checkpoint，并要求重载后复评逐条一致。主指标是 dev 上 PIQA 与 BoolQ 准确率的宏平均。F*、C*、“有效”与“concat 胜出”的规则都在第一个正式 run 之前写进契约，按点估计判定；配对 bootstrap 区间（10,000 次，按任务分层）只作描述。E-0005 生成 V2 的单跳合成任务（每个 episode 16 条事实、4 种关系、单 token 答案），并在 dev 上评估 Base 的 M 线（只有问题）与 F 线（事实在上下文中）。E-0006 实现 M 线训练与诊断流水线并做冒烟。E-0007 在 calibration 切片上诊断 Base 在 F 线上失败的原因。各实验的契约摘要如下。

\section{Discussion}

证据支持两点。第一，V0 侧分支在所测试的恒等式与隔离项上实现正确（diagnostic，D-0003）。第二，在 V1 的固定配方下，gate/up 条件融合没有显示出预期的、超过加法写回 1 pp 的优势（screening，D-0004）。证据不支持以下推断：任何关于有记忆读取（H-0003）的结论；对其他 seed、接口专属学习率或总体效应大小的推断（最佳 concat 对 F* 的描述区间上限为 1.35 pp，仍覆盖 1 pp 的优势）；以及参数效率比较（接口之间参数不相等）。效度方面的威胁包括：单 seed 与单一 dev 切分；学习率只按家族在两个候选中校准；PIQA 提供的区分信号较弱；配对区间不含训练 seed 的变异，也没有做多重比较校正。V2 准备方面，E=16 的 F 线对 Base 很难，主要原因是问题主语复制；事实增多时，在名字中的检索也明显变弱。因此 V2 需要一个训练后的 F 线正对照，才能判断 M 线的失败是否来自任务本身。E-0007 保留了未通过的原始实现检查；FP32 对照是看到结果后补做的诊断。决策如下：H-0001 记为 supported，继续作为后续阶段的基础；H-0002 记为 challenged 并暂停，V2 保留 F*=F\_out、C*=C\_up 与 C\_dual 交互探针；阶段决定为继续探索，V2 是否释放由用户决定。
