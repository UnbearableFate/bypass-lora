# 超出 backbone 上下文的记忆

截至 2026-11-02。

## backbone 的上下文是什么

Transformer 每一层的 attention 只能读那些 K/V 还保留着的 token，这些 token 就是它的上下文。Qwen3-0.6B-Base 有 28 层，每层 8 个 KV 头、每头 128 维，所以每个 token 要存的 K/V 有

$$28 \times 2 \times 8 \times 128 = 57{,}344$$

个数，BF16 下约 112 KiB。文本越长，KV 越大，位置上限是 32,768。

一段文字的 KV 一旦被丢掉，backbone 之后就完全看不到它。常见情况有：文本超出窗口，为省显存淘汰旧 KV，上一次调用的内容，把长输入切成几段分别处理。

## 超出上下文的记忆：跨过这条边界还留着的固定大小状态

项目的侧分支在第 6、13、20、27 层各维护一个 KernelMatrix 状态。每读到一个 token 就写入一次：

$$M_t = M_{t-1} + \phi(k_t)\, v_t^\top, \qquad c_t = c_{t-1} + \phi(k_t)$$

之后任何位置都可以读：

$$a_t = \frac{\phi(q_t)^\top M_t}{\phi(q_t)^\top c_t}, \qquad \phi(x) = \mathrm{ELU}(x) + 1$$

$k, v, q$ 是从 backbone 特征压缩出来的 32 维向量，$M$ 是 $32 \times 32$，$c$ 是 32 维。四层合计 4,224 个 FP32 数，约 16.5 KiB，不管写入多少 token 都是这个大小，比一个 token 的 KV 还小。

backbone 的 KV 被丢掉以后，这个状态还在，后面的 token 仍能从里面读出前文的压缩摘要。这就是"超出 backbone 上下文的记忆"。它是有损的：几千个数装不下一整段文字的全部信息。

## LoRA 为什么做不到

LoRA 只改权重：$W \rightarrow W + BA$。推理时它对每个输入都一样，没有随输入累积的状态。它能把训练数据里的通用规律学进权重，但这一次输入里已经被丢掉的那段内容，它拿不到。

反过来，当 backbone 能看到全部输入时，侧分支状态里的信息 backbone 自己也有，状态就没有独占的东西。RB1 正是这种设置，侧分支没有赢过 LoRA，也不比不读历史的同参数对照好。

## 项目里检验过这种能力的两个实验

M 线：先读 16 条事实，写进记忆，丢掉这些事实的 KV，再提问，模型只能靠记忆回答。每条事实单独编码再写入时，单跳问题在 3 个 seed 上都达到门槛，正常记忆的 EM 比清零或打乱记忆高 41 到 48 pp（H-0012）。要沿事实链连读两次以上的问题没有成功（V3 停在 A3，H-0005 inconclusive）。

E-0025（还在分析）：每个样本拆成两次 backbone 前向。PIQA 的目标、BoolQ 的文章只在第 1 段，第 2 段的 backbone 看不到它们，只有四层侧支状态能跨段。初步点估计（PIQA）：

| 组 | PIQA |
|---|---|
| 保留跨段状态 | 69.4% |
| 段界清空状态 | 67.8% |
| 同参数、不读历史的 T0 | 66.9% |
| 分段 LoRA（看不到第 1 段） | 67.4% |
| 能看到全文的 LoRA（RB1） | 74.4% |

状态确实带过去一点信息，但离看到全文差得远。比同结构里最好的对照高 1.6 pp，低于预先登记的 3 pp 门槛；干预和锁定分析还没做完，规则 6 可能还要测 r128。

## 什么场景会需要它

超长文档、流式输入或多轮对话里旧 KV 被淘汰、显存不够存全部 KV 的部署。在这些场景里要比的对象不再是 LoRA，而是其他能跨过上下文边界的方法。

同类工作已经不少，下面几个是凭记忆举的例子，项目里还没有核查：Transformer-XL 的段级循环、Compressive Transformer、Recurrent Memory Transformer，以及 Infini-attention。Infini-attention 在每层用同样形式的 ELU+1 线性注意力做压缩记忆，和这里的 KernelMatrix 状态几乎一样。要把这个方向当成研究目标，需要先和这些方法比，这属于改变研究目标，要由你决定。
